# 健壮性与降级原则（设计阶段参考）

> **定位**：本 skill 在 Step 4（约束原则）、Step 6.6（配置默认值）、Step 7（失败模式）横切引用的健壮性判据。
> 覆盖：默认值、降级、异常吞没、魔法数字、降级可观测五个主题。
> 核心心智：**兜底的默认值不是「正确答案」，只是「避免崩溃的临时替身」；降级本身不是问题，降级了不吭声才是问题。**

---

## §0 四个字段类别（决定一切）

设计失败模式 / 默认值时，先把字段归类，再按类别判「该报错还是该给默认」：

| 类别 | 例子 | 能否降级 / 给默认 |
|------|------|------------------|
| **决策 / 门禁类** | 审批动作、审批决策、待审 / 放行标记、是否耗尽 | **绝不**（缺失即 fail-closed / fail-fast） |
| **ID / 身份类** | 会话 ID、用户 ID、模型 ID、渠道 / provider 标识 | **绝不**（缺失即报错，没有 default 这回事） |
| **金额 / 计费类** | 价格、费用、预算额度 | **绝不**（缺失绝不默认 0，必须留痕） |
| **展示 / 辅助类** | 会话标题、preview、UI 文案、上限阈值 | **可以**（但必须留痕） |

> 前三类不叫「降级」，叫「**必须失败**」。别用「降级」这个词软化它们。

## §1 默认值 vs 兜底（fallback）

问题从来不是「默认值」，是「散落在消费点的 inline 兜底」：

| | 例子 | 判定 |
|---|------|------|
| **声明处默认**（好） | `def cleanup(ttl=30)`、常量、dataclass 字段默认 | ✅ 显式、声明一次、有名字 —— 鼓励 |
| **消费处兜底**（坏） | `content.get("model_id") or None`、`x or "unknown"` 散落各调用点 | ❌ 同一缺失值 N 处各兜各的、兜法不一致 —— 禁止 |

**规则**：
1. 默认值**只允许在「定义处」声明一次**（函数签名 / 常量 / dataclass 字段）。
2. **消费点禁止 `or 默认` / `.get(k, 兜底)`** —— 缺了就向声明处要，或按字段类别 fail-fast。
3. 三大零默认禁区（决策 / ID / 金额）**连声明处默认都不许** —— 它们没有「合理默认」。

> 口诀：**默认值应该"长在字段的出生地"，不该"长在每个用它的地方"。**

## §2 降级原则

### §2.1 能不能降 —— 看字段类别（见 §0）
决策 / ID / 金额类**一票否决**；只有展示 / 辅助类可降。

### §2.2 什么时候可以降 —— 三条同时满足
1. 字段是**展示 / 辅助类**；
2. 替身值**不造成方向性错误**（不把门打开、不把钱算成 0、不把数据归错人）；
3. 触发点**能留痕**（走统一 degradation 通道，见 §5）。

### §2.3 怎么通知 —— 按「是否影响用户可见结果」三档
| 档位 | 触发条件 | 手段 |
|------|---------|------|
| **只留痕** | 不影响用户可见结果 | `degradation` logger warning |
| **冒泡到 UI** | 影响用户可见结果（模型被换、run 无法恢复） | warning + 错误事件，别让用户「以为正常」 |
| **中止 + 报错** | 决策 / ID / 金额类缺失、跨会话污染 | fail-fast，把「发生了什么 / 为什么停」告诉用户 |

### §2.4 降级的四个「必须」
1. **必须可观测**：走统一 degradation 通道（§5），不是散落的 `logger.warning`。
2. **必须有熔断上限**：同一路径连续降级 N 次 → 升级为 fail-fast，不许无限降级（复用已有熔断状态机）。
3. **只由 owner 层判一次，不层层重判**：谁产生该值谁决定能不能降；下游不许把上游的降级值当正常输入再兜一次（防级联）。
4. **可恢复的最低标准**：降级后下次请求从真相源重新解析，别缓存降级值。

> 典型级联：model_id 回落 → 模型变了 → pricing 不识别 → 费用静默计 0 → 预算永不停机。每层独立校验，掐断链条。

## §3 异常处理

**核心立场：异常要么传播（不 catch），要么在指定边界处理（catch + log + 转错误）。中间层绝不无声吞掉。**

### §3.1 三层职责
| 层 | 允许的 except | 说明 |
|----|--------------|------|
| **中间逻辑**（锁查询、ID 解析、计费、状态机） | **无 broad except** | 让异常自然往上冒。这里出现 `except: pass` / `except: return None` = 违规 |
| **故障隔离点**（白名单，见 §3.2） | `except Exception:` catch-all | **必须三步：catch → log → 转用户可见错误**，缺一不可 |
| **非关键清理**（aclose、看板推送） | `except Exception: logger.warning(exc_info=True)` + 继续 | 失败不阻断主流程，但**必须留痕** |

### §3.2 故障隔离点白名单（只有这几处允许 broad except）
- 顶层执行入口（对外 `run()` / `run_stream()`，异常转结果对象）
- 后台任务协程入口（转 error 事件 + 释放上游等待方）
- 路由顶层 handler（转 error 事件冒泡 UI）
- 观测 / 账本的 Fail-Safe 边界（绝不因观测 / 计费炸断主流程，但必须 `logger.exception` 留痕）

> 清单之外的任何 `except Exception` 都算违规。

### §3.3 每写一个 except 前的三问
1. 这异常是**预期内可恢复**还是**意料外 bug**？预期内 → 用具体异常类型捕获；意料外 → 传播 / `logger.exception`。
2. 吞掉它会不会让上游拿到**错误结果**？会 → 绝不能吞。
3. 吞掉后**有没有留痕**？没有 → 补，至少 `logger.exception`。

## §4 魔法数字 / 魔法字符串

**核心：命名 + 就近归属 + 单一真相源。不是「全塞进一个 constants.py」。**

| 类别 | 管理方式 | 例子 |
|------|---------|------|
| **契约字符串**（跨端字段名 / 事件类型） | 共享协议常量 / Enum（优先级最高） | `"model_id"`、`"plan_action"` —— 拼错一字符=静默 bug |
| **语义 / 枚举类**（状态、决策值） | `Enum` | 审批决策、熔断状态 |
| **配置类**（超时、上限、默认） | 就近的 owner 模块常量；真正跨层才进 `config/` | 默认上限、超时 |
| **阈值类**（金额比较、重试次数） | 模块级常量 + 注释说明「为什么是这个值」 | `BUDGET_WARN_THRESHOLD = 0.8` |

**⚠️ 别矫枉过正**：只收编三种 —— ① 重复出现的 / ② 编码了策略阈值的 / ③ 属于契约的。一次性、语义自明的（`[:8]` id 后缀、`> 0`）强行命名反而更难读。

## §5 统一降级可观测

**核心：让所有降级 / 兜底 / 异常吞没在同一视角下可追踪、可统计、可告警。但别造第五根柱子** —— 汇入已有的 Metrics + Logger 后端。

### §5.1 双写：log（取证）+ counter（驱动迭代）
log 是事后取证；让系统「越来越稳定」的是 metric —— 按 category 的 counter，能看趋势。

### §5.2 结构化字段
统一 logger（如 `pandapal.degradation`）+ 结构化 `extra`：
- **`event_code`**：稳定主键，用于 group by（别塞进自由文本）
- `category`：decision / id / cost / exception_swallowed / display
- `severity`：log_only / ui_bubble / abort（对应 §2.3 三档）
- `source`、`expected`（本该是什么）、`fallback`（实际回落了什么）
- 同时 +1 到 Metrics counter，labels = {category, source, severity}

### §5.3 要点
1. **`event_code` 作稳定主键**（不是 message 文本）—— 才能聚合统计。
2. **degradation ≠ audit**：audit 管「安全相关发生了什么」（不可绕过）；degradation 管「在哪兜了底」。两个概念别塞一个通道。
3. **去重防刷屏**：高频路径按 key 去重（如按模型名，每模型 / 每小时最多一条）。

## §6 设计阶段自查清单

- [ ] **字段类别**：这是决策 / ID / 金额类吗？是 → 缺失必须 fail-fast，不许任何默认（Step 7 失败行为列写「报错 / 拒绝」而非替身值）。
- [ ] **默认值**：配置项默认（Step 6.6）在「定义处」声明？消费点没有散落的 `or 默认`？
- [ ] **except**：在 §3.2 白名单点上吗？不在 → 让它传播；在 → catch / log / 转错误三步齐了吗？
- [ ] **级联**：有没有把上游的降级值当正常输入又兜了一次？
- [ ] **降级留痕**：走统一 degradation 通道了吗？有 `event_code` + `category` 吗？
- [ ] **魔法数字**：这个字面量重复出现 / 是阈值 / 是契约吗？是 → 命名并就近归属。
