# 博客系统 PRD（产品需求文档）

## 1. 文档信息

| 项目 | 内容 |
| --- | --- |
| 产品名称 | 博客系统（Blog System） |
| 文档版本 | v1.0 |
| 撰写日期 | 2026-08-11 |
| 文档状态 | 评审稿 |
| 适用范围 | Web 端（桌面 + 移动浏览器响应式） |

## 2. 项目背景与目标

### 2.1 背景
用户需要一个支持基本内容创作与互动交流的博客系统，覆盖从账号开通到内容消费、再到社交互动的完整链路。

### 2.2 产品目标
1. 提供注册/登录能力，区分游客与注册用户的权限边界。
2. 支持注册用户发布、编辑、管理自己的文章。
3. 支持登录用户在文章下发表评论与回复，形成基础互动闭环。
4. 保证核心数据（账号、文章、评论）的安全与稳定。

### 2.3 成功指标（建议）
- 注册转化率：访客 → 注册用户 ≥ 10%
- 文章发布成功率 ≥ 99.9%
- 评论提交成功率 ≥ 99.5%
- 核心页面首屏加载 ≤ 2s（4G 网络）

## 3. 用户角色与权限

| 角色 | 说明 | 核心权限 |
| --- | --- | --- |
| 游客 | 未登录访客 | 浏览文章列表、查看文章详情、浏览评论；不可发文章、不可评论 |
| 注册用户 | 已登录普通用户 | 游客权限 + 创建/编辑/删除自己的文章 + 发表/删除自己的评论 + 回复评论 |
| 管理员 | 系统运维角色 | 注册用户权限 + 审核/下架任意文章 + 删除任意评论 + 用户管理（可选，本期可仅预留） |

> 说明：管理员为可选范围，本期 PRD 以游客与注册用户为必做，管理员能力标记为"可选/二期"。

## 4. 功能需求

### 4.1 用户注册与登录（FR-01）

#### 4.1.1 注册
- **入口**：导航栏"注册"按钮 / 登录页"立即注册"链接。
- **必填字段**：用户名、邮箱、密码、确认密码。
  - 用户名：4~20 个字符，仅限中文、字母、数字、下划线；全站唯一。
  - 邮箱：符合标准邮箱格式；全站唯一；注册成功后发送激活邮件（可选，若不做邮件则注册即生效）。
  - 密码：8~32 位，至少包含字母和数字；需二次确认且两次输入一致。
- **校验规则**：前端即时校验 + 后端二次校验；用户名/邮箱重复时给出明确错误提示。
- **协议勾选**：注册需勾选《用户协议》与《隐私政策》（默认不勾选，未勾选不可提交）。
- **防滥用**：同一 IP 注册频率限制（如 1 小时 ≤ 10 次）；图形验证码（可选）。

#### 4.1.2 登录
- **方式**：支持"用户名 + 密码"或"邮箱 + 密码"两种登录。
- **会话**：登录成功返回会话令牌（Token），默认有效期 7 天，支持"记住我"（30 天）。
- **错误处理**：账号不存在与密码错误提示统一为"用户名或密码错误"，防止账号枚举；连续 5 次失败锁定 15 分钟（可选）。
- **登出**：导航栏提供登出入口，登出后清除本地会话。

#### 4.1.3 密码找回（本期可选，建议纳入）
- 通过注册邮箱发送重置链接，链接 30 分钟内有效，一次性使用。

### 4.2 文章发布与管理（FR-02）

#### 4.2.1 文章列表（首页 / 归档）
- 按发布时间倒序展示文章卡片：标题、摘要（前 120 字）、作者、发布时间、标签、阅读量。
- 支持分页（每页 10 篇）与按标签/分类筛选。
- 游客与注册用户均可浏览。

#### 4.2.2 文章详情
- 展示标题、作者、发布时间、标签、正文、阅读量。
- 正文支持 Markdown 渲染（或富文本），代码块高亮。
- 文章底部展示评论区（见 4.3）。
- 作者本人可看到"编辑 / 删除"入口；其他用户仅浏览。

#### 4.2.3 发布文章（发文章）
- **入口**：登录后导航栏"写文章"按钮。
- **字段**：标题（必填，≤ 100 字）、正文（必填）、标签（可选，最多 5 个）、分类（可选）。
- **编辑器能力**：Markdown 编辑 + 实时预览；图片上传（≤ 5MB，支持 jpg/png/gif/webp）。
- **保存方式**：
  - "保存草稿"：仅作者可见，可继续编辑。
  - "发布"：立即对所有人可见，进入文章列表。
- **自动保存**：编辑过程中每 60s 自动保存草稿，防止内容丢失。

#### 4.2.4 文章编辑 / 删除
- 仅作者本人可编辑、删除自己的文章。
- 删除需二次确认；删除后文章及其下所有评论一并逻辑删除（保留数据用于审计）。
- 已发布文章编辑保存后立即生效。

#### 4.2.5 文章状态机
- 草稿（Draft）→ 已发布（Published）；已发布可改回草稿（下架）；删除为终态。

### 4.3 评论功能（FR-03）

#### 4.3.1 发表评论
- **权限**：仅登录用户可评论；游客看到评论区时展示"登录后参与评论"。
- **字段**：评论内容（必填，1~1000 字）。
- **校验**：去除首尾空白；禁止纯空白/纯表情；敏感词过滤（基础词库，可选）。
- **频率限制**：同一用户 60s 内最多 3 条评论，防止刷屏。

#### 4.3.2 回复评论
- 支持对已有评论进行回复，采用二级嵌套（评论 + 回复）或楼层模式，本期建议：二级嵌套（回复可 @ 被回复者用户名）。
- 回复同样需要登录，校验规则同 4.3.1。

#### 4.3.3 评论展示
- 按时间正序展示，最新回复在对应评论下展开。
- 展示评论者用户名（脱敏昵称）、评论时间、内容、被回复对象。
- 评论总数显示在评论区标题处。

#### 4.3.4 评论删除
- 评论作者本人可删除自己的评论；文章作者可删除自己文章下的任意评论（可选）；管理员可删除任意评论（可选）。
- 删除后展示"该评论已删除"占位，避免楼层面板错乱。

## 5. 页面与交互流程

### 5.1 页面清单
| 页面 | 路径（建议） | 访问权限 |
| --- | --- | --- |
| 首页/文章列表 | `/` | 全部 |
| 文章详情 | `/articles/:id` | 全部 |
| 注册页 | `/register` | 游客 |
| 登录页 | `/login` | 游客 |
| 写文章页 | `/editor` | 登录用户 |
| 文章编辑页 | `/editor/:id` | 文章作者 |
| 个人中心（我的文章） | `/me/articles` | 登录用户 |

### 5.2 关键流程
1. **注册流程**：填写表单 → 前端校验 → 后端校验（查重） → 创建账号 → 自动登录或跳转登录页 → 进入首页。
2. **发文章流程**：登录 → 点击"写文章" → 填写标题/正文/标签 → 保存草稿或发布 → 跳转文章详情。
3. **评论流程**：登录 → 在文章详情底部输入评论 → 提交 → 校验 → 发布成功 → 评论列表即时刷新。
4. **未登录拦截**：访问写文章页、个人中心等受限页面时，跳转登录页并携带回跳参数。

## 6. 数据模型（核心表）

### 6.1 users（用户表）
| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | BIGINT PK | 用户 ID |
| username | VARCHAR(20) UNIQUE | 用户名 |
| email | VARCHAR(128) UNIQUE | 邮箱 |
| password_hash | VARCHAR(255) | 密码哈希（bcrypt） |
| role | TINYINT | 0=用户, 1=管理员 |
| status | TINYINT | 0=正常, 1=禁用 |
| created_at / updated_at | DATETIME | 创建/更新时间 |

### 6.2 articles（文章表）
| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | BIGINT PK | 文章 ID |
| author_id | BIGINT FK→users.id | 作者 |
| title | VARCHAR(100) | 标题 |
| content | TEXT | 正文（Markdown） |
| status | TINYINT | 0=草稿, 1=已发布 |
| view_count | INT | 阅读量 |
| created_at / updated_at | DATETIME | 创建/更新时间 |
| deleted_at | DATETIME NULL | 逻辑删除时间 |

### 6.3 comments（评论表）
| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | BIGINT PK | 评论 ID |
| article_id | BIGINT FK→articles.id | 所属文章 |
| user_id | BIGINT FK→users.id | 评论者 |
| parent_id | BIGINT FK→comments.id NULL | 父评论（NULL 为顶层评论） |
| content | VARCHAR(1000) | 评论内容 |
| status | TINYINT | 0=正常, 1=已删除 |
| created_at | DATETIME | 评论时间 |

### 6.4 tags / article_tags（标签表，可选）
- tags：id、name（唯一）。
- article_tags：article_id、tag_id 多对多关联。

## 7. 非功能需求

### 7.1 安全
- 密码使用 bcrypt 加盐哈希存储，禁止明文。
- 登录/接口使用 Token（JWT）鉴权，敏感操作校验会话有效性。
- 防注入：所有 SQL 使用参数化查询。
- 防 XSS：评论与文章正文展示时转义，Markdown 渲染白名单化。
- 接口限流：登录、注册、评论、发文章均有频率限制。

### 7.2 性能
- 文章列表接口 P95 ≤ 300ms；文章详情 P95 ≤ 500ms。
- 阅读量采用异步/延迟写入，不阻塞请求。
- 图片走对象存储 + CDN（如接入）。

### 7.3 兼容性
- 支持 Chrome / Edge / Safari / Firefox 最新两个大版本；移动端响应式。

### 7.4 可用性
- 服务可用性 ≥ 99.9%；数据库每日备份，保留 7 天。

## 8. 验收标准

### 8.1 注册登录（AC-01）
- [ ] 新用户可成功注册，重复用户名/邮箱被拦截并提示。
- [ ] 注册用户可登录、登出；密码错误提示不泄露账号是否存在。
- [ ] 未登录访问受限页面被重定向到登录页。

### 8.2 发文章（AC-02）
- [ ] 登录用户可创建文章并发布，发布后首页列表可见。
- [ ] 草稿仅作者可见，可继续编辑并最终发布。
- [ ] 仅作者可编辑/删除自己的文章，删除需二次确认。

### 8.3 评论（AC-03）
- [ ] 登录用户可评论、回复；游客不可评论且有引导提示。
- [ ] 评论内容为空/超长被拦截。
- [ ] 作者/评论者可按规则删除评论，删除后展示占位。

## 9. 风险与假设

### 9.1 假设
- 假设不包含邮件服务，注册后直接生效；邮件激活与密码找回为可选增强项。
- 假设不包含管理员后台的完整管理界面，管理员能力仅预留数据层与接口。
- 假设正文编辑器采用 Markdown（可低成本切换富文本）。
- 假设单机部署起步，后续可按需扩展。

### 9.2 风险
| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 内容合规风险 | 文章/评论含违规内容 | 敏感词过滤 + 举报入口（二期）+ 管理员下架 |
| 刷评论/垃圾注册 | 社区质量下降 | 频率限制 + 验证码（可选） |
| 图片存储成本 | 存储与带宽成本上升 | 限制大小/格式 + CDN + 压缩 |
| 数据丢失 | 用户内容不可恢复 | 每日备份 + 逻辑删除 |

## 10. 迭代规划（建议）

- **MVP（本期）**：注册/登录、发文章（Markdown）、评论/回复、文章列表与详情。
- **V1.1**：密码找回、邮件激活、标签/分类筛选、个人中心。
- **V1.2**：管理员后台、举报、点赞、阅读统计、全文搜索。
