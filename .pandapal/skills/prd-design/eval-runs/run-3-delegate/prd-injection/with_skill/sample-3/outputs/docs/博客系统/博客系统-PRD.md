## 一、概述与背景

##### 背景
当前缺少一个轻量、易用的个人博客与内容发布平台：作者缺少便捷的内容沉淀与分享渠道，读者缺少集中浏览与互动的社区。现有零散方案（社交平台发文、笔记工具）存在内容易被信息流淹没、无法沉淀结构化、互动数据不透明等问题。需要一个打通「创作 → 发布 → 互动」闭环的完整博客系统，支撑用户注册登录、文章发布与评论互动三大核心能力。

##### 目标
- 目标 1：上线后 4 周内注册用户达到 5,000，其中月活跃作者 ≥ 1,000
- 目标 2：文章发布成功率 ≥ 99.5%，评论发布成功率 ≥ 99%
- 目标 3：文章发布到读者可见的端到端延迟 < 5 秒
- 目标 4：违规内容从举报到处置的平均时长 < 24 小时

##### 角色清单

| 角色 | 职责 | 核心诉求 |
|------|------|---------|
| 访客（未登录用户） | 浏览文章列表与详情、查看评论，触发注册 | 快速找到并阅读感兴趣的内容 |
| 注册用户（作者） | 注册登录、发布/编辑/下线/删除自己的文章、发表评论、管理个人资料 | 顺畅创作与表达，获得互动反馈 |
| 管理员 | 用户管理、内容审核与治理（删除违规文章/评论、封禁账号） | 高效维护平台内容安全与秩序 |

##### 场景清单

### 场景 1：新用户注册（核心）
- **发生时态**：首次
- **角色**：访客
- **目标**：创建账号成为注册用户，获得发布文章与评论的资格
- **前置条件**：访客处于未登录状态进入注册页；用户名未被占用、邮箱合法且未注册

### 场景 2：用户登录（核心）
- **发生时态**：日常
- **角色**：注册用户
- **目标**：通过账号密码登录，进入个人工作台开始创作
- **前置条件**：账号已注册且状态为 active（未被封禁）；输入正确的用户名/邮箱与密码

### 场景 3：浏览文章与评论（核心）
- **发生时态**：日常
- **角色**：访客、注册用户
- **目标**：浏览文章列表、搜索/筛选文章、阅读文章详情并查看评论
- **前置条件**：系统存在已发布的文章；浏览不要求登录

### 场景 4：发布文章（核心）
- **发生时态**：日常
- **角色**：注册用户
- **目标**：撰写并发布一篇文章，使读者可见
- **前置条件**：用户已登录；文章标题/正文通过内容校验；可先存草稿再发布

### 场景 5：发表评论（核心）
- **发生时态**：日常
- **角色**：注册用户
- **目标**：在文章详情页发表评论，参与讨论
- **前置条件**：用户已登录；文章状态为已发布；评论内容非空且通过校验

### 场景 6：个人文章管理（边缘）
- **发生时态**：日常
- **角色**：注册用户
- **目标**：查看/编辑/下线/删除自己的文章，管理草稿
- **前置条件**：用户已登录；仅能操作 author_id 属于自己的文章

### 场景 7：管理员内容治理（边缘）
- **发生时态**：日常/异常
- **角色**：管理员
- **目标**：删除违规文章/评论、封禁违规用户，维护平台秩序
- **前置条件**：管理员已登录且角色为 admin；接到举报或巡检发现违规内容

### 场景 8：异常与边界场景（边缘）
- **发生时态**：异常
- **角色**：访客、注册用户、管理员
- **目标**：在网络中断、数据为空、无权限、并发冲突时获得合理反馈，而非报错/白屏
- **前置条件**：任意操作过程中出现网络异常 / 列表数据为空 / 越权操作 / 多人同时编辑同一文章

##### 场景-角色矩阵

| 场景 | 角色 | 核心/边缘 | 发生时态 |
|------|------|----------|---------|
| 新用户注册 | 访客 | 核心 | 首次 |
| 用户登录 | 注册用户 | 核心 | 日常 |
| 浏览文章与评论 | 访客、注册用户 | 核心 | 日常 |
| 发布文章 | 注册用户 | 核心 | 日常 |
| 发表评论 | 注册用户 | 核心 | 日常 |
| 个人文章管理 | 注册用户 | 边缘 | 日常 |
| 管理员内容治理 | 管理员 | 边缘 | 日常/异常 |
| 异常与边界 | 全部角色 | 边缘 | 异常 |

## 三、核心业务数据流

### 3.1 数据流分类

### 3.2 业务链路

#### 核心链路 1：文章发布链路

```text
┌──────────┐  点击「发布」   ┌──────────┐  校验通过   ┌──────────┐   写入存储   ┌──────────┐
│ 写文章页  │ ─────────────► │ 文章发布  │ ─────────► │ 内容存储  │ ──────────► │ 文章列表  │
└──────────┘                └────┬─────┘            └──────────┘            └────┬─────┘
                                 │                                               │
                                 │ <校验失败/未登录>                              │ 读者浏览
                                 ▼                                               ▼
                           ┌──────────┐                                      ┌──────────┐
                           │ 拦截与提示│                                      │ 文章详情  │
                           └──────────┘                                      └──────────┘
```

**链路说明**：作者在写文章页点击「发布」→ 文章发布模块校验登录态、标题/正文/标签合法性 → 通过后写入内容存储（status=published）→ 文章进入首页列表 → 读者浏览进入详情页。

#### 核心链路 2：评论互动链路

```text
┌──────────┐  输入评论+提交  ┌──────────┐  校验通过   ┌──────────┐  关联文章   ┌──────────┐
│ 文章详情页 │ ─────────────► │ 评论模块  │ ─────────► │ 评论存储  │ ─────────► │ 评论列表  │
└──────────┘                └────┬─────┘            └──────────┘            └────┬─────┘
                                 │                                               │
                                 │ <未登录/命中敏感词>                            │ 其他读者查看
                                 ▼                                               ▼
                           ┌──────────┐                                      ┌──────────┐
                           │ 拦截/待审核│                                     │ 评论展示区 │
                           └──────────┘                                      └──────────┘
```

**链路说明**：用户在文章详情页发表评论 → 评论模块校验登录态与内容（1~1000 字）→ 命中敏感词则进入待审核，否则写入评论存储 → 评论挂载到文章评论区 → 其他读者可见。

#### 核心链路 3：内容治理链路（管理员）

```text
┌──────────┐  巡检/收到举报  ┌──────────┐  审核确认   ┌──────────┐  触发联动   ┌──────────┐
│ 管理后台  │ ─────────────► │ 违规内容  │ ─────────► │ 内容处置  │ ──────────► │ 下线/删除 │
└──────────┘                │ 列表     │            └────┬─────┘            └──────────┘
                           └──────────┘                 │ <情节严重>
                                                        ▼
                                                  ┌──────────┐
                                                  │ 用户封禁  │
                                                  └──────────┘
```

**链路说明**：管理员巡检或收到举报 → 在管理后台查看违规文章/评论 → 确认后执行下线或删除 → 情节严重者联动封禁用户，封禁后该用户无法登录与发布。

### 3.3 状态流转

#### 文章状态机

```text
      ┌──────────┐  保存为草稿  ┌──────────┐  点击发布   ┌──────────┐  作者/管理员下线 ┌──────────┐
 ────►│   草稿    │ ──────────► │  已发布   │ ─────────► │  已下线   │ ─────────────► │  已删除   │
      └─────┬────┘             └─────┬────┘            └─────┬────┘              └──────────┘
            │ 删除草稿               │ 作者编辑（内容更新）      │ 重新发布
            ▼                        ▼                        ▼
      ┌──────────┐             已发布（更新）             ┌──────────┐
      │ 已删除    │                                       │  已发布   │
      └──────────┘                                       └──────────┘
```

##### 状态定义

| 状态 | 含义 | 允许的下一状态 | 触发迁移的动作/条件 |
|------|------|---------------|-------------------|
| 草稿 | 作者创建但未发布，仅作者可见 | 已发布, 已删除 | 作者点击发布；作者删除草稿 |
| 已发布 | 文章对全部访客可见 | 已下线, 已删除 | 作者/管理员下线；管理员删除 |
| 已下线 | 文章被下线，读者不可见，作者可编辑 | 已发布, 已删除 | 作者重新发布；作者/管理员删除 |
| 已删除 | 文章逻辑删除（软删除），仅后台可查 | — | — |

##### 非法迁移

| 从 | 到 | 拒绝原因 | 系统行为 |
|----|-----|---------|---------|
| 草稿 | 已下线 | 未发布内容无需下线 | 拒绝操作，提示先发布 |
| 已删除 | 已发布 | 已删除内容不可恢复上线 | 拒绝操作，提示已删除（可申请管理员恢复） |
| 已发布 | 草稿 | 发布内容不可退回草稿（编辑直接更新） | 拒绝，引导进入编辑态 |

#### 评论状态机

```text
      ┌──────────┐  发表评论   ┌──────────┐  命中敏感词/被举报  ┌──────────┐
 ────►│  已提交   │ ─────────► │   正常    │ ─────────────────► │  待审核   │
      └──────────┘            └─────┬────┘                   └─────┬────┘
                                    │ 作者/管理员删除               │ 审核通过/驳回
                                    ▼                              ▼
                              ┌──────────┐                   ┌──────────┐
                              │  已删除   │                   │ 正常/已删除│
                              └──────────┘                   └──────────┘
```

##### 状态定义

| 状态 | 含义 | 允许的下一状态 | 触发迁移的动作/条件 |
|------|------|---------------|-------------------|
| 正常 | 评论对读者可见 | 待审核, 已删除 | 命中敏感词/被举报进入审核；作者/管理员删除 |
| 待审核 | 评论暂时隐藏，仅管理员可见 | 正常, 已删除 | 管理员审核通过/驳回 |
| 已删除 | 评论逻辑删除，读者不可见 | — | — |

### 3.4 数据字典

> **字段级契约**：让研发不用来回追问"这个字段是啥类型？能为空吗？取值范围？"

#### 用户（user）

- 所有 ID 用 `xxx_id`（如 `article_id`），时间戳用 `xxx_at`（如 `created_at`），布尔值用 `is_xxx`（本期无布尔字段，预留规范）

### 3.5 流转规则

| 规则 | 触发条件 | 行为 |
|------|---------|------|
| 注册唯一性 | 用户名/邮箱已存在 | 拒绝注册并提示已占用 |
| 发布前置校验 | 未登录 / 账号 status≠active | 拦截发布，引导登录 |
| 评论敏感词拦截 | 评论命中敏感词库 | 评论进入待审核，不直接展示 |
| 文章删除级联 | 文章被删除 | 该文章下评论同步逻辑删除 |
| 越权拦截 | 操作非本人文章/评论 | 拒绝并提示无权限 |
| 浏览量去重 | 同一用户 10 分钟内重复浏览同一文章 | 不重复计数 |

## 四、需求详细描述

### 4.1 背景与目标

打通「创作 → 发布 → 互动」闭环：让用户能注册登录、发布文章、浏览内容、发表评论，管理员可治理违规内容，形成可持续的内容社区。

##### 本期范围
- ✅ 包含：用户注册/登录/登出、文章发布（含草稿）、文章浏览与搜索、评论发表与删除、个人文章管理、管理员内容治理（下线/删除/封禁）
- ❌ 不包含：移动端 App、私信、关注关系、打赏、富文本编辑器（本期用 Markdown 编辑器）、多语言、找回密码的完整实现（见缺口标注）

### 4.2 用户故事

#### Story 1：新用户注册
- **作为** 访客
- **我希望** 在注册页输入邮箱、用户名、密码并填写邮箱验证码，即可创建账号
- **以便** 获得发布文章与发表评论的资格
- **没有这个功能，用户会怎样？** 访客永远只能浏览，无法成为创作者，社区无法形成
- **优先级**：P0

#### Story 2：用户登录与登出
- **作为** 注册用户
- **我希望** 用用户名/邮箱+密码登录并保持登录态，需要时登出
- **以便** 快速进入个人工作台开始创作
- **没有这个功能，用户会怎样？** 每次操作都要重新认证，创作体验断裂
- **优先级**：P0

#### Story 3：发布文章
- **作为** 注册用户
- **我希望** 在写文章页填写标题、正文、标签，可先存草稿后发布
- **以便** 将我的内容沉淀并分享给读者
- **没有这个功能，用户会怎样？** 平台没有内容供给，博客系统名存实亡
- **优先级**：P0

#### Story 4：浏览与搜索文章
- **作为** 访客/注册用户
- **我希望** 在首页浏览文章列表、按标签筛选、搜索关键词，并阅读文章详情
- **以便** 高效找到并阅读感兴趣的内容
- **没有这个功能，用户会怎样？** 内容无法被发现，读者流失
- **优先级**：P0

#### Story 5：发表评论
- **作为** 注册用户
- **我希望** 在文章详情页发表评论，并可删除自己的评论
- **以便** 与作者和其他读者交流观点
- **没有这个功能，用户会怎样？** 阅读成为单向行为，缺少互动与社区感
- **优先级**：P0

#### Story 6：管理自己的文章
- **作为** 注册用户
- **我希望** 在我的文章页编辑、下线或删除自己发布的文章
- **以便** 维护内容质量、修正错误或撤回不适内容
- **没有这个功能，用户会怎样？** 内容一经发布无法维护，作者体验受损
- **优先级**：P1

#### Story 7：管理员内容治理
- **作为** 管理员
- **我希望** 在管理后台查看并处置违规文章/评论，可封禁违规用户
- **以便** 维护平台内容安全与社区秩序
- **没有这个功能，用户会怎样？** 违规内容无法管控，平台存在合规风险
- **优先级**：P1

### 4.3 功能清单

#### 4.3.1 用户注册模块

##### 1. 提交注册信息

| 四步 | 说明 |
|------|------|
| **触发** | 访客在注册页填写邮箱、用户名、密码，点击「注册」；前置：未登录 |
| **反馈** | 按钮进入加载态；校验通过后跳转登录页并提示「注册成功，请登录」 |
| **规则** | 用户名 3~20 位字母数字下划线且全局唯一；邮箱格式合法且唯一；密码 ≥ 8 位且含字母+数字；需填写邮箱验证码 |
| **循环** | 校验失败停留在注册页并定位错误字段；成功后引导登录，可再次注册新账号 |

##### 2. 邮箱验证码

| 四步 | 说明 |
|------|------|
| **触发** | 用户点击「发送验证码」；前置：邮箱格式合法且未注册 |
| **反馈** | 按钮进入 60 秒倒计时；提示邮件已发送 |
| **规则** | 60 秒内不可重复发送；验证码 6 位数字，有效期 10 分钟，错误 5 次作废 |
| **循环** | 倒计时结束后可再次发送；验证码过期/作废后需重新获取 |

##### 异常分支

| 异常类型 | 触发条件 | 系统行为 | 用户提示 |
|---------|---------|---------|---------|
| 网络异常 | 发送验证码/提交注册请求超时 | 自动重试 2 次，仍失败则放弃 | Toast「网络异常，请稍后重试」 |
| 数据异常 | 用户名/邮箱已存在、验证码错误 | 拦截提交并标记字段 | 「用户名已被占用」「验证码错误」 |
| 权限异常 | 已登录状态访问注册页 | 重定向 | 跳转首页 |
| 并发冲突 | 同一用户名同时注册 | 唯一索引兜底，后提交者失败 | 「用户名已被占用」 |
| 业务异常 | 邮箱已注册但用户再次尝试注册 | 拦截并引导登录 | 「该邮箱已注册，请直接登录」 |

##### 业务规则
- 规则 1：同一 IP 每小时最多注册 10 个账号
- 规则 2：注册即创建 role=user、status=active 的账号
- 规则 3：密码仅存 bcrypt 哈希，任何场景不回显明文

##### 全局状态

| 状态 | 呈现方式 |
|------|---------|
| 加载态 | 按钮 Loading + 禁用重复点击 |
| 空状态 | 不适用（表单页） |
| 错误态 | 字段级红字提示 + 顶部 Toast |
| 成功态 | 跳转登录页 + 成功提示 |
| 确认操作 | 发送验证码无需二次确认 |
| 撤销操作 | 注册不可撤销，但支持后续注销（不在本期范围） |

## 五、验收标准

### AC-01：正常注册流程
- **Given**：访客在注册页输入合法且未被占用的邮箱、用户名和密码，并收到正确的邮箱验证码
- **When**：用户填写验证码并点击「注册」
- **Then**：注册成功，系统创建 role=user、status=active 的账号，跳转登录页并提示「注册成功，请登录」；数据库新增 1 条 user 记录

### AC-02：注册重名校验（边界）
- **Given**：用户名「tom」已被占用
- **When**：新用户尝试用「tom」注册
- **Then**：注册被拦截，用户名输入框下方红字提示「用户名已被占用」，不产生新用户记录

### AC-03：正常发布文章
- **Given**：注册用户已登录，写文章页已填写合法标题、正文和标签
- **When**：用户点击「发布」
- **Then**：文章状态变为已发布，跳转详情页；首页文章列表按时间倒序可见该文章；记录 published_at

### AC-04：发布校验失败
- **Given**：用户已登录但未填写标题
- **When**：用户点击「发布」
- **Then**：发布被拦截并提示「请填写标题」，文章保持草稿状态不对外可见

### AC-05：正常发表评论
- **Given**：注册用户已登录，打开一篇已发布文章的详情页
- **When**：用户输入 1~1000 字评论并点击「发表」
- **Then**：评论（未命中敏感词）立即展示在评论区；文章 comment_count +1

### AC-06：评论敏感词审核（异常）
- **Given**：用户评论内容命中敏感词库
- **When**：用户点击「发表」
- **Then**：评论不直接展示，状态进入待审核；提示「评论需审核后展示」；管理后台可见该待审核评论

### AC-07：越权操作拦截（异常）
- **Given**：用户 A 已登录，浏览用户 B 的文章
- **When**：A 尝试编辑/删除 B 的文章
- **Then**：操作被拒绝并提示「无权限操作该文章」，B 的文章不受影响

### AC-08：网络中断容错（异常）
- **Given**：用户已登录，在写文章页完成编辑，网络连接中断
- **When**：用户点击「保存草稿」
- **Then**：系统提示「网络异常，内容已保留」，本地已输入内容不丢失，恢复后可重试

### AC-09：空数据展示（边界）
- **Given**：系统尚无任何文章（article 表为空）
- **When**：访客打开首页
- **Then**：首页展示空状态「暂无内容，来发布第一篇文章吧」，不报错、不白屏

### AC-10：评论超长拦截（边界）
- **Given**：用户输入 1001 字评论
- **When**：用户点击「发表」
- **Then**：评论被拦截并提示「评论最多 1000 字」，内容保留供用户删改
