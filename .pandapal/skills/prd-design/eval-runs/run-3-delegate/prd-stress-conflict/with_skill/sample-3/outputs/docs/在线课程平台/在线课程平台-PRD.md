# PRD · 在线课程平台

> 版本：v1.0 | 日期：2026-02-19 | 复杂度：复杂

---

## 一、概述与背景

##### 背景

当前课程内容分发、作业布置与批改、成绩反馈分散在不同工具中，学生需要在多个系统间切换，讲师无法在一个地方完成"上传课程→布置作业→批改评分"的全流程，平台也缺少课程上架前的质量审核机制。需要一个一体化的在线课程平台，把"课程→作业→成绩"闭环打通，并引入管理员审核保障上架内容合规。

##### 目标

- 目标 1：打通"看课→做作业→提交→批改→看成绩"完整闭环，学生作业提交率提升至 85% 以上
- 目标 2：课程从提交审核到上架的**平均审核时长 ≤ 24 小时**，上架审核覆盖率 100%
- 目标 3：违规/劣质课程在审核环节 100% 拦截，不进入学生可见范围
- 目标 4：学生端核心操作（看课、交作业、看成绩）可用性 ≥ 99.9%

##### 角色清单

| 角色 | 职责 | 核心诉求 |
|------|------|---------|
| 学生 | 浏览学习课程、做作业、提交作业、查看成绩 | 学习链路顺畅，作业不丢、成绩即时可见 |
| 讲师 | 上传课程、布置作业、批改作业 | 教学管理一处完成，批改高效，学生提交不遗漏 |
| 管理员 | 审核课程上架、违规下架 | 审核流程清晰、可追溯，劣质内容不进平台 |

##### 场景清单

### 场景 1：学生浏览与学习课程（核心）

- **发生时态**：日常
- **角色**：学生
- **目标**：在课程列表中发现已上架课程，进入详情页学习内容，并找到课程配套作业入口
- **前置条件**：学生已登录并完成选课；课程状态为「已上架」

### 场景 2：学生做作业并提交（核心）

- **发生时态**：日常
- **角色**：学生
- **目标**：在截止时间前完成作答并提交，提交后进入讲师批改队列
- **前置条件**：学生已选该课程；作业已布置且处于可提交时间窗内

### 场景 3：学生查看成绩（核心）

- **发生时态**：日常
- **角色**：学生
- **目标**：查看每次作业得分与讲师评语，了解学习情况
- **前置条件**：讲师已完成批改；成绩已写入该学生的提交记录

### 场景 4：讲师上传课程（核心）

- **发生时态**：日常
- **角色**：讲师
- **目标**：上传课程内容（视频/图文）并提交审核，等待管理员放行
- **前置条件**：讲师已登录且通过实名认证；课程为草稿或驳回修改态

### 场景 5：讲师布置作业（核心）

- **发生时态**：日常
- **角色**：讲师
- **目标**：为自己的已上架课程创建作业，设置截止时间与满分，对学生可见
- **前置条件**：课程已上架或至少处于讲师可管理的状态

### 场景 6：讲师批改作业（核心）

- **发生时态**：日常
- **角色**：讲师
- **目标**：查看学生提交列表，逐份打分、写评语，批改结果回传学生
- **前置条件**：有学生已提交作业；讲师拥有该课程的批改权限

### 场景 7：管理员审核课程上架（核心）

- **发生时态**：日常
- **角色**：管理员
- **目标**：对待审核课程逐份检查内容合规性，给出「通过上架」或「驳回」决定
- **前置条件**：讲师已提交审核；课程状态为「待审核」

### 场景 8：提交作业时断网/超时（边缘）

- **发生时态**：异常
- **角色**：学生
- **目标**：在网络异常下提交不丢失，恢复后能重试完成提交
- **前置条件**：学生在作答页点击提交时网络中断

### 场景 9：截止时间高峰并发提交（边缘）

- **发生时态**：峰值
- **角色**：学生
- **目标**：大量学生在截止前集中提交，系统不丢单、不超时
- **前置条件**：一门课选课人数多（如 1000+），截止前 10 分钟提交量激增

##### 场景-角色矩阵

| 场景 | 角色 | 核心/边缘 | 发生时态 |
|------|------|----------|---------|
| 浏览学习课程 | 学生 | 核心 | 日常 |
| 做作业并提交 | 学生 | 核心 | 日常 |
| 查看成绩 | 学生 | 核心 | 日常 |
| 上传课程 | 讲师 | 核心 | 日常 |
| 布置作业 | 讲师 | 核心 | 日常 |
| 批改作业 | 讲师 | 核心 | 日常 |
| 审核课程上架 | 管理员 | 核心 | 日常 |
| 提交断网/超时 | 学生 | 边缘 | 异常 |
| 截止高峰并发 | 学生 | 边缘 | 峰值 |

## 三、核心业务数据流

### 3.1 数据流分类

本章包含三种视角：**业务链路**（数据怎么走）、**状态流转**（对象生命周期）、**数据字典**（对象长什么样）。

### 3.2 业务链路

#### 核心链路 1：课程上架链路（讲师 → 管理员 → 学生）

```text
┌──────────┐   创建并提交审核    ┌──────────┐   审核{课程}    ┌──────────┐
│ 讲师·课程  │ ─────────────────► │ 管理员·审核 │ ─────────────► │ 已上架    │
│ 管理      │                    └────┬─────┘                └────┬─────┘
└──────────┘                         │                           │
                                     │ <驳回>                    │ 学生可见
                                     ▼                           ▼
                               ┌──────────┐                ┌──────────┐
                               │ 退回草稿  │                │ 学习中心  │
                               │(讲师修改) │                │ 课程列表  │
                               └──────────┘                └──────────┘
```

**链路说明**：讲师在课程管理页创建课程并提交审核 → 课程进入「待审核」→ 管理员在审核台审核 → 通过则上架、学生列表可见；驳回则退回草稿并附驳回原因，讲师修改后重新提交。

#### 核心链路 2：作业闭环链路（讲师 → 学生 → 讲师 → 学生）

```text
┌──────────┐   布置作业{作业}   ┌──────────┐   提交{作答}    ┌──────────┐
│ 讲师·作业  │ ─────────────────► │ 学生·作业  │ ─────────────► │ 讲师·批改  │
│ 管理      │                    │ 作答      │                └────┬─────┘
└──────────┘                    └────┬─────┘                     │ 评分{成绩}
                                     │ <逾期未交>                 ▼
                                     ▼                     ┌──────────┐
                               ┌──────────┐               │ 学生·成绩  │
                               │ 标记逾期  │               │ 查看      │
                               └──────────┘               └──────────┘
```

**链路说明**：讲师对已上架课程布置作业（含截止时间）→ 学生在可提交时间窗内作答并提交 → 讲师在批改页打分写评语 → 成绩写入提交记录，学生成绩页即时可见并收到通知。

### 3.3 状态流转

#### 课程状态机

```text
      ┌──────────┐  讲师提交审核   ┌──────────┐  审核通过    ┌──────────┐
 ────►│  草稿    │ ───────────────►│  待审核  │ ───────────►│  已上架  │
      └──────────┘                 └─────┬────┘             └────┬─────┘
                                         │ 审核驳回               │ 管理员下架
                                         ▼                        ▼
                                   ┌──────────┐             ┌──────────┐
                                   │ 退回草稿  │             │  已下架  │
                                   └──────────┘             └──────────┘
```

##### 状态定义

| 状态 | 含义 | 允许的下一状态 | 触发迁移的动作/条件 |
|------|------|---------------|-------------------|
| 草稿 | 讲师创建但未提交审核 | 待审核 | 讲师点击「提交审核」 |
| 待审核 | 等待管理员审核 | 已上架, 退回草稿 | 管理员通过 / 管理员驳回 |
| 已上架 | 对学生可见，可布置作业 | 已下架 | 管理员下架（违规） |
| 已下架 | 学生不可见，历史提交保留 | 草稿 | 管理员重新开放编辑 |

##### 非法迁移

| 从 | 到 | 拒绝原因 | 系统行为 |
|----|-----|---------|---------|
| 草稿 | 已上架 | 未经验证不允许直接上架 | 拒绝，提示先提交审核 |
| 待审核 | 已下架 | 未上架内容无下架语义 | 拒绝，仅可驳回 |
| 已下架 | 待审核 | 需先进入草稿修改 | 引导先转为草稿 |

#### 作业提交状态机

```text
      ┌──────────┐  学生提交作业   ┌──────────┐  讲师批改完成  ┌──────────┐
 ────►│  待提交  │ ───────────────►│  已提交  │ ─────────────►│  已批改  │
      └─────┬────┘                 └──────────┘               └──────────┘
            │ 截止时间到且未提交
            ▼
      ┌──────────┐
      │  已逾期  │
      └──────────┘
```

##### 状态定义

| 状态 | 含义 | 允许的下一状态 | 触发迁移的动作/条件 |
|------|------|---------------|-------------------|
| 待提交 | 作业已布置，学生未提交 | 已提交, 已逾期 | 学生提交 / 截止时间到 |
| 已提交 | 学生已提交，等待批改 | 已批改 | 讲师完成批改 |
| 已批改 | 批改完成，含成绩与评语 | — | — |
| 已逾期 | 截止时间到仍未提交 | —（[待确认]是否允许补交） | 系统定时任务标记 |

##### 非法迁移

| 从 | 到 | 拒绝原因 | 系统行为 |
|----|-----|---------|---------|
| 已逾期 | 已提交 | 默认截止后不接受提交 | 拒绝提交，提示已截止（[待确认]补交策略） |
| 已批改 | 已提交 | 成绩已生效 | 拒绝，需讲师撤回批改（需二次确认） |

### 3.4 数据字典

> **字段级契约**：让研发不用来回追问"这个字段是啥类型？能为空吗？取值范围？"

#### 用户（user）

| 字段名 | 类型 | 必填 | 约束/取值域 | 业务含义 | 来源 |
|-------|------|-----|-------------|---------|------|
| user_id | string | ✅ | UUID | 用户唯一标识 | 系统生成 |
| role | enum | ✅ | student / teacher / admin | 角色 | 系统分配 |
| name | string | ✅ | ≤50 字符 | 姓名/昵称 | 用户输入 |
| email | string | ✅ | 邮箱格式 | 登录账号与通知 | 用户输入 |
| created_at | datetime | ✅ | ISO8601 | 注册时间 | 系统生成 |

#### 课程（course）

| 字段名 | 类型 | 必填 | 约束/取值域 | 业务含义 | 来源 |
|-------|------|-----|-------------|---------|------|
| course_id | string | ✅ | UUID | 课程唯一标识 | 系统生成 |
| teacher_id | string | ✅ | 引用 user_id | 授课讲师 | 系统生成 |
| title | string | ✅ | ≤100 字符 | 课程标题 | 讲师输入 |
| description | string | ✅ | ≤2000 字符 | 课程简介 | 讲师输入 |
| content_url | string | ✅ | 视频/图文资源地址 | 课程内容 | 讲师上传 |
| status | enum | ✅ | draft / pending / online / offline | 课程状态 | 系统生成 |
| reject_reason | string | ❌ | ≤500 字符 | 审核驳回原因 | 管理员输入 |
| created_at / updated_at | datetime | ✅ | ISO8601 | 创建/更新时间 | 系统生成 |

#### 作业（assignment）

| 字段名 | 类型 | 必填 | 约束/取值域 | 业务含义 | 来源 |
|-------|------|-----|-------------|---------|------|
| assignment_id | string | ✅ | UUID | 作业唯一标识 | 系统生成 |
| course_id | string | ✅ | 引用 course_id | 所属课程 | 系统生成 |
| title | string | ✅ | ≤100 字符 | 作业标题 | 讲师输入 |
| description | string | ✅ | ≤2000 字符 | 作业要求 | 讲师输入 |
| deadline | datetime | ✅ | ISO8601 | 截止时间 | 讲师输入 |
| full_score | int | ✅ | 1~100 | 满分 | 讲师输入 |

#### 作业提交（submission，含成绩）

| 字段名 | 类型 | 必填 | 约束/取值域 | 业务含义 | 来源 |
|-------|------|-----|-------------|---------|------|
| submission_id | string | ✅ | UUID | 提交唯一标识 | 系统生成 |
| assignment_id | string | ✅ | 引用 assignment_id | 对应作业 | 系统生成 |
| student_id | string | ✅ | 引用 user_id | 提交学生 | 系统生成 |
| content | text | ✅ | ≤5000 字符或附件 | 作答内容 | 学生输入 |
| status | enum | ✅ | pending / submitted / graded / overdue | 提交状态 | 系统生成 |
| score | int | ❌ | 0~full_score | 得分 | 讲师输入 |
| comment | string | ❌ | ≤500 字符 | 批改评语 | 讲师输入 |
| submitted_at | datetime | ✅ | ISO8601 | 提交时间 | 系统生成 |
| graded_at | datetime | ❌ | ISO8601 | 批改时间 | 系统生成 |

**字段命名约定**：所有 ID 用 `xxx_id`，时间戳用 `xxx_at`，布尔值用 `is_xxx`，状态用 `status`。

**跨对象引用**：

| 引用字段 | 指向对象 | 引用类型 | 级联行为 |
|---------|---------|---------|---------|
| submission.student_id | user | 多对1 | 学生注销时保留成绩快照 |
| submission.assignment_id | assignment | 多对1 | 作业删除时级联删除提交记录 |
| assignment.course_id | course | 多对1 | 课程下架不影响历史提交 |

### 3.5 流转规则

| 规则 | 触发条件 | 行为 |
|------|---------|------|
| 自动逾期 | 截止时间到且状态为待提交 | 系统将状态置为「已逾期」并通知学生 |
| 审核驳回 | 管理员驳回 | 课程回到「草稿」并附 reject_reason，讲师修改后可重新提交 |
| 提交后锁定 | 学生提交成功 | 默认不可修改（[待确认]是否支持撤回重交） |
| 批改完成通知 | 讲师保存批改 | 成绩写入 submission，学生成绩页可见并收到通知 |
| 上架可见性 | 课程状态变为已上架 | 立即出现在学生课程列表 |

### 3.6 缺口标注

- 🟡 **当前状态**：作业批改方式（人工打分 vs 客观题自动判分）、是否支持多轮重交、成绩是否需要跨作业汇总，均未在需求中明确。
- 🟢 **需补充的内容**：作业类型（单选/多选/简答/附件）、成绩展示粒度（单次 vs 汇总均分）、逾期是否允许补交及补交规则。
- 🔵 **影响范围**：作业模块与成绩模块的数据模型、状态机与权限设计。

## 四、需求详细描述

### 4.1 背景与目标

一期建设目标是打通"课程→作业→成绩"闭环：学生能看课、做作业、提交、看成绩；讲师能上传课程、布置作业、批改作业；管理员能审核课程上架。三方在同一个平台内协作，减少工具切换。

##### 本期范围

- ✅ 包含：课程浏览学习、作业布置/作答/提交/批改、成绩查看、课程审核上架/下架、通知触达
- ❌ 不包含：课程付费/交易、直播课、客观题自动判分、多机构/多租户、移动端原生 App（本期仅响应式 Web）

### 4.2 用户故事

#### Story 1：学生提交作业（P0）
- **作为** 已选课的学生
- **我希望** 在截止前进入作业页完成作答并提交
- **以便** 作业被系统记录并进入讲师批改队列，不担心丢失
- **没有这个功能，用户会怎样？** 作业闭环断裂，教学无法推进
- **优先级**：P0

#### Story 2：讲师上传课程（P0）
- **作为** 讲师
- **我希望** 上传课程内容并提交审核
- **以便** 课程经管理员审核后对学生可见
- **没有这个功能，用户会怎样？** 课程永远无法上架，平台无内容
- **优先级**：P0

#### Story 3：管理员审核课程（P0）
- **作为** 管理员
- **我希望** 对待审核课程逐份审核并给出通过/驳回决定
- **以便** 平台只上架合规、优质的课程
- **没有这个功能，用户会怎样？** 课程积压在待审核态，劣质内容无拦截
- **优先级**：P0

#### Story 4：学生浏览学习课程（P1）
- **作为** 学生
- **我希望** 在课程列表中发现已上架课程并进入详情学习
- **以便** 随时按需学习
- **没有这个功能，用户会怎样？** 学生无学习入口
- **优先级**：P1

#### Story 5：讲师布置作业（P1）
- **作为** 讲师
- **我希望** 为自己的课程布置作业并设置截止时间
- **以便** 学生有明确的任务与提交时限
- **没有这个功能，用户会怎样？** 无作业环节，只能线下布置
- **优先级**：P1

#### Story 6：讲师批改作业（P1）
- **作为** 讲师
- **我希望** 在学生提交后逐份打分并写评语
- **以便** 学生获得反馈、成绩可量化
- **没有这个功能，用户会怎样？** 提交无反馈，成绩缺失
- **优先级**：P1

#### Story 7：学生查看成绩（P1）
- **作为** 学生
- **我希望** 在成绩页查看每次作业得分与评语
- **以便** 了解自己的学习情况
- **没有这个功能，用户会怎样？** 学习反馈闭环缺失
- **优先级**：P1

#### Story 8：作业截止与批改完成提醒（P2）
- **作为** 学生/讲师
- **我希望** 在截止前与批改完成后收到通知
- **以便** 不遗漏提交与批改
- **没有这个功能，用户会怎样？** 依赖主动刷新，体验下降
- **优先级**：P2

### 4.3 功能清单

#### 4.3.1 课程模块（浏览学习 / 上传 / 审核）

##### 1. 课程列表浏览（学生）

| 四步 | 说明 |
|------|------|
| **触发** | 学生进入课程列表页（已登录、已选课） |
| **反馈** | 展示已上架课程卡片（标题、讲师、简介摘要），加载中显示骨架屏 |
| **规则** | 仅展示 status=online 的课程；按最新上架排序；支持按课程名搜索 |
| **循环** | 点击卡片进入课程详情；可返回列表继续浏览 |

##### 2. 课程详情学习（学生）

| 四步 | 说明 |
|------|------|
| **触发** | 学生点击课程卡片进入详情页 |
| **反馈** | 展示课程内容（视频/图文）与该课程作业入口列表 |
| **规则** | 未选课学生提示先选课；作业入口按状态展示（待做/已提交/已批改） |
| **循环** | 学习完成后可进入作业列表或返回课程列表 |

##### 3. 上传并提交审核（讲师）

| 四步 | 说明 |
|------|------|
| **触发** | 讲师在课程管理页点击「新建课程」，填写标题/简介/上传内容 |
| **反馈** | 保存成功进入草稿列表；点击「提交审核」后状态变为待审核 |
| **规则** | 必填项（标题、简介、内容）缺失时拦截；提交审核后不可再编辑 |
| **循环** | 审核驳回后可编辑重新提交；审核通过后课程上架 |

##### 4. 审核课程（管理员）

| 四步 | 说明 |
|------|------|
| **触发** | 管理员在审核台打开一条待审核课程 |
| **反馈** | 展示课程完整内容与讲师信息；点击「通过」上架 / 「驳回」填原因 |
| **规则** | 驳回必须填写原因；通过后课程立即可见；记录审核人与时间 |
| **循环** | 处理完一条自动进入下一条待审核记录 |

##### 异常分支

| 异常类型 | 触发条件 | 系统行为 | 用户提示 |
|---------|---------|---------|---------|
| 网络异常 | 上传内容时断网 | 暂停上传并保留已上传分片，恢复后续传 | Toast「网络中断，已暂停上传」 |
| 数据异常 | 课程内容为空/格式不支持 | 拦截保存 | 表单错误提示「请填写完整课程信息」 |
| 权限异常 | 非讲师访问课程管理页 | 路由拦截 | 提示「无访问权限」 |
| 并发冲突 | 讲师编辑时管理员下架 | 乐观锁，提示刷新 | 弹窗「课程状态已变更，请刷新」 |
| 业务异常 | 待审核课程被再次提交 | 拒绝重复提交 | 提示「课程已处于待审核状态」 |

##### 业务规则

- 规则 1：仅「已上架」课程对学生可见；讲师可见自己全部状态课程；管理员可见全部。
- 规则 2：提交审核后锁定编辑，驳回后可改；下架后需重新走审核流程。
- 规则 3：审核记录（审核人、时间、结果）全量留痕，可追溯。

##### 全局状态

| 状态 | 呈现方式 |
|------|---------|
| 加载态 | 课程列表骨架屏、详情页 Loading |
| 空状态 | 无课程时展示「暂无课程」+ 引导（学生：去选课；讲师：去创建） |
| 错误态 | 加载失败展示错误页 + 重试按钮 |
| 成功态 | 提交审核成功 Toast + 状态徽标更新 |
| 确认操作 | 「提交审核」「驳回」需二次确认 |
| 撤销操作 | 草稿可删除（回收站保留 7 天）；审核操作不可撤销（留痕） |

#### 4.3.2 作业模块（布置 / 作答 / 提交）

##### 1. 布置作业（讲师）

| 四步 | 说明 |
|------|------|
| **触发** | 讲师在作业管理页选择已上架课程，点击「布置作业」 |
| **反馈** | 填写标题、要求、截止时间、满分，保存后作业进入学生作业列表 |
| **规则** | 截止时间必须晚于当前时间；满分 1~100；仅自己名下课程可选 |
| **循环** | 可继续布置下一份；作业布置后讲师可随时查看提交情况 |

##### 2. 作答与提交（学生）

| 四步 | 说明 |
|------|------|
| **触发** | 学生在作业列表点击「去作答」，在作答页填写内容并点击「提交」 |
| **反馈** | 提交成功 Toast + 状态变为「已提交」；进入批改队列 |
| **规则** | 截止前可提交；提交前校验必填内容；提交后默认锁定 |
| **循环** | 提交后可在列表查看「批改中」状态，批改完成后可查看成绩 |

##### 异常分支

| 异常类型 | 触发条件 | 系统行为 | 用户提示 |
|---------|---------|---------|---------|
| 网络异常 | 提交请求超时/断网 | 作答内容本地暂存，恢复后重试，重复提交去重 | Toast「提交失败，已保存草稿，请重试」 |
| 数据异常 | 作答内容为空 | 拦截提交 | 提示「请填写作答内容」 |
| 权限异常 | 非选课学生访问作答页 | 拦截 | 提示「未选课，无法提交」 |
| 并发冲突 | 截止瞬间多端同时提交 | 以服务端时间为准，超时拒绝 | 提示「已超过截止时间」 |
| 业务异常 | 逾期提交 | 拒绝并标记逾期 | 提示「作业已截止」 |

##### 业务规则

- 规则 1：可提交时间窗 = 布置时刻 ~ 截止时间；截止后状态自动变「已逾期」。
- 规则 2：提交以服务端收到时间为准，防客户端改时间。
- 规则 3：重复提交（网络重试）按 submission_id 幂等去重，不产生重复记录。

##### 全局状态

| 状态 | 呈现方式 |
|------|---------|
| 加载态 | 作答页 Loading、提交按钮 loading 态 |
| 空状态 | 无作业时展示「暂无作业」 |
| 错误态 | 提交失败保留草稿 + 错误提示 |
| 成功态 | 提交成功 Toast + 状态徽标「已提交」 |
| 确认操作 | 提交前弹窗确认「确认提交？提交后不可修改」 |
| 撤销操作 | 提交后不可撤销（[待确认]是否支持撤回重交） |

#### 4.3.3 批改与成绩模块

##### 1. 批改作业（讲师）

| 四步 | 说明 |
|------|------|
| **触发** | 讲师在批改页打开一份「已提交」作业 |
| **反馈** | 展示学生作答内容，讲师填得分与评语，保存后状态变「已批改」 |
| **规则** | 得分 0~满分；评语选填；仅自己课程学生提交可见 |
| **循环** | 可连续批改下一份；批改完成后学生即时可见并收到通知 |

##### 2. 查看成绩（学生）

| 四步 | 说明 |
|------|------|
| **触发** | 学生在成绩页查看各作业得分 |
| **反馈** | 展示得分、评语、批改时间；批改完成有通知 |
| **规则** | 仅本人成绩可见；未批改显示「批改中」 |
| **循环** | 有新批改完成自动刷新/提示 |

##### 异常分支

| 异常类型 | 触发条件 | 系统行为 | 用户提示 |
|---------|---------|---------|---------|
| 网络异常 | 保存批改时断网 | 本地暂存批改草稿，恢复后重试 | Toast「保存失败，请重试」 |
| 数据异常 | 得分超范围/非数字 | 拦截保存 | 提示「得分需在 0~满分之间」 |
| 权限异常 | 讲师批改他人课程作业 | 拦截 | 提示「无该课程批改权限」 |
| 并发冲突 | 讲师批改中学生撤回重交 | 以最新提交为准，提示刷新 | 弹窗「学生提交已更新，请刷新」 |
| 业务异常 | 对未提交作业批改 | 拒绝 | 提示「该学生尚未提交」 |

##### 业务规则

- 规则 1：批改结果写入 submission（score + comment + graded_at），一旦保存即对学生生效。
- 规则 2：成绩页展示每次作业得分与满分；[待确认]是否提供课程均分汇总。

##### 全局状态

| 状态 | 呈现方式 |
|------|---------|
| 加载态 | 批改列表 Loading、成绩页骨架屏 |
| 空状态 | 无提交时展示「暂无学生提交」 |
| 错误态 | 批改保存失败保留草稿 + 重试 |
| 成功态 | 批改保存成功 Toast + 状态徽标「已批改」 |
| 确认操作 | 分数修改需二次确认（涉及已生效成绩） |
| 撤销操作 | 讲师可撤回批改重新评分（留痕，学生端有更新通知） |

## 五、验收标准

### AC-01：学生提交作业成功（正常场景）
- **Given**：学生已选课，作业处于可提交时间窗内，且未提交过
- **When**：学生在作答页填写内容并点击「提交」
- **Then**：提交成功，状态变为「已提交」，进入讲师批改队列，学生收到提交成功提示

### AC-02：提交作业断网重试不丢单（异常场景）
- **Given**：学生点击提交时网络中断
- **When**：作答内容被本地暂存，网络恢复后再次点击提交
- **Then**：提交成功且只生成一条提交记录（幂等去重），无重复数据

### AC-03：截止时间边界提交（边界场景）
- **Given**：作业截止时间为 23:59:59
- **When**：学生在 23:59:59 之前发出提交请求
- **Then**：以服务端收到时间判定，未超时则提交成功；超时则拒绝并提示「作业已截止」，状态标记为「已逾期」

### AC-04：课程审核上架全流程（正常场景）
- **Given**：讲师已提交课程审核，课程状态为「待审核」
- **When**：管理员在审核台点击「通过」
- **Then**：课程状态变为「已上架」，立即出现在学生课程列表；驳回则退回草稿并附原因

### AC-05：越权访问拦截（异常/权限场景）
- **Given**：学生账号访问课程管理页，或讲师访问审核台
- **When**：发起页面访问或接口请求
- **Then**：路由拦截 + 接口返回 403，提示「无访问权限」，不暴露任何业务数据

### AC-06：批改完成成绩即时可见（正常场景）
- **Given**：学生已提交作业，讲师尚未批改
- **When**：讲师保存得分与评语
- **Then**：学生成绩页立即展示得分与评语，并收到批改完成通知

## 六、数据指标

### 6.1 核心成功指标（North Star）
- **指标名**：课程完成率（作业闭环完成率）
- **计算方式**：完成课程全部作业并查看成绩的学生数 ÷ 选课学生数
- **目标值**：上线 12 周后达到 60% 以上
- **数据来源**：平台行为日志 + 提交/成绩库
