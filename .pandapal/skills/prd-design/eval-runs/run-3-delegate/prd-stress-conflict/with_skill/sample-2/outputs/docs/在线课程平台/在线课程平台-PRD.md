# PRD · 在线课程平台

> 版本：v1.0 | 日期：2025-07-20（假设值，落地前请更新） | 复杂度：复杂

## 一、概述与背景

##### 背景
- 当前课程内容分散在网盘、聊天群与线下课堂，学习、作业提交、批改与成绩公布割裂在多个工具中，学生与讲师需在多个系统间反复切换，效率低且数据易丢失。
- 课程上架缺少统一审核入口，内容质量与合规性无法保障；作业与成绩缺乏线上沉淀，历史数据不可追溯。
- 需要一个多角色在线课程平台，将「课程内容 — 作业 — 成绩」闭环线上化，并让管理员对内容上架进行把关。

##### 目标
- 目标 1：打通「讲师上传课程 → 管理员审核 → 上架 → 学生学习」全链路，课程从提交到上架平均耗时 ≤ 24 小时。
- 目标 2：作业「布置 → 提交 → 批改 → 成绩」全流程线上化，作业按时提交率 ≥ 90%，批改完成时效 ≤ 48 小时。
- 目标 3：建立课程内容审核机制，违规/低质课程上架拦截率 100%（人工审核兜底）。
- 目标 4：学生可随时查询成绩与批改反馈，成绩查询接口 P95 响应 < 500ms。

##### 角色清单

| 角色 | 职责 | 核心诉求 |
|------|------|---------|
| 学生 | 浏览并学习课程、完成并提交作业、查看成绩与批改反馈 | 学习顺畅、作业不丢失、成绩透明可查 |
| 讲师 | 创建并上传课程、布置作业、批改作业并评分 | 课程快速上架、作业管理高效 |
| 管理员 | 审核课程内容并决定上架/驳回、下架违规课程、查看运营数据 | 审核流程清晰、内容合规可控 |

##### 场景清单

### 场景 1：学生浏览课程并开始学习（核心）

- **发生时态**：日常
- **角色**：学生
- **目标**：从课程广场找到感兴趣的课程，进入详情页并开始学习（视频/课件），记录学习进度
- **前置条件**：已登录；课程状态为「已上架」

### 场景 2：学生完成并提交作业（核心）

- **发生时态**：日常
- **角色**：学生
- **目标**：在作业截止时间前在线作答/上传附件并提交，支持草稿保存与撤回重交
- **前置条件**：已选学课程；讲师已发布作业；当前时间 ≤ 截止时间

### 场景 3：学生查看成绩（核心）

- **发生时态**：日常
- **角色**：学生
- **目标**：查看每份作业的得分、批改评语与课程总评
- **前置条件**：讲师已完成批改

### 场景 4：讲师上传课程并申请上架（核心）

- **发生时态**：日常
- **角色**：讲师
- **目标**：创建课程、填写信息、上传课件/视频，提交审核并跟踪审核状态
- **前置条件**：已登录；讲师身份已验证

### 场景 5：讲师布置与批改作业（核心）

- **发生时态**：日常
- **角色**：讲师
- **目标**：在课程下布置作业（题目/截止时间/分值），查看提交列表，逐份批改打分并写评语
- **前置条件**：课程已上架（或讲师可见）

### 场景 6：管理员审核课程上架（核心）

- **发生时态**：日常
- **角色**：管理员
- **目标**：查看待审核课程内容，合规则通过上架，不合规则驳回并填写原因
- **前置条件**：讲师已提交审核

### 场景 7：作业提交遇到网络异常（边缘）

- **发生时态**：异常
- **角色**：学生
- **目标**：断网/超时导致提交失败时内容不丢失，恢复后可重试
- **前置条件**：提交过程中网络中断

### 场景 8：开学选课/提交高峰（边缘）

- **发生时态**：峰值
- **角色**：学生、讲师
- **目标**：学期开始大量学生同时选课与提交作业，系统不崩溃、不丢数据
- **前置条件**：高并发请求涌入（预估峰值 5000 提交/分钟）

##### 场景-角色矩阵

| 场景 | 角色 | 核心/边缘 | 发生时态 |
|------|------|----------|---------|
| 学生浏览课程并开始学习 | 学生 | 核心 | 日常 |
| 学生完成并提交作业 | 学生 | 核心 | 日常 |
| 学生查看成绩 | 学生 | 核心 | 日常 |
| 讲师上传课程并申请上架 | 讲师 | 核心 | 日常 |

| 管理员审核课程上架 | 管理员 | 核心 | 日常 |
| 作业提交网络异常 | 学生 | 边缘 | 异常 |
| 开学选课/提交高峰 | 学生、讲师 | 边缘 | 峰值 |

### 2.2 层级说明

| 层级 | 节点 | 说明 |
|------|------|------|
| L0 | 在线课程平台 | 课程、作业、成绩一站式在线教学平台 |
| L1 | 课程中心 | 职责：课程内容从创建、审核到学生学习浏览的全链路 |
| L1 | 作业中心 | 职责：作业布置、提交、批改与成绩的闭环管理 |
| L1 | 平台管理 | 职责：内容审核、账号权限与运营数据支撑 |
| L2 | 课程浏览学习（学生） | 所属域：课程中心；浏览已上架课程、学习内容、记录进度 |
| L2 | 课程管理（讲师） | 所属域：课程中心；创建编辑课程、上传课件、提交审核 |
| L2 | 作业管理（讲师） | 所属域：作业中心；布置作业、批改打分、评语反馈 |
| L2 | 作业提交成绩（学生） | 所属域：作业中心；在线作答、附件提交、成绩查询 |
| L2 | 课程审核（管理员） | 所属域：平台管理；审核队列、通过/驳回、下架管理 |
| L2 | 用户与数据（管理员） | 所属域：平台管理；账号角色管理、数据看板 |

### 2.3 跨域依赖

| 调用方 | 关系 | 被调用方 | 机制说明 |

| 课程中心·课程管理 | 提交审核 | 平台管理·课程审核 | 课程状态由「待审核」进入管理员审核队列 |

### 3.2 业务链路

#### 核心链路 1：课程创建 → 审核 → 上架 → 学习

```text
┌──────────┐ 创建并完善课程  ┌──────────┐ 提交审核  ┌──────────┐ 审核通过  ┌──────────┐
│  讲师端    │ ─────────────►│ 课程草稿   │ ─────────►│ 审核队列   │ ─────────►│ 课程上架   │
└──────────┘               └──────────┘          └────┬─────┘          └────┬─────┘
                                                      │ 驳回（必填原因）        │ 消息通知：课程已上架
                                                      ▼                       ▼
                                                ┌──────────┐            ┌──────────┐
                                                │ 讲师修改后 │            │ 学生浏览   │
                                                │ 重新提交   │            │ 开始学习   │
                                                └──────────┘            └──────────┘
```

### 3.3 状态流转

#### 课程状态机

```text
      ┌──────────┐ 讲师提交审核  ┌──────────┐ 审核通过  ┌──────────┐ 管理员下架  ┌──────────┐
 ────►│   草稿    │ ────────────►│  待审核   │ ─────────►│  已上架   │ ───────────►│  已下架   │
      └──────────┘              └────┬─────┘           └──────────┘            └──────────┘
                                     │ 审核驳回
                                     ▼
                               ┌──────────┐
                               │  已驳回   │
                               └────┬─────┘
                                    │ 讲师修改后重新提交
                                    ▼
                              ┌──────────┐
                              │  待审核   │
                              └──────────┘
```

##### 课程状态定义

| 状态 | 含义 | 允许的下一状态 | 触发迁移的动作/条件 |
|------|------|---------------|-------------------|
| 草稿 | 讲师创建但未提交审核 | 待审核 | 讲师点击「提交审核」 |
| 待审核 | 已在审核队列中 | 已上架, 已驳回 | 管理员审核通过 / 审核驳回 |
| 已上架 | 对学生端可见可学 | 已下架, 待审核 | 管理员下架 / 讲师修改内容触发重新审核（旧版本继续展示） |
| 已驳回 | 内容不合规被退回 | 待审核 | 讲师修改后重新提交 |
| 已下架 | 停止对学生展示 | 待审核 | 讲师修改后重新提交审核 |

##### 课程非法迁移

| 从 | 到 | 拒绝原因 | 系统行为 |
|----|-----|---------|---------|
| 草稿 | 已上架 | 未经过审核流程 | 拒绝，提示先提交审核 |
| 已驳回 | 已上架 | 未经重新审核 | 拒绝，提示重新提交 |
| 已上架 | 已上架（直接改内容） | 内容变更需合规把关 | 内容修改仅保存为草稿版本，需重新审核 |

#### 作业提交状态机

```text
      ┌──────────┐ 截止前提交   ┌──────────┐ 讲师批改  ┌──────────┐
 ────►│  未提交   │ ───────────►│  已提交   │ ─────────►│  已批改   │
      └──────────┘             └────┬─────┘           └──────────┘
                                    │ 截止前撤回/重新提交
                                    ▼
                              ┌──────────┐
                              │  未提交   │
                              └──────────┘
```

##### 作业提交状态定义

| 状态 | 含义 | 允许的下一状态 | 触发迁移的动作/条件 |
|------|------|---------------|-------------------|
| 未提交 | 无有效提交记录 | 已提交 | 学生在截止前提交成功 |
| 已提交 | 已提交待批改 | 已批改, 未提交 | 讲师批改 / 学生在截止前撤回或覆盖提交 |
| 已批改 | 已打分并给出评语 | — | 终态 |

##### 作业提交非法迁移

| 从 | 到 | 拒绝原因 | 系统行为 |
|----|-----|---------|---------|
| 已提交 | 未提交（截止后撤回） | 截止时间已过，保护讲师批改结果的确定性 | 拒绝，提示已截止 |
| 未提交/已提交 | 已批改（学生侧） | 学生无批改权限 | 拒绝，仅讲师可批改 |

#### 作业状态机

```text
      ┌──────────┐ 讲师发布    ┌──────────┐ 截止时间到  ┌──────────┐
 ────►│   草稿    │ ──────────►│  已发布   │ ──────────►│  已截止   │
      └──────────┘            └──────────┘            └──────────┘
```

##### 作业状态定义

| 状态 | 含义 | 允许的下一状态 | 触发迁移的动作/条件 |
|------|------|---------------|-------------------|
| 草稿 | 讲师编辑中未发布 | 已发布 | 讲师点击「发布作业」 |
| 已发布 | 学生可见并可提交 | 已截止 | 系统定时任务到截止时间 |
| 已截止 | 停止接受提交 | — | 终态（讲师仍可批改已提交内容） |

### 3.5 流转规则

| 规则 | 触发条件 | 行为 |
|------|---------|------|
| 截止时间拦截 | 提交时当前时间 > deadline_at | 拒绝提交并提示「已截止」 |
| 上架可见性 | course.status = published | 学生端可见、可学习；非上架课程仅讲师/管理员可见 |
| 内容修改重新审核 | 已上架课程编辑内容并保存 | 旧版本继续展示，新版本进入待审核 |
| 批改生成成绩 | 讲师提交批改 | 生成 grade + feedback，学生成绩单实时可见 |
| 重复提交覆盖 | 截止前再次提交 | 覆盖原提交（attempt_count+1），保留最新版本 |
| 驳回必填原因 | 管理员选择驳回 | 强制填写 review_comment，讲师可见并可修改重提 |
| 提交幂等 | 同一学生同一作业重复请求提交 | 接口幂等，仅生成一条提交记录 |

## 四、需求详细描述

### 4.1 背景与目标

围绕三角色核心诉求，将课程内容、作业、成绩三个业务对象线上化闭环，并以管理员审核保障内容合规。本期聚焦 Web 端核心流程，数据埋点仅预留点位。

##### 本期范围

- ✅ 包含：课程创建/编辑/上传课件、提交审核、审核通过/驳回/下架、课程浏览与学习（视频/课件/进度）、作业布置/发布/截止、作业在线作答/附件提交/草稿/撤回、批改打分/评语、成绩查询与总评、角色权限、基础数据看板。
- ❌ 不包含：付费与订单、直播/互动课堂、社区讨论、移动端 App、完整数据埋点方案设计。

### 4.2 用户故事

#### Story 1：讲师上传课程并提交审核（P0）
- **作为** 讲师
- **我希望** 创建课程、填写信息、上传课件并一键提交审核，随时查看审核状态
- **以便** 课程内容能尽快合规上架给学生学习
- **没有这个功能，用户会怎样？** 课程只能线下分发或绕过平台，无法规模化教学
- **优先级**：P0

#### Story 2：学生提交作业（P0）
- **作为** 学生
- **我希望** 在截止时间前在线作答/上传附件并提交，可保存草稿、撤回重交
- **以便** 作业按时提交且不因网络问题丢失
- **没有这个功能，用户会怎样？** 作业闭环断裂，讲师无法批量批改
- **优先级**：P0

#### Story 3：管理员审核课程上架（P0）
- **作为** 管理员
- **我希望** 在审核队列中查看课程完整内容，通过则上架、不合规则驳回并写明原因
- **以便** 保证平台上架内容合规、质量可控
- **没有这个功能，用户会怎样？** 无内容把关，违规内容直接触达学生，风险不可控
- **优先级**：P0

#### Story 4：讲师布置与批改作业（P1）
- **作为** 讲师
- **我希望** 在课程下布置作业（题目/截止时间/分值），查看提交列表并逐份打分写评语
- **以便** 高效完成批改闭环，学生及时获得反馈
- **没有这个功能，用户会怎样？** 批改回归线下 Excel/邮件，效率低且数据不沉淀
- **优先级**：P1

#### Story 5：学生查看成绩（P1）
- **作为** 学生
- **我希望** 查看每份作业的得分、批改评语与课程总评
- **以便** 了解学习效果并及时改进
- **没有这个功能，用户会怎样？** 成绩不可追溯，学习反馈缺失
- **优先级**：P1

#### Story 6：学生浏览课程并学习（P1）
- **作为** 学生
- **我希望** 从课程广场检索已上架课程，进入学习页观看视频/阅读课件并记录进度
- **以便** 随时随地按自己的节奏学习
- **没有这个功能，用户会怎样？** 学习入口缺失，平台无内容消费场景
- **优先级**：P1

#### Story 7：提交异常自动保护（P2）
- **作为** 学生
- **我希望** 提交作业遇到断网/超时时内容不丢失，恢复网络后可一键重试
- **以便** 网络抖动不导致作业丢失
- **没有这个功能，用户会怎样？** 用户重复输入、体验差，易产生客诉
- **优先级**：P2

#### Story 8：管理员查看数据看板（P2）
- **作为** 管理员
- **我希望** 查看课程数、上架通过率、作业按时提交率等运营指标
- **以便** 判断平台健康度并调整运营策略
- **没有这个功能，用户会怎样？** 运营决策无数据支撑
- **优先级**：P2

### 4.3 功能清单

> **微交互四步法**：每个交互点按 触发 → 反馈 → 规则 → 循环 展开。

#### 4.3.1 课程浏览与学习（学生）

##### 1. 浏览课程列表

| 四步 | 说明 |
|------|------|
| **触发** | 进入课程广场 / 输入关键词搜索 / 点击分类筛选 |
| **反馈** | 课程卡片列表展示（封面/标题/讲师/评分），加载态为骨架屏 |
| **规则** | 仅展示「已上架」课程；分页加载每页 20 条；支持按热度/最新排序 |
| **循环** | 可反复筛选，点击卡片跳转课程详情页 |

##### 2. 开始学习课程

| 四步 | 说明 |
|------|------|
| **触发** | 在课程详情页点击「开始学习」 |
| **反馈** | 进入学习页，视频可播放、课件可阅读，章节大纲展示进度 |
| **规则** | 需登录；课程状态为已上架；无权限时提示且不泄露内容 |
| **循环** | 支持断点续学，再次进入定位上次学习位置 |

##### 3. 记录学习进度

| 四步 | 说明 |
|------|------|
| **触发** | 观看视频/阅读课件产生进度变化 |
| **反馈** | 章节标记「已学」，进度条实时更新 |
| **规则** | 章节 ≥ 90% 时长记为完成；进度保存防抖 5 秒；全部章节完成则课程标记「已完成」 |
| **循环** | 可重复学习，进度只增不减，重新学习可选重置 |

##### 异常分支

| 异常类型 | 触发条件 | 系统行为 | 用户提示 |
|---------|---------|---------|---------|
| 网络异常 | 视频加载超时 | 自动重试 3 次后降级为音频/文字 | Toast「网络不稳定，正在重试」 |
| 数据异常 | 课程列表为空 | 展示空状态 + 引导关注更多课程 | 「暂无课程，去看看其他分类」 |
| 权限异常 | 未登录/课程未上架 | 拦截跳转登录或提示不可见 | 「请先登录」/「课程暂未开放」 |
| 并发冲突 | 同一课程多端同时学习 | 以最近进度为准，无写冲突 | 静默合并 |
| 业务异常 | 课程被下架/删除 | 学习页跳转课程详情并提示 | 「该课程已下架」 |

##### 业务规则
- 规则 1：学生仅能学习「已上架」课程。
- 规则 2：学习进度按学生+课程+章节维度唯一保存。
- 规则 3：课程被下架后，历史进度保留，重新上架后进度可续。

##### 全局状态

| 状态 | 呈现方式 |
|------|---------|
| 加载态 | 列表骨架屏、视频 loading 动画 |
| 空状态 | 「暂无课程」+ 分类切换引导 |
| 错误态 | 加载失败重试按钮 + 错误文案 |
| 成功态 | 学习页打开、进度保存 Toast |
| 确认操作 | 重置学习进度需二次确认 |
| 撤销操作 | 重置进度后 30 秒内可撤销 |

#### 4.3.2 课程管理（讲师）

##### 1. 创建/编辑课程

| 四步 | 说明 |
|------|------|

| 业务异常 | 提交审核时内容不完整 | 定位未填项并拦截 | 「请完善必填项后再提交」 |

##### 业务规则
- 规则 1：讲师仅能管理本人创建的课程。
- 规则 2：提交审核后内容锁定；驳回后解锁修改。
- 规则 3：审核中的课程不允许删除。

| 撤销操作 | 草稿编辑支持 Ctrl+Z；删除课程进回收站 7 天可恢复 |

|------|------|
| **触发** | 进入审核详情页，查看课程完整内容后点击「通过」或「驳回」 |
| **反馈** | 通过则课程上架并通知讲师；驳回弹出原因填写框（必填） |
| **规则** | 驳回必须填写 review_comment；通过后课程状态变更为已上架；审核操作记录留痕 |
| **循环** | 驳回后讲师修改重新提交，重新进入队列 |

| 四步 | 说明 |
|------|------|
| **触发** | 在课程管理页对已上架课程点击「下架」 |
| **反馈** | 课程对学生端立即不可见，二次确认后生效 |
| **规则** | 下架需填写原因并二次确认；下架不删除数据 |
| **循环** | 讲师可修改后重新提交审核上架 |

##### 异常分支

| 异常类型 | 触发条件 | 系统行为 | 用户提示 |
|---------|---------|---------|---------|
| 网络异常 | 审核提交失败 | 自动重试，保留已填原因 | 「提交失败，请重试」 |
| 数据异常 | 课程内容加载失败 | 重试加载，不丢失已审记录 | 「内容加载失败」 |
| 权限异常 | 非管理员访问审核页 | 拦截跳转 | 「无操作权限」 |
| 并发冲突 | 讲师撤回审核同时管理员操作 | 以先到动作为准，刷新提示 | 「课程状态已变更，请刷新」 |

##### 业务规则
- 规则 1：审核通过/驳回/下架操作全量留痕（操作人/时间/原因）。
- 规则 2：SLA 超时（> 24 小时）自动升级提醒。
- 规则 3：审核中的课程不可被讲师删除。

## 五、验收标准

### AC-01：学生提交作业成功（正常场景）
- **Given**：学生已选学某课程，讲师已发布作业且未截止；学生已填写作答内容
- **When**：学生点击「提交」
- **Then**：提交成功，状态变为「已提交」，记录提交时间；再次进入显示提交状态与时间

### AC-02：课程上架全链路（正常场景）
- **Given**：讲师已创建完整课程并提交审核
- **When**：管理员在审核队列中点击「通过」
- **Then**：课程状态变为「已上架」，讲师收到通知，学生端课程广场可见该课程

### AC-03：批改后成绩可见（正常场景）
- **Given**：学生已提交作业
- **When**：讲师批改并提交得分与评语
- **Then**：学生成绩单页显示得分、评语与批改时间，实时可见

### AC-04：截止后提交被拒（异常场景）
- **Given**：作业已截止（当前时间 > deadline_at）
- **When**：学生点击「提交」
- **Then**：系统拒绝提交，提示「作业已截止」，不产生提交记录

### AC-05：断网提交不丢失（异常场景）
- **Given**：学生提交过程中网络中断
- **When**：恢复网络后点击「重试提交」
- **Then**：作答内容完整保留并提交成功；重复点击不产生重复提交记录（幂等）

### AC-06：无权限访问拦截（边界场景）
- **Given**：学生尝试直接访问批改页 URL
- **When**：发起页面请求
- **Then**：系统拦截并提示「无操作权限」，不泄露任何学生提交内容

### AC-07：并发重复提交只生成一条记录（边界场景）
- **Given**：学生在截止前快速双击「提交」或双端同时提交
- **When**：两个提交请求几乎同时到达
- **Then**：仅生成一条提交记录，attempt_count 正确累加，无脏数据

## 六、数据指标

### 6.1 核心成功指标（North Star）

- **指标名**：课程完成率（完课学生占比）
- **计算方式**：完成全部章节学习且提交全部作业的学生数 ÷ 选学该课程的学生总数
- **目标值**：上线 12 周后单课程平均完成率 ≥ 40%
- **数据来源**：学习记录表 + 提交表 + 课程表聚合

### 6.2 过程指标

| 指标名 | 计算方式 | 基准值 | 目标值 | 数据来源 |
|-------|---------|-------|-------|---------|
| 课程审核平均时长 | 提交审核至审核完成的时间均值 | — | ≤ 24h | 审核操作日志 |
| 审核通过率 | 通过数 ÷ 审核完成总数 | — | ≥ 80% | 审核操作日志 |
| 作业按时提交率 | 截止前提交数 ÷ 应提交总数 | — | ≥ 90% | 提交表 |
| 48h 批改完成率 | 48 小时内批改数 ÷ 应批改总数 | — | ≥ 95% | 批改日志 |
| 提交成功率 | 提交成功数 ÷ 提交请求总数 | — | ≥ 99.5% | 提交接口日志 |
| 学生成绩查询 P95 | 成绩查询接口耗时 P95 | — | < 500ms | 接口监控 |
| 周活跃师生数 | 每周完成 ≥1 次有效学习/教学操作的去重用户数 | — | 上线 8 周 ≥ 5000 | 行为埋点 |

### 6.3 异常告警阈值

| 监控项 | 告警条件 | 告警级别 | 处理 SOP |
