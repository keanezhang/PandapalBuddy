# 在线课程平台 PRD（产品需求文档）

## 1. 文档信息

- 产品名称：在线课程平台
- 文档版本：v1.0（紧急评审初稿）
- 文档状态：草稿，待评审
- 文档日期：评估运行当日
- 编写说明：本 PRD 按用户角色划分功能需求，覆盖学生、讲师、管理员三角色核心闭环。应需求方要求，全文采用 Markdown 编写且不使用任何表格，不使用 JSON。

## 2. 背景与目标

### 2.1 背景

随着在线教育需求增长，需要一个支持"课程学习—作业练习—评价反馈—内容治理"全流程的在线课程平台。平台核心价值是打通内容生产者（讲师）、内容消费者（学生）与内容把关者（管理员）三方协作链路。

### 2.2 产品目标

- 学生能便捷地浏览与学习课程、完成并提交作业、及时查看成绩。
- 讲师能上传课程内容、布置作业并对学生作业进行批改。
- 管理员能对讲师提交的课程进行审核，把控内容质量与合规性，决定是否上架。
- 平台整体流程清晰、权限分明、状态可追踪。

### 2.3 成功指标（建议）

- 课程审核平均耗时不超过 24 小时。
- 作业提交成功率不低于 99.5%。
- 学生端核心操作（看课、交作业、看成绩）在弱网环境下可用。

## 3. 术语定义

- 课程：讲师创建并经管理员审核上架后可供学生学习的内容单元（含视频/课件/图文等）。
- 上架：课程通过管理员审核后在平台可见可学的状态。
- 作业：讲师针对某课程布置的任务，含题目、要求、截止时间。
- 提交记录：学生对某次作业的作答内容（文本、附件等）及提交时间。
- 成绩：讲师对学生提交记录的评分及评语，学生可查看。
- 草稿：讲师创建但未提交审核的课程状态。

## 4. 用户角色与权限

### 4.1 角色定义

- 学生（Student）：注册用户，学习与作业提交的主体。
- 讲师（Instructor）：注册用户，课程与作业内容的生产者，需通过身份认证（建议）。
- 管理员（Admin）：平台运营人员，负责课程审核与内容治理。
- 游客（Guest，可选）：未登录用户，仅可浏览课程列表与公开详情页。

### 4.2 角色权限总览

权限按"角色 × 功能域"描述如下（无表格）：

- 学生：可查看已上架课程列表与详情、播放/阅读课程内容、查看作业要求、作答并提交作业、在截止前修改/重新提交、查看作业成绩与课程总评。
- 讲师：可创建课程、编辑课程信息、上传课程内容（视频/课件/图文）、将课程提交审核、查看审核结果、创建/编辑/删除作业、查看学生提交列表、批改作业（打分+评语）、查看作业成绩分布。
- 管理员：可查看待审核课程列表、审核通过/驳回课程（驳回需填写原因）、下架已上架课程、查看课程与用户基础统计。
- 通用：登录、注册、退出、修改个人资料、消息通知（作业截止提醒、审核结果通知）。

## 5. 功能需求

需求优先级说明：P0 = 首期必须，P1 = 首期应有，P2 = 后续迭代。

### 5.1 学生端

#### 5.1.1 看课程（P0）

- 课程列表：分页展示已上架课程，支持按分类、关键词、讲师筛选与搜索。
- 课程详情：展示课程名称、简介、讲师、封面、章节结构、作业列表、学习进度。
- 课程学习：支持在线播放视频/查看课件/阅读图文内容；记录学习进度，断点续学。
- 学习记录：展示"我的课程"列表与学习进度百分比。

#### 5.1.2 做作业（P0）

- 作业列表：在课程详情或"我的作业"中查看作业要求、题目内容、截止时间、状态（未开始/进行中/已截止/已提交/已批改）。
- 在线作答：支持文本作答，以及附件上传（图片/文档，建议单文件 ≤ 50MB）。

#### 5.1.3 提交作业（P0）

- 提交：在截止时间前提交作答；提交成功生成提交记录并回执提交时间。
- 修改/重新提交：截止前可覆盖修改；截止后不可再提交（除非讲师开启补交，P2）。
- 防丢失：作答内容支持自动保存草稿，防止误关闭丢失。

#### 5.1.4 看成绩（P0）

- 成绩查询：查看每次作业的得分、评语、批改时间。
- 课程总评：展示课程内各作业成绩汇总与总评（规则由讲师配置，默认取平均分）。
- 通知：批改完成时通过消息中心提醒学生。

### 5.2 讲师端

#### 5.2.1 上传课程（P0）

- 创建课程：填写课程名称、简介、分类、封面、讲师介绍。
- 内容上传：上传视频（建议支持常见格式，单视频 ≤ 2GB）、课件（PDF/PPT）、图文章节；支持章节化结构编排。
- 状态管理：课程状态流转为"草稿 → 待审核 → 已上架 / 已驳回"，讲师可编辑草稿、重新提交。
- 审核结果：查看管理员审核意见；被驳回后可修改后重新提交。

#### 5.2.2 布置作业（P0）

- 创建作业：选择关联课程，填写作业标题、题目/要求、分值、截止时间。
- 编辑/删除：截止前可编辑作业内容与截止时间；已删除作业需提示将影响已提交记录（建议软删除）。
- 作业列表：查看各课程下的作业及提交统计（已提交/未提交人数）。

#### 5.2.3 批改作业（P1）

- 批改列表：按作业查看学生提交记录，标记"未提交/已提交/已批改"。
- 评分评语：对提交记录打分（建议 0～100 或按作业分值）、填写评语。
- 批量操作：支持快捷键切换下一位、批量通过（P2）。
- 成绩汇总：查看该作业成绩分布与学生名单。

### 5.3 管理员端

#### 5.3.1 审核课程上架（P0）

- 待审核列表：展示讲师提交的待审核课程，含提交时间、讲师信息、课程信息摘要。
- 审核操作：通过（上架）或驳回（必须填写驳回原因，原因对讲师可见）。
- 审核记录：保留每次审核的操作人、时间、结果、原因，可追溯。
- 内容治理：对已上架课程支持下架（P1）；支持违规举报处理（P2）。

#### 5.3.2 平台概览（P1）

- 基础统计：课程数、上架/待审核/驳回数量、学生数、讲师数、作业提交数。
- 数据导出：课程与作业维度报表导出（CSV，P2）。

### 5.4 通用功能

- 账号与认证：注册、登录、退出；讲师身份需额外认证（建议提交资质材料，P1）。
- 消息通知：作业截止提醒、作业批改完成、课程审核结果，站内消息（P1）。
- 帮助与反馈：意见反馈入口（P2）。

## 6. 核心业务流程

### 6.1 课程上架流程

讲师创建课程（草稿）→ 编辑并上传内容 → 提交审核（状态：待审核）→ 管理员审核：

- 通过 → 课程上架，学生可见可学（状态：已上架）。
- 驳回 → 填写驳回原因，讲师收到通知，可修改后重新提交。

### 6.2 作业全流程

讲师创建作业并关联课程、设置截止时间 → 学生在截止前查看要求并作答 → 学生提交（可截止前修改）→ 讲师查看提交记录并批改（打分+评语）→ 系统通知学生 → 学生查看成绩。

### 6.3 权限校验规则

- 讲师只能操作自己创建的课程与作业。
- 学生只能访问已上架课程及其作业。
- 管理员只能审核，不能代改课程内容。
- 所有涉及他人数据的操作需校验角色与数据归属。

## 7. 非功能需求

### 7.1 性能

- 课程列表页首屏加载 ≤ 2s（常规网络）。
- 视频播放支持自适应码率，弱网可播放低清流（P1）。
- 作业提交接口响应 ≤ 3s。

### 7.2 安全

- 密码加密存储，登录态使用安全会话；接口防越权（水平/垂直越权校验）。
- 用户上传内容做类型与大小校验，防恶意文件；视频/课件需防未授权下载（P1）。
- 敏感操作（审核、删除）记录操作日志。

### 7.3 可用性与兼容性

- 支持主流浏览器（Chrome/Edge/Safari/Firefox 近两个大版本）。
- 建议提供移动端 H5（P1）与 App（P2）。

### 7.4 可维护性

- 功能按角色模块化，权限点可配置；状态机（课程、作业、提交）明确且可扩展。

## 一、概述与背景

##### 背景
- 当前课程内容分散在网盘、聊天群与线下课堂，学习、作业提交、批改与成绩公布割裂在多个工具中，学生与讲师需在多个系统间反复切换，效率低且数据易丢失。
- 课程上架缺少统一审核入口，内容质量与合规性无法保障；作业与成绩缺乏线上沉淀，历史数据不可追溯。
- 需要一个多角色在线课程平台，将「课程内容 — 作业 — 成绩」闭环线上化，并让管理员对内容上架进行把关。

##### 目标
- 目标 1：打通「讲师上传课程 → 管理员审核 → 上架 → 学生学习」全链路，课程从提交到上架平均耗时 ≤ 24 小时。
- 目标 2：作业「布置 → 提交 → 批改 → 成绩」全流程线上化，作业按时提交率 ≥ 90%，批改完成时效 ≤ 48 小时。
- 目标 3：建立课程内容审核机制，违规/低质课程上架拦截率 100%（人工审核兜底）。
- 目标 4：学生可随时查询成绩与批改反馈，成绩查询接口 P95 响应 < 500ms。

##### 角色清单

| 角色 | 职责 | 核心诉求 |
|------|------|---------|
| 学生 | 浏览并学习课程、完成并提交作业、查看成绩与批改反馈 | 学习顺畅、作业不丢失、成绩透明可查 |
| 讲师 | 创建并上传课程、布置作业、批改作业并评分 | 课程快速上架、作业管理高效 |
| 管理员 | 审核课程内容并决定上架/驳回、下架违规课程、查看运营数据 | 审核流程清晰、内容合规可控 |

##### 场景清单

### 场景 1：学生浏览课程并开始学习（核心）

判定要求：
- 对每条断言，分别对 A 和 B 给出 score：1=完全满足（有明确证据）；0.5=部分满足；0=不满足或相反。
- evidence 必须引用 A.md/B.md 或对应产出文件的具体原文（引用位置 + 原文），不允许空证据。
- assertion_index 为断言清单中的编号（1 到 5），不要用 0 开始的索引。
- 输出纯 JSON（不要多余文字），格式：
{
  "A": [
    {"assertion_index": 1, "score": 1, "evidence": "A.md: '原文引用'", "evidence_ref": "A.md:12"}
  ],
  "B": [...]
}
- 若某条断言在输出中完全找不到对应内容，score 记 0，evidence 写 "A.md/B.md 中未找到相关内容"。
