## 一、概述与背景

##### 背景

当前课程内容分发、作业布置与批改、成绩反馈分散在不同工具中，学生需要在多个系统间切换，讲师无法在一个地方完成"上传课程→布置作业→批改评分"的全流程，平台也缺少课程上架前的质量审核机制。需要一个一体化的在线课程平台，把"课程→作业→成绩"闭环打通，并引入管理员审核保障上架内容合规。

##### 目标

- 目标 1：打通"看课→做作业→提交→批改→看成绩"完整闭环，学生作业提交率提升至 85% 以上
- 目标 2：课程从提交审核到上架的**平均审核时长 ≤ 24 小时**，上架审核覆盖率 100%
- 目标 3：违规/劣质课程在审核环节 100% 拦截，不进入学生可见范围
- 目标 4：学生端核心操作（看课、交作业、看成绩）可用性 ≥ 99.9%

##### 角色清单

| 角色 | 职责 | 核心诉求 |
|------|------|---------|
| 学生 | 浏览学习课程、做作业、提交作业、查看成绩 | 学习链路顺畅，作业不丢、成绩即时可见 |
| 讲师 | 上传课程、布置作业、批改作业 | 教学管理一处完成，批改高效，学生提交不遗漏 |
| 管理员 | 审核课程上架、违规下架 | 审核流程清晰、可追溯，劣质内容不进平台 |

##### 场景清单

### 场景 1：学生浏览与学习课程（核心）

- **发生时态**：日常
- **角色**：学生
- **目标**：在课程列表中发现已上架课程，进入详情页学习内容，并找到课程配套作业入口
- **前置条件**：学生已登录并完成选课；课程状态为「已上架」

### 场景 2：学生做作业并提交（核心）

- **发生时态**：日常
- **角色**：学生
- **目标**：在截止时间前完成作答并提交，提交后进入讲师批改队列
- **前置条件**：学生已选该课程；作业已布置且处于可提交时间窗内

### 场景 3：学生查看成绩（核心）

- **发生时态**：日常
- **角色**：学生
- **目标**：查看每次作业得分与讲师评语，了解学习情况
- **前置条件**：讲师已完成批改；成绩已写入该学生的提交记录

### 场景 4：讲师上传课程（核心）

- **发生时态**：日常
- **角色**：讲师
- **目标**：上传课程内容（视频/图文）并提交审核，等待管理员放行
- **前置条件**：讲师已登录且通过实名认证；课程为草稿或驳回修改态

### 场景 5：讲师布置作业（核心）

- **发生时态**：日常
- **角色**：讲师
- **目标**：为自己的已上架课程创建作业，设置截止时间与满分，对学生可见
- **前置条件**：课程已上架或至少处于讲师可管理的状态

### 场景 6：讲师批改作业（核心）

- **发生时态**：日常
- **角色**：讲师
- **目标**：查看学生提交列表，逐份打分、写评语，批改结果回传学生
- **前置条件**：有学生已提交作业；讲师拥有该课程的批改权限

### 场景 7：管理员审核课程上架（核心）

- **发生时态**：日常
- **角色**：管理员
- **目标**：对待审核课程逐份检查内容合规性，给出「通过上架」或「驳回」决定
- **前置条件**：讲师已提交审核；课程状态为「待审核」

### 场景 8：提交作业时断网/超时（边缘）

- **发生时态**：异常
- **角色**：学生
- **目标**：在网络异常下提交不丢失，恢复后能重试完成提交
- **前置条件**：学生在作答页点击提交时网络中断

### 场景 9：截止时间高峰并发提交（边缘）

- **发生时态**：峰值
- **角色**：学生
- **目标**：大量学生在截止前集中提交，系统不丢单、不超时
- **前置条件**：一门课选课人数多（如 1000+），截止前 10 分钟提交量激增

| 做作业并提交 | 学生 | 核心 | 日常 |
| 查看成绩 | 学生 | 核心 | 日常 |
| 上传课程 | 讲师 | 核心 | 日常 |
| 布置作业 | 讲师 | 核心 | 日常 |
| 批改作业 | 讲师 | 核心 | 日常 |
| 审核课程上架 | 管理员 | 核心 | 日常 |
| 提交断网/超时 | 学生 | 边缘 | 异常 |
| 截止高峰并发 | 学生 | 边缘 | 峰值 |

### 3.2 业务链路

#### 核心链路 1：课程上架链路（讲师 → 管理员 → 学生）

```text
┌──────────┐   创建并提交审核    ┌──────────┐   审核{课程}    ┌──────────┐
│ 讲师·课程  │ ─────────────────► │ 管理员·审核 │ ─────────────► │ 已上架    │
│ 管理      │                    └────┬─────┘                └────┬─────┘
└──────────┘                         │                           │
                                     │ <驳回>                    │ 学生可见
                                     ▼                           ▼
                               ┌──────────┐                ┌──────────┐
                               │ 退回草稿  │                │ 学习中心  │
                               │(讲师修改) │                │ 课程列表  │
                               └──────────┘                └──────────┘
```

**链路说明**：讲师在课程管理页创建课程并提交审核 → 课程进入「待审核」→ 管理员在审核台审核 → 通过则上架、学生列表可见；驳回则退回草稿并附驳回原因，讲师修改后重新提交。

#### 核心链路 2：作业闭环链路（讲师 → 学生 → 讲师 → 学生）

```text
┌──────────┐   布置作业{作业}   ┌──────────┐   提交{作答}    ┌──────────┐
│ 讲师·作业  │ ─────────────────► │ 学生·作业  │ ─────────────► │ 讲师·批改  │
│ 管理      │                    │ 作答      │                └────┬─────┘
└──────────┘                    └────┬─────┘                     │ 评分{成绩}
                                     │ <逾期未交>                 ▼
```

# 在线课程平台产品需求文档（PRD）

- 文档版本：v1.0
- 编写日期：2026-08-11
- 编写人：PandaPal 样本执行 Agent
- 文档状态：初稿（供研发/产品评审）

---

## 1. 产品概述

### 1.1 产品背景
在线教育需求持续增长，需要一个统一的在线课程平台，将课程内容、作业练习、成绩管理三个核心教学环节线上化，覆盖学生、讲师、管理员三类角色的协作闭环。

### 1.2 产品目标
- 让学生可以随时随地看课、做作业、提交作业并查看成绩。
- 让讲师可以便捷地上传课程、布置作业、批改作业。
- 让管理员可以审核课程内容，确保上架课程合规、优质。
- 打通"课程上架 → 学习 → 作业 → 成绩"的完整业务闭环。

### 1.3 产品范围
- 本期范围：课程管理（上传/审核/上架/浏览）、作业管理（布置/提交/批改）、成绩管理（发布/查看）、角色与权限基础能力。
- 不在本期范围：直播授课、论坛社区、支付与订单、多租户/机构管理。

### 1.4 名词解释
- 课程：讲师上传、管理员审核通过后上架的学习内容，可包含多个章节/课时。
- 作业：讲师在课程下布置的任务，学生需在截止时间前提交。
- 成绩：讲师对作业批改后给出的评分，学生可查看。
- 审核：管理员对讲师上传课程的合规性检查，决定上架或驳回。

---

## 2. 用户角色与权限

### 2.1 学生（Student）
- 角色说明：平台的主要学习用户。
- 核心权限：浏览/检索课程、查看课程详情、查看作业、提交作业、查看成绩。
- 无权限：上传课程、审核课程、批改作业。

### 2.2 讲师（Instructor）
- 角色说明：教学内容的生产者。
- 核心权限：上传/编辑自己名下的课程、在自己课程下布置作业、批改学生提交的作业并打分。
- 无权限：审核课程上架（只能提交审核）、浏览其他讲师课程的管理操作、以学生身份提交作业。

### 2.3 管理员（Admin）
- 角色说明：平台运营与合规管理者。
- 核心权限：审核课程上架（通过/驳回）、下架违规课程、管理用户账号。
- 无权限：参与教学业务（布置/批改作业、提交作业）。

## 3. 功能需求

### 3.1 学生端功能

#### 3.1.1 浏览与查看课程
- 课程列表页：支持按分类筛选、关键词搜索、按热度/更新时间排序。
- 课程详情页：展示课程简介、章节/课时结构、讲师信息、已选课人数。
- 学习记录：记录学生已学课时，支持断点续看（若含视频）。
- 收藏/选课：学生可收藏或加入"我的课程"。

#### 3.1.2 查看作业
- 在课程详情页或"作业"入口查看讲师布置的作业列表。
- 作业详情展示：作业标题、要求说明、截止时间、分值、附件（可选）。
- 明确展示作业状态：未开始 / 待提交 / 已提交 / 已批改。

#### 3.1.3 提交作业
- 提交方式：文本作答 + 附件上传（支持常见文档/图片格式，附件大小限制见非功能需求）。
- 截止时间前可修改并重新提交，系统保留最近一次提交。
- 截止时间后按平台规则锁定提交（是否允许补交由讲师配置）。
- 提交成功后系统回执确认，学生可在作业列表看到"已提交"状态。

#### 3.1.4 查看成绩
- 成绩列表：按课程维度展示各次作业得分、总分、批改评语。
- 成绩明细：展示讲师批改的打分依据与文字评语。
- 成绩通知：批改完成后学生可收到站内/通知提醒（见非功能需求）。

### 3.2 讲师端功能

#### 3.2.1 上传课程
- 创建课程：填写课程名称、分类、简介、封面、适用人群、学习目标。
- 上传章节/课时：支持文本、视频、附件等多种内容形式。
- 草稿与提交：课程可先存草稿，完善后提交审核。
- 课程状态流转：草稿 → 待审核 → 已上架 / 已驳回（可修改后重新提交）→ 已下架。
- 已上架课程支持讲师发起更新，更新内容需再次过审或按平台策略生效。

#### 3.2.2 布置作业
- 在名下课程内创建作业：标题、题目/要求、截止时间、满分分值、是否允许补交。
- 支持为作业关联课时或章节。
- 作业创建后立即对学生可见（或按设定的发布时间可见）。

#### 3.2.3 批改作业
- 作业提交列表：按课程/作业维度查看所有学生的提交情况（未提交/已提交）。
- 批改操作：逐份查看学生提交内容，输入得分（不超过满分）与文字评语。
- 批量能力：支持按提交时间排序、标记已批/未批，支持一键"全部标记为已读"等轻量批量操作。
- 批改完成后成绩自动对学生可见，触发成绩通知。

### 3.3 管理员端功能

#### 3.3.1 审核课程上架
- 待审核列表：展示所有讲师提交审核的课程，含提交时间、讲师、分类。
- 审核操作：查看课程完整内容后进行"通过"或"驳回"。
- 驳回必填原因：驳回时必须填写原因，原因回传给讲师供其修改。
- 审核记录：保留审核人、审核时间、审核结论的日志，便于追溯。

#### 3.3.2 课程管理（补充）
- 对已上架课程可执行下架操作（如内容违规），下架后学生不可再访问。
- 用户管理：禁用/启用学生或讲师账号。

### 3.4 公共能力
- 登录与鉴权：统一账号体系，按角色分配权限（RBAC）。
- 消息通知：作业布置、提交成功、批改完成、审核结果等关键节点发送站内通知。
- 基础搜索与分页：课程列表、作业列表、待审核列表均支持分页与状态筛选。

## 4. 核心业务流程

### 4.1 课程上架流程（讲师 + 管理员）
1. 讲师创建课程并填写完整信息，上传章节内容。
2. 讲师提交审核，课程状态变为"待审核"。
3. 管理员在待审核列表查看课程内容。
4. 审核通过 → 课程上架，学生可见；审核驳回 → 课程退回，讲师收到驳回原因并修改后重新提交。
5. 已上架课程可被管理员下架（内容违规或运营需要）。

### 4.2 作业闭环流程（讲师 + 学生）
1. 讲师在课程下布置作业（含要求、截止时间、分值）。
2. 学生查看作业并在截止时间前提交（文本 + 附件）。
3. 学生可修改重交直至截止；系统锁定截止后的提交（是否允许补交由讲师配置）。
4. 讲师查看提交列表，逐份批改并给出得分与评语。
5. 批改完成 → 成绩对学生可见，学生收到通知并可查看成绩明细。

### 4.3 状态机摘要
- 课程：草稿 → 待审核 → 已上架 →（可）已下架；待审核可被驳回回草稿/待修改。
- 作业：进行中（可提交）→ 已截止（锁定提交）→ 已批改（成绩发布）。
- 提交：待提交 → 已提交（可重交）→ 已批改。
