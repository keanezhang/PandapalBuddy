# 在线课程平台 产品需求文档（PRD）

## 文档信息

- 产品名称：在线课程平台
- 文档版本：v1.0（评审稿）
- 目标读者：产品、研发、测试、设计
- 编写说明：本 PRD 覆盖学生、讲师、管理员三角色，聚焦「课程内容管理 + 作业闭环 + 审核上架」三条主线。全文采用 Markdown 编写，不使用表格，所有对照关系以列表形式呈现。

## 1. 产品概述

### 1.1 背景

线下/半线下教学中存在课程资料分散、作业收发与批改效率低、成绩反馈不及时、课程质量缺乏审核机制等问题，需要一个统一的在线课程平台支撑「教、学、管」三方协作。

### 1.2 产品目标

- 学生可以随时随地查看课程、完成并提交作业、及时查看成绩与批改反馈。
- 讲师可以便捷地上传课程内容、布置与批改作业，降低事务性负担。
- 管理员可以审核课程上架，保障平台内容质量与合规。

### 1.3 成功指标（简要）

- 作业提交率（已提交人数 / 应提交人数）。
- 批改时效（如发布截止后 48 小时内完成批改的作业占比）。
- 课程审核时效（提交审核到出结果的时长中位数）。
- 学生满意度与留存（NPS、月活）。

### 1.4 本期范围

- 本期包含：课程管理（上传 / 审核 / 上架 / 浏览）、作业管理（布置 / 提交 / 批改 / 成绩）、基础用户与权限体系。
- 本期不包含：直播、支付交易、社区问答、移动端原生 App（本期仅 Web + H5 响应式）。

## 2. 用户角色与权限

### 2.1 角色定义

- 学生（student）：平台内容消费者，核心动作是「看课程、做作业、提交作业、看成绩」。
- 讲师（teacher）：内容生产者，核心动作是「上传课程、布置作业、批改作业」。
- 管理员（admin）：平台运营者，核心动作是「审核课程上架、课程与用户管理」。

### 2.2 角色权限对照（列表形式）

- 学生可执行：浏览已上架课程列表与详情；查看课程下的作业列表与详情；在线作答并暂存草稿；提交 / 重新提交作业；查看成绩与批改评语。
- 讲师可执行：创建 / 编辑课程并上传章节内容；提交课程审核；管理课程（编辑、查看选课学生）；创建 / 编辑 / 发布作业；查看提交情况；批改作业（评分、评语、打回）；查看本课程成绩统计。
- 管理员可执行：审核待上架课程（通过 / 驳回并附原因）；对已上架课程执行下架；管理用户账号（禁用 / 启用）；查看平台级数据看板。
- 越权规则：所有页面与接口按角色鉴权；学生只能访问自己可见（已上架或已加入）的课程；草稿与待审核内容仅创建者与管理员可见。

## 3. 全局约定

- 登录与认证：统一账号体系，支持邮箱 / 手机号 + 密码登录；会话超时 30 分钟，超时需重新登录。
- 时间基准：作业截止时间与提交时间均以服务器时间为准；提交有效性以服务器收到请求的时间为准。
- 通知触达：作业发布、批改完成、审核通过 / 驳回等事件通过站内消息（可选邮件）通知相关方。
- 状态可见性：草稿仅创建者可见；待审核对创建者与管理员可见；已上架对所有用户可见；已下架对学生不可见但历史数据保留。
- 防重复提交：提交作业、审核、批改等写操作需做幂等处理，防止双击 / 重试导致重复数据。

## 4. 功能需求

### 4.1 学生端功能

#### FR-S1 浏览课程列表

- 描述：学生可查看已上架课程列表，支持按分类、关键字、讲师进行筛选与排序。
- 优先级：P0
- 规则：仅展示状态为「已上架」的课程；未上架 / 已下架课程不可见。
- 验收：登录学生打开课程页，能看到全部已上架课程，筛选与排序结果正确。

#### FR-S2 查看课程详情

- 描述：查看课程介绍、讲师信息、章节 / 课时列表、该课程下的作业列表。
- 优先级：P0
- 规则：详情页展示课程基本信息与内容目录；作业区展示作业标题、截止时间、分值、个人提交状态。
- 验收：进入任意已上架课程详情，可完整看到介绍、章节与作业入口。

#### FR-S3 查看作业列表与详情

- 描述：查看课程下作业列表（标题、截止时间、分值、状态），以及作业详情（题目、要求、附件）。
- 优先级：P0
- 规则：未发布的作业对学生不可见；已截止作业标注「已截止」。
- 验收：学生能区分作业的未开始 / 进行中 / 已截止状态。

#### FR-S4 在线作答（做作业）

- 描述：支持文本作答与附件上传；作答内容支持实时暂存草稿，防止内容丢失。
- 优先级：P0
- 规则：截止时间后不可再编辑或提交（除非讲师开启补交）；附件需校验类型与大小。
- 验收：作答内容刷新页面后仍可从草稿恢复；截止后编辑入口置灰。

#### FR-S5 提交作业

- 描述：将作答内容正式提交给讲师；截止前支持多次修改并重新提交（覆盖式）。
- 优先级：P0
- 规则：提交后状态变为「已提交」；截止时间之后的提交标记为「逾期提交」；提交按钮做幂等防重复。
- 验收：提交成功可见状态变化；重复点击不产生重复提交记录。

#### FR-S6 查看成绩

- 描述：查看已批改作业的得分、总分、批改评语与批改时间。
- 优先级：P0
- 规则：仅讲师批改完成（出分）后学生可见成绩；学生不可修改成绩。
- 验收：讲师批改完成后，学生成绩页立即展示分数与评语。

#### FR-S7 查看个人成绩单

- 描述：按课程汇总各作业成绩，形成个人成绩单视图，支持查看整体进度。
- 优先级：P1
- 规则：仅展示已出分作业；未出分作业显示「待批改」。
- 验收：成绩单按课程分组，已批改作业分数齐全。

### 4.2 讲师端功能

#### FR-T1 创建并上传课程

- 描述：填写课程基本信息（标题、简介、分类、封面、适用对象），上传章节内容（视频 / 文档 / 图文）。
- 优先级：P0
- 规则：创建后课程为「草稿」状态，仅讲师本人可见；内容完善后可提交审核。
- 验收：讲师创建课程并上传章节后，课程保存为草稿且其他角色不可见。

#### FR-T2 管理课程

- 描述：编辑课程信息、增删章节、查看选课学生列表、查看课程学习数据。
- 优先级：P0
- 规则：已上架课程被编辑后，需重新提交审核（或按配置仅提示，本期默认需重新审核）。
- 验收：讲师可编辑草稿 / 待审核课程，并查看课程学生名单。

#### FR-T3 布置作业

- 描述：在课程下创建作业，配置标题、题目 / 要求、附件、分值、截止时间，可关联课时。
- 优先级：P0
- 规则：作业创建后为「草稿」；发布后对学生可见；发布后允许编辑题目与截止时间，但分值变更需提示影响。
- 验收：作业发布后学生端立即可见；未发布作业学生端不可见。

#### FR-T4 管理作业

- 描述：编辑 / 重新发布作业、延长截止时间、查看提交情况（已提交 / 未提交名单）。
- 优先级：P0
- 规则：截止时间延长后，学生端截止时间同步更新；未提交名单实时刷新。
- 验收：讲师可查看某作业下每个学生的提交状态，并延长截止时间。

#### FR-T5 批改作业

- 描述：查看学生提交内容，给出分数与评语；支持按名单逐个批改；支持「打回」要求学生修改后重新提交。
- 优先级：P0
- 规则：批改保存后学生可见成绩；支持重新批改覆盖原成绩；打回后学生重新提交进入待批改队列。
- 验收：讲师批改保存后学生可见分数评语；打回后学生可再次提交且讲师可再次批改。

#### FR-T6 查看成绩统计

- 描述：按作业或按学生查看成绩分布、平均分、提交率等统计信息。
- 优先级：P1
- 规则：统计基于已批改数据实时计算。
- 验收：讲师可查看单作业成绩分布与全班提交率。

### 4.3 管理员端功能

#### FR-A1 审核课程上架

- 描述：查看待审核课程列表与详情，作出「通过」或「驳回」决定；驳回须填写原因并通知讲师。
- 优先级：P0
- 规则：审核通过后课程状态变为「已上架」；驳回后讲师可修改并重新提交；审核操作留痕（操作人、时间、原因）。
- 验收：管理员审核通过后课程对学生可见；驳回后讲师收到原因并可修改重提。

#### FR-A2 课程管理

- 描述：查看平台全部课程及状态；对已上架课程可执行「下架」。
- 优先级：P0
- 规则：下架后课程对学生不可见，但历史作业与成绩保留可查；下架原因留痕。
- 验收：管理员下架某课程后，学生端不再展示该课程，历史数据仍可查询。

#### FR-A3 用户管理

- 描述：查看 / 搜索用户，禁用 / 启用账号，处理举报。
- 优先级：P1
- 规则：被禁用账号无法登录与访问；禁用操作留痕。
- 验收：禁用某用户后该用户立即无法登录。

#### FR-A4 数据看板

- 描述：查看平台级指标：课程数、用户数、活跃度、作业提交率、审核时效等。
- 优先级：P2
- 规则：看板数据 T+1 更新。
- 验收：管理员可查看平台核心指标看板。

## 5. 核心业务流程

### 5.1 课程发布与审核上架流程

1. 讲师创建课程（草稿）。
2. 讲师完善课程内容并「提交审核」（待审核）。
3. 管理员查看待审核课程详情。
4. 管理员操作：通过 → 课程上架（已上架），对学生可见；驳回 → 填写原因，课程回到讲师侧（已驳回），讲师修改后重新提交审核。
5. 管理员可对已上架课程执行下架（已下架）。

### 5.2 作业闭环流程

1. 讲师创建作业（草稿）→ 发布（已发布 / 进行中）。
2. 学生查看作业并在线作答（草稿暂存）。
3. 学生提交作业（已提交，截止后提交标记逾期）。
4. 作业截止（已截止），讲师开始批改。
5. 讲师批改：给出分数与评语（已批改 / 出分），或打回（学生修改后重新提交，再次进入待批改）。
6. 学生查看成绩与批改反馈。

### 5.3 异常与边界

- 截止时间后提交：标记「逾期」，默认仍计入批改（可通过配置关闭）。
- 批改中打回：学生重新提交后再次进入待批改队列，原成绩保留直至重新批改。
- 课程下架：学生不可再浏览该课程，但已提交作业、成绩、批改记录保留可查。
- 课程被驳回：学生始终不可见；讲师修改后重新提交，审核记录完整保留。

## 6. 状态定义

- 课程状态：草稿 → 待审核 → 已上架 ⇄ 已下架；待审核 → 已驳回（可修改后重新提交审核）。
- 作业状态：草稿 → 已发布（进行中）→ 已截止。
- 作业提交状态：未提交 → 已提交 → 已批改；已提交 → 已打回（可重新提交）。
- 成绩状态：未出分 / 已出分；重新批改后覆盖更新。

## 7. 非功能需求

- 性能：课程列表 / 详情接口 P95 响应时间 < 300ms；支持 500 并发在线用户正常使用；附件上传支持断点续传，单文件 ≤ 500MB。
- 安全：统一登录鉴权（JWT / Session）；接口做角色与数据权限校验，防止越权访问；附件上传做类型与大小校验；敏感操作（审核、批改、禁用）写入审计日志。
- 可用性：核心流程（提交作业、批改、审核）可用性 ≥ 99.5%；写操作幂等，防止重复提交。
- 兼容性：支持 Chrome / Edge / Firefox 最新两个大版本；移动端 H5 响应式适配。
- 合规：遵守用户隐私与数据保护要求；课程内容版权声明；作业与成绩数据仅限授权角色访问。

## 8. 数据模型概述（字段级，列表形式）

### 8.1 用户（user）

- id、角色（student / teacher / admin）、姓名、邮箱 / 手机号、密码哈希、状态（正常 / 禁用）、创建时间。

### 8.2 课程（course）

- id、讲师 id、标题、简介、分类、封面、适用对象、状态（草稿 / 待审核 / 已上架 / 已驳回 / 已下架）、审核人 id、审核时间、驳回原因、创建与更新时间。

### 8.3 章节（chapter）

- id、课程 id、标题、排序、内容类型（视频 / 文档 / 图文）、内容地址。

### 8.4 作业（assignment）

- id、课程 id、标题、题目 / 要求、附件、分值、截止时间、状态（草稿 / 已发布 / 已截止）、创建与更新时间。

### 8.5 作业提交（submission）

- id、作业 id、学生 id、作答内容、附件、提交时间、是否逾期、状态（已提交 / 已打回 / 已批改）、批改人 id、分数、评语、批改时间。

### 8.6 审核记录（review_log）

- id、课程 id、审核人 id、审核结果（通过 / 驳回）、驳回原因、审核时间。

## 9. 埋点与报表（简要）

- 关键事件：课程浏览、作业查看、作答保存、作业提交、批改完成、审核通过 / 驳回。
- 报表：课程上架数、作业提交率、批改时效、成绩分布、用户活跃度。

## 10. 验收标准

### 3.3 状态流转

#### 课程状态机

```text
      ┌──────────┐  提交审核    ┌──────────┐  审核通过    ┌──
…(截断)

断言清单（来自 evals.json 的 assertions_sem，逐条复制，severity 保留）：

1. 最终产物是 Markdown 文档而非 JSON（跟随最后指令，处理矛盾指令）（severity: major）
2. 三角色场景产出权限矩阵（讲师/学生/管理员）（severity: major）
3. 产出物是完整可交付的 PRD 而非仅有提纲/大纲（有时间压力也不偷工）（severity: major）
4. Agent 没有输出 '<太简单了不需要>' 或 '时间不够只写提纲' 等借口（severity: minor）
5. 产出物无占位符残留（severity: minor）

判定要求：
- 对每条断言，分别对 A 和 B 给出 score：1=完全满足（有明确证据）；0.5=部分满足；0=不满足或相反。
- evidence 必须引用 A.md/B.md 或对应产出文件的具体原文（引用位置 + 原文），不允许空证据。
- assertion_index 为断言清单中的编号（1 到 5），不要用 0 开始的索引。
- 输出纯 JSON（不要多余文字），格式：
{
  "A": [
    {"assertion_index": 1, "score": 1, "evidence": "A.md: '原文引用'", "evidence_ref": "A.md:12"}
  ],
  "B": [...]
}
- 若某条断言在输出中完全找不到对应内容，score 记 0，evidence 写 "A.md/B.md 中未找到相关内容"。
