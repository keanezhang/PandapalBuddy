## 2. 产品概述

### 2.1 背景

平台已具备成熟的电商下单与会员体系，但缺少有效的用户留存与复购激励手段。通过引入会员积分体系，将"下单行为"与"消费权益"挂钩：用户下单累积积分，积分可在积分商城兑换优惠券或商品，形成"消费 → 得积分 → 兑权益 → 再消费"的闭环，提升用户粘性、复购率与客单价。

### 2.2 产品目标

| 目标 | 说明 | 可量化指标（上线后 3 个月） |
| --- | --- | --- |
| G1 提升复购 | 积分让用户产生"沉淀资产"，回访消耗积分 | 积分商城月访问 UV 占活跃用户 ≥ 15%；兑换用户 90 天内复购率较非兑换用户提升 ≥ 10% |
| G2 消耗库存/券 | 通过积分兑换清理合作商品库存、发放优惠券带动转化 | 优惠券兑换后核销率 ≥ 40% |
| G3 运营可控 | 运营可自助配置积分规则与兑换商品，无需发版 | 规则与商品配置自助化覆盖率 100% |

### 2.3 产品范围

**本期范围（In Scope）：**

1. C 端：积分账户（余额/明细）、下单积分获取、积分商城（浏览/兑换商品/兑换优惠券）、兑换记录；
2. 后台：积分规则管理、兑换商品库管理、兑换订单管理、积分流水查询与人工调整；
3. 基础能力：积分有效期、退款扣回、并发防超兑、审计日志。

**本期不做（Out of Scope，列为二期候选）：**

- 会员等级 / 成长值体系（本期积分与会员等级解耦）；
- 签到、任务、邀请等运营活动类积分；
- 积分抵现（下单时直接用积分抵扣金额，本期仅"下单得积分"）；
- 积分转让 / 赠送 / 提现（明确禁止）；
- 积分商城个性化推荐（算法）。

### 2.4 名词解释

| 名词 | 定义 |
| --- | --- |
| 积分 | 平台内虚拟权益单位，不可提现、不可转让、不可兑现为现金，仅可用于平台内兑换 |
| 积分账户 | 每个用户唯一，记录积分余额、累计获得/消耗、冻结金额 |
| 积分流水 | 积分账户每一笔变动（增加/扣减/过期/调整）的可追溯记录 |
| 积分规则 | 定义"什么行为获得多少积分"及"每笔获得上限"的配置项 |
| 兑换商品 | 积分商城内可消耗积分兑换的实物商品、虚拟权益或优惠券 |
| 兑换订单 | 用户消耗积分兑换商品后生成的履约单据 |
| 优惠券 | 平台优惠券，可作为兑换商品的一种（虚拟权益） |
| 积分有效期 | 积分自到账之日起的有效时长，过期自动清零 |

### 2.5 用户角色与权限

| 角色 | 说明 | 主要权限 |
| --- | --- | --- |
| 普通用户（会员） | 已注册并登录的平台消费者 | 查看积分余额/明细；兑换优惠券与商品；查看兑换记录；使用/查看优惠券 |
| 运营管理员（运营） | 平台运营人员，负责积分玩法 | 配置积分规则；管理兑换商品库（含上下架、库存）；处理兑换订单发货/取消；查询流水 |
| 财务/风控（只读） | 对账与风控人员 | 只读查看积分流水、兑换订单、规则变更记录 |
| 系统管理员 | 平台技术/超管 | 账号与角色权限管理、人工积分调整（需双人审批） |

## 3. 业务规则总览

> 以下为默认规则，除标注"系统固定"外均可由运营在后台配置。**本 PRD 在信息不足处已做假设，假设清单见 §18。**

### 3.1 积分获取规则

| 规则项 | 默认值（可配置） | 说明 |
| --- | --- | --- |
| 消费积分比例 | 1 元实付金额 = 1 积分 | 按**实付金额**（扣除优惠、运费后的实际支付金额）计算，向下取整 |
| 类目倍数 | 全局 1.0（可按类目/商品单独配置倍数，如 3C 类 0.5 倍、美妆 2 倍） | 支持按类目、按指定商品 SKU 覆盖 |
| 单笔订单积分上限 | 10,000 积分（可配置） | 防止大额订单产生异常积分 |
| 发放时点 | 订单**签收完成**后 T+0 发放 | 与订单状态机挂钩：支付成功不发放，签收完成后发放 |
| 新用户奖励 | 注册完成赠送 100 积分（一次性，可配置开关） | 与下单积分相互独立 |
| 活动翻倍 | 支持运营配置"全场/指定类目 N 倍积分"活动（有效期+优先级） | 与基础规则叠加，取优先级高者 |

### 3.2 积分消耗规则

| 规则项 | 默认值（可配置） | 说明 |
| --- | --- | --- |
| 兑换价值锚定 | 100 积分 ≈ 1 元权益价值 | 仅作为运营定价参考，非强制 |
| 兑换下限 | 单次兑换最低消耗 10 积分 | 防止碎片化流水 |
| 积分不足 | 禁止兑换，前端置灰并提示差额 | 不支持"积分+现金"混合支付（本期） |
| 消耗顺序 | 优先消耗最早到期的积分（FEFO） | 避免临近过期积分滞留 |
| 不可退规则 | 兑换成功后积分不退（优惠券/虚拟权益即时发放） | 实物商品支持"取消兑换"或"售后"时按规则退回（见 §3.4） |

### 3.3 积分有效期

- 默认有效期 **12 个月**（可配置为 6/12/24 个月或永久），自积分**到账日**起算；
- 到期积分按"最早到期优先"自动清零，生成 `EXPIRE` 类型流水并通知用户；
- 退款退回的积分，沿用原积分剩余有效期（若原积分已过期则不再退回）。

### 3.4 退款 / 退货扣回

| 场景 | 扣回规则 |
| --- | --- |
| 订单退款（未签收/整单退款） | 若该订单已发放积分，按退款金额占比等比例扣回该笔积分 |
| 部分退款 | 按退款金额/实付金额 × 该笔发放积分 计算应扣回积分，四舍五入取整 |
| 扣回时余额不足 | 账户余额置 0，产生**负余额（欠积分）**；用户后续获得积分时优先补足欠款，补足前不可兑换 |
| 兑换订单售后 | 实物商品"取消兑换"退回全额积分（含原有效期）；"售后退款"按实退价值折算退回；虚拟/券类一经兑换不可退 |

### 3.5 防超兑与一致性

- 积分账户余额扣减与兑换订单创建**同事务**，通过行锁 + 乐观锁（version 字段）保证余额不为负；
- 实物商品库存扣减采用原子操作（`stock >= quantity` 条件下 `stock -= quantity`），超卖由数据库保证；
- 兑换接口支持**幂等键**（用户 + 商品 + 客户端请求号），防止重复提交导致重复扣积分。

## 4. 功能需求

### 4.1 C 端 - 积分账户（用户端）

#### FR-01 积分余额查询
- **入口**：我的 → 积分 / 积分商城首页顶部；
- **展示**：当前可用积分余额、即将过期积分（30 天内到期）提示、积分价值说明（如"100 积分 ≈ 1 元"）；
- **规则**：余额实时读取积分账户，负数（欠积分）状态展示"待补足 XX 积分"。

#### FR-02 积分明细（流水）
- **展示**：分页列表，按时间倒序；每条含：变动类型（获得/消耗/过期/调整/退款扣回）、变动积分（+/-）、业务来源（订单号/兑换单号/规则名）、发生时间、变动后余额；
- **筛选**：按类型（获得/消耗）、按时间范围；
- **规则**：流水只读、不可修改，作为对账依据。

#### FR-03 积分到期提醒
- 到期前 7 天 / 3 天通过站内信 + 推送提醒（用户已开启通知时）；
- 到期清零后生成流水并可查询。

### 4.2 C 端 - 下单积分获取

#### FR-04 下单累积积分（用户端）
- **入口**：订单完成页 / 订单详情"获得积分"入口、积分明细；
- **流程**：订单签收完成 → 系统按 §3.1 计算积分 → 发放到账户 → 通知用户；
- **展示**：下单时商品页/购物车展示"预计可得积分"（按当前有效规则预估，含活动倍数）；订单详情展示"实际到账积分"。

### 4.3 C 端 - 积分商城

#### FR-05 积分商城首页
- **元素**：顶部积分余额卡（含"去赚积分"入口）、Banner 位（运营配置）、分类 Tab（全部/实物/虚拟/优惠券）、商品瀑布流列表（封面、名称、所需积分、库存状态）；
- **排序**：默认按运营配置排序（置顶 + 兑换热度）；支持按所需积分升/降序筛选；
- **状态**：积分不足的商品置灰并显示差额；库存为 0 显示"已兑完"。

#### FR-06 兑换商品详情页
- **元素**：商品主图/详情图、名称、所需积分、市场参考价、库存、剩余可兑数量、兑换说明（发货方式/有效期/是否可退）、用户评价（如有）；
- **交互**：实物商品需填写/确认收货地址；优惠券展示券面规则（门槛、面额、有效期）；
- **CTA**："立即兑换"按钮，积分不足时置灰并提示差额。

#### FR-07 兑换下单流程
1. 用户点击"立即兑换" → 校验登录态（未登录跳转登录）；
2. 展示确认弹窗：商品信息、消耗积分、收货信息（实物）、数量（默认 1，实物限购见商品配置）；
3. 点击确认 → 后端校验（积分余额、库存、限购、幂等）→ 冻结并扣减积分 → 创建兑换订单 → 返回成功；
4. 虚拟权益/优惠券：即时发放（优惠券进入"我的优惠券"，虚拟商品发放兑换码/卡密，页面展示）；
5. 实物商品：进入"待发货"，由后台履约发货。

#### FR-08 我的兑换记录
- 分页列表：兑换单号、商品缩略图/名称、消耗积分、状态、时间；
- 实物：可查看物流信息、申请取消（待发货状态下，全额退积分）与售后；
- 虚拟/券：可查看发放的卡密/券码、复制使用。

#### FR-09 优惠券管理与使用
- 我的优惠券：未使用/已使用/已过期三个 Tab，展示券面额、门槛、有效期、适用商品范围；
- 兑换获得的券在结账时可正常选择使用（复用既有优惠券系统）；
- 券过期前 3 天提醒。

### 4.4 后台 - 积分规则管理（运营）

#### FR-10 积分规则列表与配置
- **列表**：规则名称、类型（基础比例/类目倍数/单笔上限/新用户奖励/活动翻倍）、生效时间、状态（草稿/生效中/已停用）、优先级、创建人；
- **新增/编辑规则**：
  - 基础比例：全局消费积分比例（默认 1:1）；
  - 类目倍数：选择类目/指定商品 + 倍数；
  - 单笔上限：数值配置；
  - 新用户奖励：开关 + 积分值 + 有效期；
  - 活动翻倍：适用范围（全场/类目/商品）、倍数、生效起止时间、优先级；
- **规则校验**：倍数 ≥ 0.1，优先级不可重复；生效时间重叠时按优先级取高；
- **发布流程**：修改生效中的规则需"草稿 → 提交 → 审批（可选）→ 发布"，发布即生效并记录审计日志；
- **灰度**：活动类规则支持按用户比例灰度（如 10% 用户先生效），验证无误后全量。

#### FR-11 规则生效与计算引擎
- 计算顺序：取用户下单时生效的全部规则 → 按优先级从高到低匹配（活动 > 类目倍数 > 全局基础比例）→ 叠加后计算积分；
- 规则以**下单时刻**快照生效（下单后规则变更不影响已下单订单）；
- 提供"规则试算"工具：运营输入金额/类目/用户，预计算可得积分。

### 4.5 后台 - 兑换商品库管理（运营）

#### FR-12 商品分类管理
- 分类 CRUD：名称、排序、启用状态（默认：全部/实物/虚拟/优惠券）；
- 分类下架时提示该分类下商品数量。

#### FR-13 兑换商品管理
- **列表**：缩略图、名称、分类、所需积分、市场价、成本价（仅运营可见）、库存、已兑数量、上下架状态、创建时间；
- **新增/编辑商品**：
  - 基础信息：名称、封面图、详情图、图文详情、分类、排序、上下架开关；
  - 积分定价：所需积分、市场参考价、成本价；
  - 库存：总库存（-1 表示不限量）、每人限购（0 表示不限）、每日限兑总量（可空）；
  - 商品类型：
    - 实物：需收货地址、运费承担方（默认包邮）、发货时效说明；
    - 虚拟：发放类型（兑换码/卡密/直充）、发放文案模板；
    - 优惠券：关联券模板（复用既有优惠券模板，绑定门槛/面额/有效期）；
  - 有效期：商品上架/下架时间（可空=长期）；
- **上下架**：下架后商城不可见，已生成订单不受影响；
- **库存预警**：库存低于阈值（可配置，默认 10）时通知运营。

#### FR-14 券模板关联
- 兑换商品若为优惠券，必须关联一个已启用的券模板；券模板停用时商品自动下架并提示运营处理。

### 4.6 后台 - 兑换订单管理（运营）

#### FR-15 兑换订单列表与处理
- **列表**：兑换单号、用户（脱敏昵称/ID）、商品、消耗积分、数量、状态、下单时间、收货信息（实物）；
- **筛选**：按状态、商品、时间范围、用户；
- **操作**：
  - 实物：确认发货（填物流单号）、查看物流、取消（全额退积分）、售后处理（退部分/全额积分）；
  - 虚拟/券：系统即时发放，运营可"补发"（异常补偿场景，需权限）；
- **对账导出**：按时间段导出 Excel（含用户、商品、积分、状态）。

### 4.7 后台 - 积分流水与调整（运营/财务/超管）

#### FR-16 积分流水查询
- 全量流水检索：用户 ID、手机号（脱敏）、类型、业务单号、时间范围；
- 支持导出与对账，流水不可修改。

#### FR-17 人工积分调整
- 超管/授权运营可手动发放/扣回积分（补偿、活动补发、异常纠正）；
- 需填写调整原因，扣减类调整需**双人审批**（提交人 ≠ 审批人）；
- 调整产生 `ADJUST` 流水并记录操作人与原因，全量审计。

### 4.8 消息通知

#### FR-18 通知触达
| 场景 | 渠道 | 文案要点 |
| --- | --- | --- |
| 积分到账 | 站内信 + 推送（可选短信） | 获得 XX 积分，有效期至 XX |
| 积分即将过期 | 站内信 + 推送 | 7/3 天内到期 XX 积分，快去兑换 |
| 兑换成功 | 站内信 + 推送 | 兑换成功，券/码/物流信息 |
| 实物发货 | 站内信 | 物流单号 |
| 退款扣回 | 站内信 | 退款扣回 XX 积分 |
| 欠积分提醒 | 站内信 | 当前欠 XX 积分，获得积分将优先补足 |

## 5. 业务流程

### 5.1 积分获取流程（下单 → 到账）

```
用户下单支付 → 订单履约（发货） → 订单签收完成
      ↓                                ↓
（下单时展示预估积分）        订单完成事件触发积分发放
                                    ↓
                    计算引擎：匹配生效规则（活动>类目>全局）× 实付金额
                                    ↓
                    校验：单笔上限、活动名额、风控（异常订单不发）
                                    ↓
                    同事务：写积分流水(+) → 更新账户余额 → 记录到期时间
                                    ↓
                            通知用户"到账 XX 积分"
```

**关键判定**：仅"签收完成"状态的订单触发发放；售后/退款单不发放；异常订单（刷单、退款率异常、风控命中）不发或延后人工审核。

### 5.2 积分兑换流程（C 端）

```
浏览商城/搜索商品 → 商品详情 → 点击"立即兑换"
      ↓
后端校验（登录态、积分余额、库存、限购、幂等键）
      ↓ 通过
同事务：扣减积分（按 FEFO 顺序） → 扣减库存 → 创建兑换订单
      ↓
虚拟/优惠券 → 即时发放（券/码入库）
实物 → 待发货 → 运营发货 → 签收 → 完成
      ↓
通知用户 → 我的兑换记录可查 → （实物可取消/售后）
```

### 5.3 订单退款扣回流程

```
订单退款成功（部分/整单）
      ↓
查询该订单发放的积分流水（按 biz_id=订单号）
      ↓
计算应扣回 = 退款金额 / 实付金额 × 发放积分
      ↓
同事务：写积分流水(-) → 更新余额
      ↓
余额不足？ → 余额置 0 + 记欠积分（后续积分先补欠）→ 通知用户
      ↓
完成
```

## 6. 状态机

### 6.1 兑换订单状态机（实物）

```
               用户取消（全额退积分）
                    ↓
待确认 PENDING ──→ 已确认 CONFIRMED ──→ 已发货 SHIPPED ──→ 已完成 COMPLETED
                    ↑                        │
                    └────────── 售后/退款（部分或全额退积分）──→ 已退款 REFUNDED
```

| 状态 | 说明 | 可执行操作 |
| --- | --- | --- |
| PENDING 待确认 | 积分已扣、订单已创建 | 用户取消（退积分）；运营确认 |
| CONFIRMED 已确认 | 运营确认订单 | 运营发货 |
| SHIPPED 已发货 | 已填物流单号 | 用户签收确认 / 申请售后 |
| COMPLETED 已完成 | 签收或超时自动完成 | 申请售后（按售后政策） |
| CANCELLED 已取消 | 取消成功，积分全额退回（含原有效期） | 无 |
| REFUNDED 已退款 | 售后完成，按折算退回积分 | 无 |

> 虚拟/优惠券类兑换：无物流环节，发放即完成（COMPLETED），不支持取消。

### 6.2 优惠券状态机

```
兑换发放 UNUSED（未使用） ──使用──→ USED（已使用）
          │
          └──到期──→ EXPIRED（已过期）
```

### 6.3 积分账户状态

```
正常（余额 ≥ 0）──扣回致不足──→ 欠积分（余额 < 0，仅因退款扣回产生）
欠积分 ──后续获得先补欠──→ 正常（余额 ≥ 0）
欠积分状态下：禁止兑换、禁止消费积分，仅可累积补欠
```

## 10. 非功能需求

### 10.1 性能

| 指标 | 目标 |
| --- | --- |
| 商城列表 / 商品详情接口 | P95 ≤ 500ms |
| 兑换接口 | P95 ≤ 1s（含事务提交） |
| 积分发放异步处理 | 订单完成后 ≤ 5 分钟内到账 |
| 并发能力 | 支撑 1,000 QPS 峰值（按当前平台规模假设，可水平扩展） |

### 10.2 数据一致性与可靠性

- 积分余额、库存、兑换订单**强一致**，采用数据库事务 + 行锁/乐观锁；
- 发放/扣回采用**消息 + 幂等**：消费端按 `biz_id + type` 去重，消息失败自动重试，重试超过 3 次进人工处理队列；
- 定期对账任务：每日核对「流水合计 = 余额变动」与「兑换订单积分合计 = 流水消耗合计」，不一致触发告警。

### 10.3 安全与风控

- 积分兑换接口：登录态校验 + 频率限制（同用户 1 分钟 ≤ 10 次）+ 设备/账号风控（异常 IP、批量注册账号不发积分）；
- 刷单防控：新注册账号 / 高退款率账号 / 异常大额订单进入人工审核，不自动发放；
- 敏感操作（规则发布、人工调整、退款扣回）全量审计日志，不可篡改；
- 后台管理接口统一走权限网关，按角色授权（RBAC）。

### 10.4 可用性与兼容性

- 服务可用性 ≥ 99.9%；依赖的订单系统 / 优惠券系统不可用时，兑换接口降级为"提示稍后再试"，积分余额展示允许短暂降级为缓存；
- 兼容主流移动端 Web / App（iOS / Android）与桌面浏览器，最低支持 iOS 13+ / Android 8+。

### 10.5 合规

- 积分不可提现、不可转让、不可兑换现金，避免"变相返现"合规风险；页面显著说明积分价值与使用规则；
- 用户积分数据遵循隐私政策，仅用于积分服务；流水数据保留期 ≥ 3 年（对账要求）。

## 12. 边界与异常场景处理

| 场景 | 处理 |
| --- | --- |
| 用户积分不足点兑换 | 按钮置灰 + 提示差额，后端二次校验拒绝 |
| 库存不足 / 并发抢兑最后一件 | 事务内原子扣库存，失败提示"手慢了，已兑完"，不扣积分 |
| 重复点击 / 网络重试 | 幂等键去重，仅创建一单、扣一次积分 |
| 订单退款时积分已用于兑换 | 按 §3.4 产生欠积分，后续获得积分优先补足，补足前禁兑 |
| 规则变更与在途订单 | 以下单时刻规则快照为准，不受后续变更影响 |
| 发放消息丢失 / 重复 | 消息重试 + 幂等消费（biz_id + type 唯一） |
| 积分账户与兑换不同步 | 单事务保证；对账任务每日校验并告警 |
| 用户注销账号 | 积分余额清零并生成流水，兑换订单冻结处理（按平台注销规范） |
| 虚拟商品发码失败 | 自动重试 3 次，仍失败转人工补发，订单状态保持"发放中" |
| 风控命中 | 不自动发放积分，订单标记待人工审核，运营在流水查询中处理 |

### 16.2 开放问题（需评审确认）

1. 积分是否支持"积分+现金"混合兑换？（本期否，若业务需要可二期评估）

4. 积分商城实物商品库存是独立库存还是复用主商城库存？（本期独立，避免影响主商城）

## 17. 验收标准（摘要）

- 用户下单签收后可查询到对应积分，金额 × 比例与规则一致；
- 订单退款后按比例扣回积分，扣回后余额与流水一致；
- 积分不足 / 库存不足 / 并发抢兑均不会出现负余额与超卖；
- 运营配置规则与商品后，C 端即时生效（≤ 1 分钟）；
- 全部积分变动可追溯（流水 + 审计），对账任务连续 7 天零差异告警。
