## 1. 背景与目标

### 1.1 背景
当前平台缺少体系化的会员激励手段，用户下单后无长期留存抓手，复购与客单价提升乏力。为增强用户黏性、提升下单频次与客单价，建设统一的会员积分系统：**用户下单累积积分 → 积分在积分商城兑换优惠券或商品**，形成"消费—激励—再消费"的闭环。

### 1.2 产品目标
1. 建立统一的积分获取与消耗通道，覆盖用户全生命周期。
2. 通过积分兑换优惠券，直接促进复购与客单价提升。
3. 通过积分兑换实物/虚拟商品，提升会员价值感知与满意度。
4. 为运营提供可配置的积分规则与兑换商品库管理能力，支撑灵活运营活动。

### 1.3 成功指标（北极星与关键指标）
| 指标类型 | 指标名称 | 目标值（假设，待运营确认） |
| --- | --- | --- |
| 北极星 | 积分兑换参与率（月内发生兑换的用户数 / 有可用积分用户数） | ≥ 15% |
| 过程指标 | 积分消耗率（周期内消耗积分 / 新增积分） | 40% ~ 60% |
| 过程指标 | 兑换优惠券核销率 | ≥ 50% |
| 过程指标 | 兑换订单履约及时率（发货 ≤ 48h） | ≥ 95% |
| 结果指标 | 兑换用户次月复购率提升 | 相对提升 ≥ 5pp |
| 体验指标 | 兑换流程成功率 | ≥ 99.5% |

## 2. 名词定义

| 术语 | 定义 |
| --- | --- |
| 积分 | 用户在平台内累积的虚拟权益数值，1 积分 = 基础单位，可按规则兑换权益 |
| 积分流水 | 记录积分增加/扣减的每一条明细，包含来源、去向、时间、关联单号 |
| 积分余额 | 当前可用积分 = 累计获得 − 累计消耗 − 已过期积分（含冻结部分） |
| 冻结积分 | 兑换订单处理中暂扣的积分，订单完成或取消后释放/扣减 |
| 积分商城 | 用户查看积分余额、浏览并兑换优惠券/商品的页面集合 |
| 兑换商品 | 可被积分兑换的权益，含实物商品与虚拟商品（优惠券、电子卡券等） |
| 积分价值 | 积分与人民币的折算比例，用于兑换定价（默认 100 积分 = 1 元） |
| 积分规则 | 获取比例、有效期、上限、兑换比例等运营可配置的规则集合 |

## 4. 核心业务流程

### 4.1 积分获取（用户下单）
```
用户下单（支付成功）
      │
      ▼
订单系统推送「订单支付成功」事件
      │
      ▼
积分服务按规则计算应得积分（实付金额 × 获取比例 × 活动倍率）
      │
      ▼
写入积分流水（+积分）→ 更新积分余额
      │
      ▼
（订单取消/全额退款时）冲正：按原路径扣回积分
```
说明：积分发放以**订单支付成功**为触发点；订单部分退款按退款金额比例扣回。

### 4.2 积分兑换（用户）
```
用户在积分商城选择优惠券/商品 → 提交兑换
      │
      ▼
校验：积分余额充足 + 商品在架 + 库存充足（实物）+ 每人限兑未超限
      │
      ▼
冻结积分 → 生成兑换订单/券发放
      ├─ 优惠券/虚拟商品：即时发放到用户账户 → 订单完成 → 积分正式扣减
      └─ 实物商品：填写收货地址 → 等待发货 → 用户确认收货/超时自动确认 → 积分正式扣减
      │
      ▼
（用户取消，未发货/未发放前）→ 解冻积分、关闭订单
```

### 4.3 积分规则配置（管理员）
```
运营管理员登录后台 → 积分规则设置页 → 修改参数（获取比例/有效期/上限等）
      → 保存（带生效时间与版本）→ 规则快照生效，历史规则存档可追溯
```

## 5. 功能需求详述

### 5.1 用户端

#### 5.1.1 积分余额与积分明细（积分中心）
- **入口**：用户端「我的 → 积分」；积分商城页顶部展示。
- **功能点**：
  1. 展示当前可用积分余额、即将过期积分（近 30 天过期数量与到期日）、累计获得积分。
  2. 积分明细列表：分页展示每条流水，字段含流水类型（获取/消耗/过期/冻结/解冻/冲正）、变动数量（±）、变动后余额、时间、关联订单/兑换单号。
  3. 支持按时间范围、类型筛选；支持"积分规则说明"入口查看规则全文。
- **交互要求**：余额数据实时刷新；下拉加载更多明细；空状态给出引导文案。

#### 5.1.2 积分商城首页
- **功能点**：
  1. 顶部固定展示积分余额与"去赚积分"入口（跳转积分规则/任务说明）。
  2. Tab 分类：全部 / 优惠券 / 实物商品 / 虚拟商品；支持搜索、按积分价格排序、按"可兑换/即将过期"筛选。
  3. 商品卡片：主图、名称、所需积分、市场参考价（划线价）、剩余库存、每人限兑次数（如有）。
  4. 已兑完商品置灰并显示"已兑完"；不满足兑换条件（限兑次数达上限）显示"已兑换 X 次"。
- **交互要求**：列表懒加载；兑换按钮在余额不足时置灰并提示"积分不足，还差 X 积分"。

#### 5.1.3 兑换优惠券
- **前置条件**：用户登录；积分余额 ≥ 所需积分；该券每人限兑未超限。
- **流程**：点击"立即兑换" → 二次确认弹窗（显示消耗积分与券面信息）→ 确认后即时发放优惠券到"我的卡券" → 提示兑换成功。
- **规则**：
  1. 券类型支持：满减券、折扣券、无门槛券（具体类型由优惠券系统定义）。
  2. 兑换成功后积分立即扣减（等价于冻结后即时完成，不做延迟发货）。
  3. 券有效期遵循优惠券系统配置；券不可转赠（默认假设）。
  4. 券若过期未使用，**积分不退还**（与实物退货策略区分）。

#### 5.1.4 兑换商品（实物/虚拟）
- **实物商品流程**：点击"立即兑换" → 确认弹窗 → 填写/确认收货地址 → 提交 → 冻结积分 → 生成兑换订单（状态：待发货）→ 管理员发货 → 用户确认收货或系统超时自动确认（发货后 15 天）→ 积分正式扣减、订单完成。
- **虚拟商品流程**：点击"立即兑换" → 确认 → 即时发放（卡密/权益到账）→ 订单完成。
- **规则**：
  1. 兑换后默认**不支持退换货**（积分商品特例）；如运营开放退货，则退货时按原值退回积分（已过期积分按"先过期先扣"原则处理）。
  2. 用户可在"待发货"状态下取消兑换，取消后解冻积分、关闭订单；已发货订单不可取消，只能走售后。
  3. 收货地址复用用户默认地址，可临时修改；地址缺失时强制引导填写。
  4. 库存不足时提交失败并提示"手慢了，商品已兑完"。

#### 5.1.5 兑换记录
- **功能点**：按状态 Tab 展示（全部 / 待发货 / 待收货 / 已完成 / 已取消）；列表项含商品/券信息、消耗积分、兑换时间、状态；实物订单可查看物流、确认收货、申请取消。
- **交互要求**：状态变更（发货、取消）通过消息中心通知用户。

#### 5.1.6 积分变动通知
- 积分到账、积分即将过期（到期前 7 天 / 3 天）、兑换成功、兑换取消、发货提醒，通过站内消息/推送通知用户（默认站内信，推送开关由用户控制）。

### 5.2 管理端（运营后台）

#### 5.2.1 积分规则设置
- **功能点**：
  1. **获取规则**：默认获取比例（如 1 元 = 1 积分，可配置为每满 X 元得 Y 积分）；特殊品类倍率（可按商品类目配置 1x/1.5x/2x 倍率）；活动期全局倍率；单笔订单积分上限、单日/单用户积分上限。
  2. **有效期规则**：积分有效期策略（长期有效 / 自获取日 N 个月有效，默认 12 个月）；过期提醒阈值。
  3. **兑换规则**：积分价值比例（100 积分 = 1 元）；兑换商品所需积分定价方式（按价值比例自动生成 + 人工微调）。
  4. **规则生效机制**：保存时生成新版本规则快照，支持"立即生效"或"指定时间生效"；历史版本可查看，支持规则变更操作日志。
- **约束**：规则修改只影响生效后的新订单积分计算，不影响已生成流水；全局倍率与类目倍率冲突时取较高者（假设，可配置）。

#### 5.2.2 兑换商品库管理
- **功能点**：
  1. 商品列表：搜索/筛选（状态、类型、上架时间）、分页；字段含商品名、类型、所需积分、市场价、库存、限兑次数、上下架状态。
  2. **新增/编辑商品**：基础信息（名称、主图、详情图、描述）；类型（优惠券 / 实物 / 虚拟）；兑换定价（所需积分、市场参考价）；库存（实物/虚拟为有限库存，优惠券默认绑定券模板不限库存）；每人限兑次数（默认不限）；上架时间与下架时间；排序权重。
  3. **关联配置**：优惠券类商品关联优惠券模板（券面、有效期由优惠券系统定义）；实物商品关联发货仓库；虚拟商品支持上传卡密/权益码或对接权益发放接口。
  4. **上下架**：下架后商品在商城不可见、不可兑换；已生成的未完成订单不受影响。
  5. **库存管理**：手动调整库存；兑换成功扣减；支持设置低库存预警阈值（如 ≤ 5 时后台提醒并可选自动下架）。
- **约束**：商品删除采用逻辑删除（软删）；已被订单引用的商品不可物理删除。

#### 5.2.3 兑换订单管理
- **功能点**：
  1. 订单列表：按状态/时间/用户/商品筛选；字段含兑换单号、用户、商品、消耗积分、状态、下单时间、收货信息。
  2. 实物订单操作：**发货**（填写物流公司+运单号）、**关闭**（仅待发货状态，需填写原因，关闭后解冻积分并通知用户）。
  3. 优惠券/虚拟商品订单：展示发放状态与卡密信息，支持"补发"（发放失败时）。
  4. 导出：按条件导出 Excel（含对账所需字段）。

#### 5.2.4 积分流水查询（对账）
- 按用户/时间/类型查询积分流水；支持按用户 ID 汇总余额对账；支持导出；异常流水（如重复发放）支持人工冲正（记录操作人）。

#### 5.2.5 数据看板
- 关键指标卡：新增积分、消耗积分、过期积分、兑换单量、兑换用户数、兑换转化率、热门兑换商品 TOP10；支持按日/周/月聚合，可导出图表数据。

## 6. 业务规则（积分规则设计）

### 6.1 积分计算规则
1. **触发**：订单支付成功事件（以实付金额为准，不含运费、不含已使用的积分抵扣额、不含退款部分）。
2. **公式**：`应得积分 = 实付金额 × 默认比例系数 × 类目倍率 × 全局倍率`，结果向下取整。
3. **上限**：单笔订单积分上限（默认 10,000，可配）；用户单日获取上限（默认 50,000，可配）。
4. **幂等**：同一订单同一用户只发放一次积分；订单事件重复推送时幂等去重。

### 6.2 积分扣减与冲正
1. **兑换扣减**：兑换时先冻结，订单完成（券发放成功/商品确认收货）后正式扣减。
2. **取消/退款冲正**：订单全额退款或取消 → 全额扣回该订单发放的积分；部分退款 → 按退款金额占比扣回（向下取整）。扣回时若余额不足，允许积分为负（负数积分），后续获得积分优先补平。
3. **过期扣减**：按"先获得先过期"（FIFO）原则批量扣减过期积分，写入过期流水。

### 6.3 有效期规则
- 默认：积分自获取之日起 12 个月有效，过期自动清零（可配置为长期有效）。
- 即将过期提醒：到期前 7 天、3 天各提醒一次。

### 6.4 兑换约束
1. 兑换所需积分 = 商品定价积分（管理员配置）。
2. 限兑次数：商品维度可配置"每人限兑 N 次/周期"。
3. 黑名单用户不可兑换（若有风控黑名单，则提示"暂不支持兑换"）。
4. 优惠券兑换后积分即时扣减且不退还；实物商品取消/退货时按规则退回积分（默认取消可退、退货不开放）。

### 6.5 异常处理规则
| 场景 | 处理方式 |
| --- | --- |
| 并发兑换导致库存不足 | 预占库存+积分冻结原子操作，失败提示重试 |
| 积分余额与流水不一致 | 定时对账任务，异常流水人工冲正并留痕 |
| 订单事件延迟/缺失 | 定时拉取订单系统补偿（T+1 对账补发） |
| 券发放失败 | 兑换订单标记"发放失败"，支持管理员补发或关闭退款积分 |

## 9. 非功能需求

### 9.1 性能
- 积分余额查询 P99 ≤ 300ms；积分商城列表 P99 ≤ 500ms。
- 兑换提交接口 P99 ≤ 1s（含库存预占与积分冻结事务）。
- 支持并发：按当前平台规模预估（假设日订单 10 万级），积分服务需支持 100 TPS 峰值，可水平扩展。

### 9.2 数据一致性
- 积分增减必须与业务单据在同一事务/最终一致机制内完成；关键链路（发放、兑换）采用事务+幂等键，重试不重复。
- 账户余额使用乐观锁/行锁防止并发超扣。
- 每日定时对账：订单应发积分 vs 实际流水；账户余额 vs 流水汇总。

### 9.3 安全与合规
- 积分账户与流水敏感操作需鉴权与审计日志（管理员操作留痕）。
- 接口需防刷：兑换接口限流、风控校验（异常频次、异常 IP/设备）。
- 用户数据最小化采集，符合个人信息保护相关要求。

### 9.4 可用性
- 核心接口可用性 ≥ 99.9%；兑换失败有明确错误提示与重试机制。

## 10. 异常与边界场景（补充）

| 场景 | 预期行为 |
| --- | --- |
| 用户同时用积分余额在多个设备兑换同一限量商品 | 仅一笔成功，其余提示库存不足/积分不足 |
| 积分即将过期时下单，过期与到账并发 | 先执行过期扣减，再执行到账，余额不出现负数 |
| 管理员误配规则（如倍率过高） | 规则版本可回滚/停用；已发放流水需人工评估冲正 |
| 用户注销账号 | 冻结账户并清零积分（默认积分不可转移、不可提现） |
| 汇率/积分价值调整 | 存量商品定价需运营重新校准，系统提供批量调价工具 |

## 14. 附录

### 14.1 兑换订单状态机
```
          用户取消(待发货)
PENDING_SHIP ────────────────► CANCELLED
     │
     │ 管理员发货
     ▼
   SHIPPED ──用户确认收货/15天自动──► COMPLETED
     │
     └────────────（实物默认不支持退货）────────────┘
ISSUE_FAILED（券/虚拟发放失败）──管理员补发──► COMPLETED
                          └──管理员关闭──► CANCELLED（退回积分）
```

### 14.2 积分流水类型枚举
| flow_type | 含义 | 方向 |
| --- | --- | --- |
| EARN | 订单积分到账 | + |
| SPEND | 兑换完成扣减 | − |
| FREEZE / UNFREEZE | 兑换冻结 / 取消解冻 | − / + |
| EXPIRE | 到期清零 | − |
| REVOKE | 退款/取消订单冲回 | − |
| REFUND | 兑换取消/补发失败退回积分 | + |
| ADMIN | 管理员人工调整（冲正） | ± |

### 14.3 状态与文案（简）
- 余额不足：`积分不足，还差 {X} 积分`
- 库存不足：`手慢了，商品已兑完`
- 限兑超限：`该商品每人限兑 {N} 次`
- 兑换成功：`兑换成功！可在"兑换记录"中查看`
