# PRD · 会员积分系统

> 版本：v1.0 | 日期：2026-08-11 | 复杂度：中等

---

## 一、概述与背景

##### 背景

平台现有促销以一次性让利为主，用户消费后缺乏持续激励，复购与留存不足。同时积分相关规则散落在各处、无法配置化，运营难以精细化调控用户激励节奏。本系统将打通"下单 → 积分 → 兑换"闭环，让每一次消费沉淀为可感知、可消费的积分资产。

##### 目标

- 目标 1：上线 3 个月内平台会员复购率提升 10%
- 目标 2：积分商城月活跃兑换率达到 30%
- 目标 3：积分规则配置化，运营调整规则无需研发发版，配置生效时间 < 5 分钟

##### 角色清单

| 角色 | 职责 | 核心诉求 |
|------|------|---------|
| 普通会员 | 下单累积积分、查看积分余额与明细、在积分商城兑换优惠券/实物商品 | 积分看得见、兑换顺畅、失败原因明确 |
| 平台管理员 | 配置积分规则、管理兑换商品库、处理兑换订单（取消/发货/售后） | 规则灵活可配、商品库可控、订单可追踪 |

##### 场景清单

### 场景 1：下单累积积分（核心）

- **发生时态**：日常
- **角色**：普通会员
- **目标**：完成一笔有效订单后自动获得对应积分，并能在明细中看到入账
- **前置条件**：会员已登录，订单状态达到"已完成"，平台存在生效的返积分规则

### 场景 2：查看积分余额与明细（核心）

- **发生时态**：日常
- **角色**：普通会员
- **目标**：随时了解积分总额与每笔积分的来龙去脉
- **前置条件**：会员已登录

### 场景 3：兑换积分商品（核心）

- **发生时态**：日常
- **角色**：普通会员
- **目标**：用积分兑换优惠券（立即到账）或实物商品（等待发货）
- **前置条件**：会员已登录，积分余额 ≥ 兑换所需积分，商品为上架且有库存

### 场景 4：管理员配置积分规则（边缘）

- **发生时态**：日常
- **角色**：平台管理员
- **目标**：新增/调整返积分比例、适用范围、有效期，配置后立即生效
- **前置条件**：管理员已登录，具有运营配置权限

### 场景 5：管理员管理兑换商品库（边缘）

- **发生时态**：日常
- **角色**：平台管理员
- **目标**：上下架兑换商品、调整兑换积分、维护库存、处理兑换订单
- **前置条件**：管理员已登录，具有商品管理权限

### 场景 6：兑换失败（边缘）

- **发生时态**：异常
- **角色**：普通会员
- **目标**：积分不足/库存不足/超每日上限时，明确知道失败原因，不产生困惑或资损
- **前置条件**：会员尝试兑换但条件不满足

### 场景 7：高并发限量兑换（边缘）

- **发生时态**：峰值
- **角色**：普通会员
- **目标**：限量商品集中兑换时不超发、不重复扣减、库存不为负
- **前置条件**：限量兑换商品开放，大量会员同时兑换

> 复杂度判定说明：本需求共 2 个角色、核心场景 4 个（场景 6/7 为异常与峰值维度识别，按规则仅识别不展开处理方案），判定为**中等**复杂度，产出全部六章。

|------|------|----------|---------|
| 下单累积积分 | 普通会员 | 核心 | 日常 |
| 查看积分余额与明细 | 普通会员 | 核心 | 日常 |
| 兑换积分商品 | 普通会员 | 核心 | 日常 |
| 管理员配置积分规则 | 平台管理员 | 边缘 | 日常 |

### 2.2 层级说明

| 层级 | 节点 | 说明 |
|------|------|------|
| L0 | 会员积分系统 | 打通订单与激励，让消费沉淀为用户可感知、可消费的积分资产 |
| L1 | 积分累积域 | 职责：承接订单完成信号，按规则计算并发放积分 |
| L1 | 积分消费域 | 职责：提供积分商城，承载用户查询余额、明细与兑换 |
| L1 | 运营管理域 | 职责：让管理员配置规则、维护商品库、处理兑换订单 |
| L2 | 积分获取 | 所属域：积分累积域；将完成订单按规则折算为积分入账 |
| L2 | 积分账户 | 所属域：积分累积域；维护用户积分总账（余额/冻结/累计） |
| L2 | 积分商城 | 所属域：积分消费域；展示可兑换商品并受理兑换 |
| L2 | 兑换记录 | 所属域：积分消费域；用户查询历史兑换及状态 |
| L2 | 积分规则配置 | 所属域：运营管理域；维护返积分比例、范围与有效期规则 |
| L2 | 兑换商品管理 | 所属域：运营管理域；维护商品上下架、兑换积分与库存 |
| L2 | 兑换订单管理 | 所属域：运营管理域；处理兑换订单的取消、发货与售后 |
| L3 | 积分明细 | 所属域：积分账户；记录每笔积分收支流水（含余额快照） |

### 3.2 业务链路

#### 核心链路 1：订单完成 → 积分入账（普通会员路径）

```text
┌──────────┐   订单完成事件    ┌──────────┐  匹配规则+计算分值 ┌──────────┐
│ 订单系统  │ ───────────────► │ 积分获取  │ ───────────────► │ 积分账户  │
└──────────┘                  └────┬─────┘                  └────┬─────┘
                                   │                             │
                                   │ <异常：规则缺失/重复事件>     │ 原子入账
                                   ▼                             ▼
                             ┌──────────┐                  ┌──────────┐
                             │ 异常处理  │                  │ 积分流水  │
                             │ 告警+补偿 │                  │ (收支记录)│
                             └──────────┘                  └────┬─────┘
                                                                │
                                                                ▼
                                                          ┌──────────┐
                                                          │ 积分明细  │
                                                          │ (用户可见)│
                                                          └──────────┘
```

链路说明：
1. 订单系统在订单达到"已完成"状态时发出完成事件（含订单号、实付金额、品类）。
2. 积分获取按"商品级 > 品类级 > 全品类"优先级匹配生效规则，计算应得积分。
3. 积分账户原子性增加余额并写入流水（带余额快照），同一订单事件幂等去重。
4. 用户可在积分明细页看到该笔入账；退款订单触发负向回撤流水。

#### 核心链路 2：用户兑换 → 扣积分 → 履约（普通会员 + 管理员路径）

```text
┌──────────┐   提交兑换      ┌──────────┐  校验余额+库存    ┌──────────┐
│ 积分商城  │ ─────────────► │ 兑换下单  │ ───────────────► │ 冻结积分  │
└──────────┘                └────┬─────┘                  └────┬─────┘
                                 │                             │
                                 │ <失败：积分不足/库存不足>     │ 冻结成功
                                 ▼                             ▼
                           ┌──────────┐                  ┌──────────┐
                           │ 兑换失败  │                  │ 兑换订单  │
                           │ 提示原因  │                  │ (待处理)  │
                           └──────────┘                  └────┬─────┘
                                                              │ 按商品类型履约
                                                              ▼
                                    ┌─────────────────────────┼─────────────────────────┐
                                    │                         │                         │
                              ┌─────▼─────┐             ┌─────▼─────┐             ┌─────▼─────┐
                              │ 优惠券类   │             │ 实物类     │             │ 取消/失败  │
                              │ 系统发券   │             │ 管理员发货 │             │ 积分解冻   │
                              └─────┬─────┘             └─────┬─────┘             └───────────┘
                                    │                         │
                                    ▼                         ▼
                              ┌──────────┐             ┌──────────┐
                              │ 已完成    │             │ 已完成    │
                              │ (券到账)  │             │ (已发货)  │
                              └──────────┘             └──────────┘
```

链路说明：
1. 用户提交兑换，系统校验积分余额 ≥ 所需积分、商品为上架且有库存、未超每日上限。
2. 校验通过后先**冻结**积分（防资损），生成兑换订单（状态：待处理）。
3. 优惠券类：调用优惠券系统发券，成功后订单置"已完成"、冻结转扣除；实物类：等待管理员发货（填物流单号）后置"已完成"。
4. 取消/失败路径：积分解冻退回余额，实物类回补库存。

### 3.3 状态流转

#### 兑换订单状态机

```text
      ┌──────────┐   用户提交兑换   ┌──────────┐   发放/发货完成  ┌──────────┐
 ────►│  待处理   │ ──────────────► │  处理中   │ ─────────────► │  已完成   │
      └──────────┘                 └─────┬────┘                 └────┬─────┘
```

##### 状态定义

| 状态 | 含义 | 允许的下一状态 | 触发迁移的动作/条件 |
|------|------|---------------|-------------------|
| 待处理 | 用户已提交兑换，积分已冻结，等待系统发放或管理员处理 | 处理中, 已取消 | 系统开始发券/管理员开始处理；用户取消、库存不足、管理员取消 |
| 处理中 | 系统正在发券或商品准备发货 | 已完成, 已取消 | 发券成功/发货完成；发券失败、管理员取消 |
| 已完成 | 优惠券已到账或实物已发货 | 已退款 | 管理员审核售后通过 |
| 已取消 | 兑换被取消，积分已解冻退回 | — | 用户取消/库存不足/管理员取消 |
| 已退款 | 售后通过，积分退回用户账户，库存回补 | — | 管理员审核售后通过 |

##### 非法迁移

| 从 | 到 | 拒绝原因 | 系统行为 |
|----|-----|---------|---------|
| 已完成 | 已取消 | 券已入账/已发货，不可取消 | 拒绝，引导走售后流程 |
| 已取消 | 处理中 | 终态不可逆 | 拒绝 |
| 已退款 | 已完成 | 终态不可逆 | 拒绝 |

#### 兑换商品状态机

```text
      ┌──────────┐  管理员创建    ┌──────────┐  管理员上架   ┌──────────┐
 ────►│  草稿     │ ───────────► │  已上架   │ ───────────► │  已下架   │
      └──────────┘              └─────┬────┘               └──────────┘
                                      │ 库存扣减至 0          ▲
                                      ▼                      │ 补库存后重新上架
                                ┌──────────┐                 │
                                │  已售罄   │ ────────────────┘
                                └──────────┘
```

##### 状态定义

| 状态 | 含义 | 允许的下一状态 | 触发迁移的动作/条件 |
|------|------|---------------|-------------------|
| 草稿 | 商品已创建但未对用户可见 | 已上架 | 管理员点击上架 |
| 已上架 | 用户可见可兑换 | 已下架, 已售罄 | 管理员下架；库存扣减至 0 |
| 已下架 | 用户不可见 | 已上架 | 管理员重新上架（需库存 > 0） |
| 已售罄 | 库存为 0，展示"已兑完" | 已上架 | 管理员补库存后恢复上架 |

##### 非法迁移

| 从 | 到 | 拒绝原因 | 系统行为 |
|----|-----|---------|---------|
| 已售罄 | 草稿 | 无此业务路径 | 拒绝 |
| 已下架 | 已售罄 | 下架即不可兑换，无售罄概念 | 拒绝 |

### 3.5 流转规则

| 规则 | 触发条件 | 行为 |
|------|---------|------|
| 订单积分入账 | 订单状态变为"已完成" | 按规则计算积分，原子入账 + 写流水（带余额快照） |
| 防重复入账 | 同一订单重复收到完成事件 | 按订单号幂等去重，重复事件直接忽略 |
| 兑换先冻结后扣除 | 用户提交兑换 | 提交时冻结积分；取消/失败解冻；发放/发货成功转扣除 |
| 库存扣减与回补 | 兑换实物商品 / 取消实物兑换 | 提交时原子扣减库存；取消时回补 |
| 积分过期 | 积分超过有效期（默认 365 天） | 定时任务清零过期积分并写流水（类型 expire） |
| 售罄保护 | 库存为 0 仍有兑换请求 | 拒绝兑换，提示"已兑完"，库存不为负 |
| 每日兑换上限 | 商品配置 daily_limit > 0 | 按会员+商品维度计数，超限拒绝 |

## 四、需求详细描述

### 4.1 背景与目标

平台需要建立"消费 → 积分 → 兑换"的激励闭环，提升复购与留存；同时积分规则与商品库需配置化，降低运营调控成本。本期聚焦积分体系从 0 到 1 的落地，确保两条核心链路（积分入账、积分兑换）可用、可控、可追踪。

##### 本期范围

- ✅ 包含：积分获取（订单返积分）、积分账户与明细、积分商城兑换（优惠券/实物）、积分规则配置、兑换商品管理、兑换订单管理
- ❌ 不包含：会员等级体系、积分抵现（订单支付抵扣）、积分转赠、第三方积分互通、数据埋点方案设计、积分活动营销玩法（如签到、任务）

### 4.2 用户故事

#### Story 1：下单获得积分
- **作为** 普通会员
- **我希望** 在完成一笔订单后自动获得对应积分，并能在明细中看到这笔入账
- **以便** 感知消费有回报，愿意持续在平台下单
- **没有这个功能，用户会怎样？** 消费后无激励反馈，复购意愿下降，积分体系形同虚设
- **优先级**：P0

#### Story 2：查看积分余额与明细
- **作为** 普通会员
- **我希望** 随时查看积分余额和每笔积分的来源去向
- **以便** 心里有数，规划如何花积分
- **没有这个功能，用户会怎样？** 积分不可见不可追溯，用户产生不信任感
- **优先级**：P0

#### Story 3：兑换优惠券
- **作为** 普通会员
- **我希望** 用积分兑换一张优惠券，兑换成功后券立即到账、下次下单可用
- **以便** 直接获得下次消费的立减实惠
- **没有这个功能，用户会怎样？** 积分无处消费，激励闭环断裂
- **优先级**：P0

#### Story 4：兑换实物商品
- **作为** 普通会员
- **我希望** 用积分兑换实物商品、填写收货地址，并跟踪发货状态
- **以便** 用积分换取实物奖励
- **没有这个功能，用户会怎样？** 积分只能换券，激励形式单一
- **优先级**：P1

#### Story 5：配置积分规则
- **作为** 平台管理员
- **我希望** 在后台配置/调整返积分比例、适用范围与有效期，配置后立即生效
- **以便** 灵活调控运营策略，无需研发发版
- **没有这个功能，用户会怎样？** 规则写死在代码里，每次调整都要排期
- **优先级**：P0

#### Story 6：管理兑换商品库
- **作为** 平台管理员
- **我希望** 在后台上下架兑换商品、调整兑换积分、维护库存
- **以便** 控制兑换成本与商品供给
- **没有这个功能，用户会怎样？** 商品库无法维护，兑换不可控
- **优先级**：P1

#### Story 7：处理兑换订单
- **作为** 平台管理员
- **我希望** 在后台查看兑换订单并执行取消/发货/售后操作
- **以便** 保证兑换履约可追踪、可干预
- **没有这个功能，用户会怎样？** 兑换异常无人处理，资损不可控
- **优先级**：P1

### 4.3 功能清单

#### 4.3.1 积分获取（订单返积分）

##### 1. 订单积分自动入账

| 四步 | 说明 |
|------|------|
| **触发** | 订单系统推送订单"已完成"事件；订单需满足：会员已登录、订单有效（非取消/退款） |
| **反馈** | 用户无感知（异步）；积分明细页出现"订单返积分"记录，订单完成页提示"本次获得 X 积分" |
| **规则** | 按订单实付金额匹配返积分规则（商品级 > 品类级 > 全品类）；同订单幂等去重；入账原子性 |
| **循环** | 每笔有效订单触发一次；同一订单重复事件直接忽略 |

##### 2. 积分明细查询

| 四步 | 说明 |
|------|------|
| **触发** | 用户进入"我的-积分明细"页 |
| **反馈** | 分页展示流水列表（类型/变动值/余额快照/时间/备注） |
| **规则** | 按时间倒序；支持按类型筛选；入账显示"+X"、扣减显示"-X" |
| **循环** | 下拉加载更多；余额实时来自积分账户 |

##### 异常分支

| 异常类型 | 触发条件 | 系统行为 | 用户提示 |
|---------|---------|---------|---------|
| 网络异常 | 明细加载失败/超时 | 重试 2 次后展示错误页，提供"重新加载" | Toast/错误页 |
| 数据异常 | 流水为空 | 展示空状态"暂无积分记录" | 空状态 + 引导去下单 |
| 权限异常 | 登录态失效 | 跳转登录页，登录后回到原页面 | 登录提示 |
| 并发冲突 | 同一订单重复推送完成事件 | 按订单号幂等去重，重复事件忽略 | 静默 |
| 业务异常 | 订单为退款/取消状态 | 不触发入账；已入账的按退款规则回撤 | 明细中显示"退款回撤"记录 |

##### 业务规则
- 规则 1：积分入账 = 订单实付金额 × 返积分比例（比例取匹配到的最具体规则：商品级 > 品类级 > 全品类级）
- 规则 2：退款订单已发积分需回撤（负向流水），回撤后余额不得为负
- 规则 3：积分有效期按规则配置（默认 365 天，可配 0=永久）

##### 全局状态

| 状态 | 呈现方式 |
|------|---------|
| 加载态 | 明细列表骨架屏 |
| 空状态 | "暂无积分记录" + 去下单引导 |
| 错误态 | 错误提示 + 重新加载按钮 |
| 成功态 | 订单完成页轻提示"+X 积分" |
| 确认操作 | 无需确认（系统自动入账） |
| 撤销操作 | 退款自动回撤，明细展示"回撤"记录 |

#### 4.3.2 积分商城兑换

##### 1. 商品浏览与筛选

| 四步 | 说明 |
|------|------|
| **触发** | 用户进入积分商城首页/商品列表页 |
| **反馈** | 展示余额、推荐商品、分类（优惠券/实物）与排序 |
| **规则** | 仅展示"已上架"且库存 > 0 的商品；按 sort_weight 排序；实物类展示库存余量 |
| **循环** | 可切换分类、分页浏览 |

##### 2. 提交兑换（含二次确认）

| 四步 | 说明 |
|------|------|
| **触发** | 用户在商品详情页点击"立即兑换" |
| **反馈** | 弹出确认弹窗：所需积分、当前余额、到账说明（券类"立即到账"/实物类"填写收货地址"） |
| **规则** | 校验积分余额 ≥ 所需积分；商品为上架且库存 > 0；实物类校验收货地址完整；通过后冻结积分 |
| **循环** | 确认后进入兑换结果页；取消则关闭弹窗，可再次触发 |

##### 3. 兑换结果与记录

| 四步 | 说明 |
|------|------|
| **触发** | 兑换提交成功或失败 |
| **反馈** | 成功页：券类展示"券已发放"、实物类展示"待发货"与订单号；失败页展示具体原因 |
| **规则** | 券类调用优惠券系统发券，发券成功订单置"已完成"；实物类订单置"待处理"，等待管理员发货 |
| **循环** | 用户可在"兑换记录"查看状态变更；实物发货后展示物流单号 |

## 五、验收标准

### AC-01：订单完成积分入账（正常）
- **Given**：会员已登录，存在生效的返积分规则（1 元 = 1 积分），会员有一笔实付 100 元的已完成订单
- **When**：订单系统推送订单完成事件
- **Then**：系统计算得 100 积分并入账，余额增加 100，积分明细出现"订单返积分 +100"记录

### AC-02：兑换优惠券成功（正常）
- **Given**：会员余额 500 积分，兑换商品"满 100 减 10 券"需 200 积分，优惠券系统可用
- **When**：会员确认兑换
- **Then**：余额扣减 200 变为 300，兑换订单状态为"已完成"，优惠券到账，明细出现"-200 兑换"记录

### AC-03：积分不足兑换失败（异常）
- **Given**：会员余额 100 积分，商品需 200 积分
- **When**：会员点击"立即兑换"
- **Then**：兑换被拦截，提示"积分不足，还差 100 分"，余额不变，不产生订单

### AC-04：库存不足兑换失败（异常）
- **Given**：限量实物商品库存为 0（已售罄）
- **When**：会员尝试兑换
- **Then**：兑换被拒绝，提示"已兑完"，商品列表展示"已兑完"标识

### AC-05：并发兑换不超发（边界/峰值）
- **Given**：限量商品库存 1 件，10 个会员同时发起兑换
- **When**：10 个兑换请求并发提交
- **Then**：恰好 1 单成功，其余 9 单失败并提示"手慢了，已兑完"，库存不为负

### AC-06：取消兑换积分退回（边界）
- **Given**：实物商品兑换订单处于"待处理"，已扣 500 积分
- **When**：用户在 30 分钟窗口内取消兑换
- **Then**：订单状态变"已取消"，500 积分退回余额，库存回补 1

### AC-07：规则配置立即生效（正常·管理端）
- **Given**：管理员将返积分比例从 1:1 调整为 1:2 并保存
- **When**：新订单完成
- **Then**：新订单按 1:2 入账，历史订单不受影响

### AC-08：重复事件幂等（异常）
- **Given**：同一已完成订单的完成事件被推送两次
- **When**：系统处理第二次事件
- **Then**：不重复入账，积分明细仅一条记录

## 六、数据指标

### 6.1 核心成功指标（North Star）
- **指标名**：积分商城月活跃兑换率
- **计算方式**：当月有兑换行为的活跃会员数 ÷ 当月活跃会员总数 × 100%
- **目标值**：上线 3 个月后达到 30%
- **数据来源**：积分系统兑换数据 + 会员活跃数据

### 6.2 过程指标

| 指标名 | 计算方式 | 基准值 | 目标值 | 数据来源 |
|-------|---------|-------|-------|---------|
| 积分入账成功率 | 成功入账笔数 ÷ 应入账笔数 | 99% | 99.9% | 积分系统 |
| 兑换转化率 | 提交兑换人数 ÷ 商城访客数 | — | 15% | 积分商城埋点 |
| 兑换失败率 | 失败兑换请求 ÷ 总兑换请求 | — | < 5% | 积分系统 |
| 积分消耗率 | 周期内消耗积分 ÷ 周期内获得积分 | — | ≥ 60% | 积分系统 |
| 优惠券核销率 | 兑换券核销数 ÷ 发放券数 | 平台券基准 | 高于平台券 10% | 优惠券系统 |
| 实物订单发货时效 | 发货时间 − 下单时间 | — | ≤ 48h | 兑换订单数据 |

### 6.3 异常告警阈值

| 监控项 | 告警条件 | 告警级别 | 处理 SOP |
|-------|---------|---------|---------|
| 积分入账失败率 | 连续 5 分钟 > 1% | P0 | 检查订单事件链路与规则配置，人工补偿 |
