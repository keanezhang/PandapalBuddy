# PRD · 会员积分系统

> 版本：v1.0 | 日期：2025-07-01（评测环境无时钟工具，此为假设值，正式发布前替换为实际日期）| 复杂度：中等（2 角色 · 4 场景）

> **关键假设（信息不足部分由需求方代为判断，评审时确认）**
> 1. 积分累积比例默认「实付 1 元 = 1 积分」，管理员可按商品类目/会员等级配置倍率；
> 2. 积分有效期默认 12 个月滚动过期（先入先出 FIFO）；
> 3. 退款处理：全额退款回收该订单全部积分；部分退款按「退款金额/实付金额」比例回收（向下取整）；
> 4. 兑换支持「纯积分」与「积分+现金」两种方式；优惠券兑换成功即时发放至会员卡包（默认有效期 30 天）；
> 5. 实物商品兑换生成「待发货」订单，由管理员发货；发货前可取消并原路退回积分；
> 6. 积分不可转让、不可提现、不可抵扣现金下单（本期）；
> 7. 渠道为现有电商 H5/小程序；会员等级体系本期仅作为规则 scope 的预留维度，不单独建设。

## 一、概述与背景

##### 背景
当前交易体系缺少统一的用户激励与留存机制：用户下单后没有沉淀资产，忠诚度难以量化，优惠券与商品发放分散在各业务线、无法统一运营。积分作为通用激励载体，可将「下单 → 累积 → 兑换 → 复购」串成闭环，同时为管理员提供可配置的运营抓手。

##### 目标
- 目标 1：上线后 4 周内，积分发放覆盖率（获得过积分的用户 / 活跃下单用户）≥ 80%
- 目标 2：上线后 8 周内，积分消耗率（累计消耗积分 / 累计发放积分）≥ 30%
- 目标 3：上线后 8 周内，参与兑换用户占有效积分用户比例 ≥ 15%
- 目标 4：兑换优惠券核销率 ≥ 40%

##### 角色清单

| 角色 | 职责 | 核心诉求 |
|------|------|---------|
| 普通会员 | 下单累积积分；在积分商城查看余额、兑换优惠券/商品；查看积分与兑换记录 | 积分看得清、算得对、兑得顺 |
| 管理员 | 配置积分规则（倍率/有效期）；管理兑换商品库（上架/下架/库存/定价）；处理兑换订单发货与售后；查看运营数据 | 规则可配、商品库易维护、账实一致、异常可追溯 |

##### 场景清单

### 场景 1：下单累积积分（核心）
- **发生时态**：日常
- **角色**：普通会员
- **目标**：订单支付完成后，系统按生效规则自动发放积分
- **前置条件**：会员已登录；订单已支付完成；订单商品属于计分范围（特殊品类除外）

### 场景 2：积分商城查看与兑换（核心）
- **发生时态**：日常
- **角色**：普通会员
- **目标**：查看积分余额与明细，用积分兑换优惠券或商品
- **前置条件**：会员已登录；积分余额 ≥ 兑换所需积分；目标兑换商品有库存且处于上架状态

### 场景 3：订单退款触发积分回收（边缘）
- **发生时态**：异常
- **角色**：普通会员（系统自动处理）
- **目标**：订单退款/取消后，已发放积分按规则回收，保证账实一致
- **前置条件**：已产生积分的订单发生退款/取消；会员积分账户存在可用余额

### 场景 4：管理员配置规则与维护兑换商品库（核心）
- **发生时态**：日常
- **角色**：管理员
- **目标**：配置积分累积倍率与有效期；上架/下架/编辑兑换商品、维护库存；处理兑换订单发货与售后
- **前置条件**：管理员已登录运营后台，具备运营管理权限

##### 场景-角色矩阵

| 场景 | 角色 | 核心/边缘 | 发生时态 |
|------|------|----------|---------|
| 下单累积积分 | 普通会员 | 核心 | 日常 |
| 积分商城查看与兑换 | 普通会员 | 核心 | 日常 |
| 订单退款积分回收 | 普通会员（系统） | 边缘 | 异常 |
| 管理员配置规则与维护商品库 | 管理员 | 核心 | 日常 |

### 2.2 层级说明

| 层级 | 节点 | 说明 |
|------|------|------|
| L0 | 会员积分系统 | 打通「下单累积 → 商城兑换 → 运营配置」的会员积分闭环 |
| L1 | 积分账户与明细 | 职责：维护每个会员的积分余额与全量流水，保证账实一致 |
| L1 | 积分累积 | 职责：与订单系统联动，按规则计算、入账、回收积分 |
| L1 | 积分商城 | 职责：面向会员的兑换入口，支持优惠券与商品兑换 |
| L1 | 运营管理 | 职责：管理员配置积分规则、维护兑换商品库、处理兑换订单、查看报表 |
| L2 | 积分余额查询 | 所属域：积分账户与明细；展示可用/冻结/累计积分 |
| L2 | 积分明细记录 | 所属域：积分账户与明细；记录每一笔发放/消耗/回收/过期流水 |
| L2 | 积分计算入账 | 所属域：积分累积；订单支付完成触发，按规则计算并异步入账 |
| L2 | 退款积分回收 | 所属域：积分累积；订单退款/取消时按比例扣回积分 |
| L2 | 优惠券兑换 | 所属域：积分商城；积分兑换优惠券，即时发放至会员卡包 |
| L2 | 商品兑换 | 所属域：积分商城；积分（或积分+现金）兑换实物/虚拟商品 |
| L2 | 兑换记录查询 | 所属域：积分商城；会员查看历史兑换订单与状态 |
| L2 | 积分规则配置 | 所属域：运营管理；配置积分倍率、计分范围、有效期策略 |
| L2 | 兑换商品库管理 | 所属域：运营管理；商品上架/下架、定价、库存维护 |
| L2 | 兑换订单处理 | 所属域：运营管理；兑换订单发货、取消、退款售后 |
| L2 | 数据报表 | 所属域：运营管理；发放/消耗/兑换转化等运营指标 |

### 2.3 跨域依赖

| 调用方 | 关系 | 被调用方 | 机制说明 |
|--------|------|---------|---------|
| 积分累积·积分计算入账 | 依赖 | 订单系统（支付结果） | 订单支付成功事件触发积分计算，需幂等 |
| 积分累积·退款积分回收 | 依赖 | 订单系统（退款结果） | 退款完成事件触发积分回收 |

### 3.2 业务链路

#### 核心链路 1：订单支付 → 积分累积入账

```text
┌──────────┐   支付成功事件    ┌────────────┐   匹配生效规则   ┌────────────┐
│  订单系统  │ ──────────────► │ 积分计算引擎 │ ─────────────► │ 积分账户服务 │
└──────────┘                  └─────┬──────┘                └─────┬──────┘
                                     │                             │
                                     │ <异常>                      │ 校验通过
                                     ▼                             ▼
                               ┌────────────┐                ┌────────────┐
                               │ 不发放+告警  │                │ 积分入账    │
                               └────────────┘                │ 生成earn流水│
                                                             └─────┬──────┘
                                                                    │
                                                                    ▼
                                                              ┌────────────┐
                                                              │ 会员端余额  │
                                                              │ +明细可见   │
                                                              └────────────┘
```

**链路说明**：订单支付成功 → 触发积分计算（匹配生效规则、按实付金额取整）→ 账户原子入账并生成流水 → 会员端可见。同一订单事件重复推送需幂等去重。

#### 核心链路 2：积分商城兑换（优惠券 / 商品）

```text
┌──────────┐   发起兑换      ┌────────────┐   校验通过     ┌────────────┐
│  会员端    │ ─────────────► │  兑换服务    │ ────────────► │ 积分账户扣减 │
└──────────┘                 └─────┬──────┘               └─────┬──────┘
                                    │                            │
                                    │ <异常：余额不足/           │ 扣减成功
                                    │  库存不足/已下架>          ▼
                                    ▼                       ┌────────────┐
                              ┌────────────┐                │ 生成兑换订单 │
                              │ 提示并终止   │               └─────┬──────┘
                              └────────────┘                      │ 按类型分发
                                                                   ▼
                                     ┌─────────────────────────────┴─────────────────────────────┐
                                     │                                                           │
                               ┌─────▼──────┐                                             ┌─────▼──────┐
                               │ 优惠券：发放 │                                             │ 商品：待发货 │
                               │ 至会员卡包   │                                             │ (管理员发货) │
                               └────────────┘                                             └────────────┘
```

**链路说明**：会员发起兑换 → 校验余额/库存/上架状态 → 原子扣减积分并生成兑换订单 → 按商品类型分发（券即时入卡包；实物进入待发货等待管理员履约）。兑换失败时余额与库存均不变。

### 3.3 状态流转

#### 兑换订单 状态机

```text
     兑换成功(扣减积分)       管理员发货(填物流单号)      确认收货/超时自动确认
┌────────────┐   ──────────► ┌────────────┐   ──────────► ┌────────────┐
│   待发货    │               │   已发货    │               │   已完成    │
└─────┬──────┘               └─────┬──────┘               └────────────┘
      │ 会员/管理员取消(发货前)      │ 售后退货退款
      ▼                            ▼
┌────────────┐               ┌────────────┐
│   已取消    │               │   已退款    │
└────────────┘               └────────────┘
```

##### 状态定义

| 状态 | 含义 | 允许的下一状态 | 触发迁移的动作/条件 |
|------|------|---------------|-------------------|
| 待发货 | 兑换成功、积分已扣减，等待管理员发货（实物商品；优惠券类即时发放无此态） | 已发货, 已取消 | 管理员发货；会员/管理员在发货前取消 |
| 已发货 | 管理员已填写物流单号，商品在途 | 已完成, 已退款 | 确认收货或超时自动完成；售后退货退款 |
| 已完成 | 用户确认收货或系统自动确认，兑换闭环结束 | — | 用户确认收货 / 发货后 N 天自动完成 |
| 已取消 | 发货前取消，积分原路退回账户 | — | 会员取消 / 管理员取消（库存或异常） |
| 已退款 | 售后受理，积分按规则退回 | — | 管理员受理售后并退款 |

##### 非法迁移

| 从 | 到 | 拒绝原因 | 系统行为 |
|----|-----|---------|---------|
| 已完成 | 已取消 | 已完成订单不可取消 | 拒绝并提示联系客服 |
| 已退款 | 已发货 | 已退款订单不可再发货 | 拒绝操作 |
| 已取消 | 已发货 | 已取消订单不可发货 | 拒绝操作并提示订单已关闭 |
| 待发货 | 已退款 | 未发货订单走取消流程而非退款 | 引导走取消 |

### 3.5 流转规则

| 规则 | 触发条件 | 行为 |
|------|---------|------|
| 积分入账 | 订单支付成功 | 按生效规则计算积分并异步入账，生成 earn 流水 |
| 全额退款回收 | 订单全额退款 | 回收该订单已发放的全部积分，生成 refund 流水；余额不足时扣至 0 并记录差额待扣 |
| 部分退款按比例回收 | 订单部分退款 | 按「退款金额/实付金额」比例回收积分，向下取整 |
| 兑换扣减 | 兑换成功 | 原子扣减可用积分（先冻结后扣减），生成 spend 流水 |
| 兑换取消/退款退回 | 兑换订单取消或退款 | 原路退回对应积分，生成 refund 流水 |
| 积分过期 | 超过有效期 | 批量任务按 FIFO 过期，生成 expire 流水 |
| 库存扣减/回补 | 兑换成功 / 取消 | 兑换成功实时扣库存；取消回补库存 |
| 规则切换 | 新规则生效 | 新订单按新规则执行，存量积分与在途订单不受影响 |

### 3.6 缺口标注

- 🟡 **当前状态**：虚拟商品（如会员时长、电子卡券）的发放通道尚未确认；订单系统「支付成功/退款完成」事件的消息字段协议待对接。
- 🟢 **需补充的内容**：虚拟商品发放方式（自动发码 vs 人工发码）；订单事件字段约定（订单号、实付金额、商品明细、退款比例）。
- 🔵 **影响范围**：积分计算入账、商品兑换两个模块的联调范围与上线顺序。

## 四、需求详细描述

### 4.1 背景与目标

会员积分系统将「下单累积」与「商城兑换」串成闭环：会员通过日常下单获得积分资产，积分可在商城兑换优惠券或商品，管理员通过可配置的规则与商品库持续运营。本期聚焦积分累积、账户流水、商城兑换、运营管理四大能力，打通订单系统与券系统。

##### 本期范围
- ✅ 包含：积分规则配置、下单积分累积、退款积分回收、积分余额与明细、优惠券兑换、商品兑换、兑换记录、兑换订单处理、数据报表
- ❌ 不包含：积分转赠/交易、积分提现、会员等级体系（等级仅作为规则 scope 预留维度）、积分抵扣现金下单、独立 App 渠道

### 4.2 用户故事

#### Story 1：下单累积积分（P0）
- **作为** 普通会员
- **我希望** 在订单支付完成后自动获得积分，无需任何额外操作
- **以便** 每次消费都有沉淀，形成「越买越划算」的感知
- **没有这个功能，用户会怎样？** 积分系统失去核心入口，无法累积资产
- **优先级**：P0

#### Story 2：查看积分余额与明细（P0）
- **作为** 普通会员
- **我希望** 在积分商城看到当前可用积分和每一笔收支流水（来源/去向/时间）
- **以便** 确认积分没算错、知道积分从哪来
- **没有这个功能，用户会怎样？** 对积分可信度存疑，兑换意愿下降
- **优先级**：P0

#### Story 3：积分兑换优惠券（P0）
- **作为** 普通会员
- **我希望** 用积分兑换优惠券，兑换后券立即进入我的卡包
- **以便** 在下单时抵扣，直接感受到积分价值
- **没有这个功能，用户会怎样？** 积分只能看不能用，激励闭环断裂
- **优先级**：P0

#### Story 4：积分兑换商品（P1）
- **作为** 普通会员
- **我希望** 用积分（或积分+少量现金）兑换实物/虚拟商品，并跟踪发货状态
- **以便** 高价值积分有出口，兑换体验完整
- **没有这个功能，用户会怎样？** 兑换品类单一，积分价值感不足
- **优先级**：P1

#### Story 5：管理员配置积分规则（P0）
- **作为** 管理员
- **我希望** 按商品类目/会员等级配置积分倍率，并设置积分有效期
- **以便** 根据运营节奏灵活调节积分发放力度
- **没有这个功能，用户会怎样？** 规则写死，运营无法调节成本
- **优先级**：P0

#### Story 6：管理员维护兑换商品库（P1）
- **作为** 管理员
- **我希望** 上架/下架/编辑兑换商品，维护积分定价与库存
- **以便** 持续优化兑换供给，避免超卖
- **没有这个功能，用户会怎样？** 兑换商品无法更新，商城内容固化
- **优先级**：P1

#### Story 7：管理员处理兑换订单（P1）
- **作为** 管理员
- **我希望** 查看兑换订单并发货、处理取消与售后退款
- **以便** 兑换闭环可控、账实一致
- **没有这个功能，用户会怎样？** 实物兑换无人履约，体验失控
- **优先级**：P1

#### Story 8：订单退款自动回收积分（P1）
- **作为** 普通会员（系统自动处理）
- **我希望** 订单退款时系统按比例自动扣回积分并展示流水
- **以便** 积分账实一致，避免「退款还赚积分」
- **没有这个功能，用户会怎样？** 积分虚增，运营成本失控
- **优先级**：P1

### 4.3 功能清单

#### 4.3.1 积分累积（下单入账）

##### 1. 支付成功触发积分计算

| 四步 | 说明 |
|------|------|
| **触发** | 订单系统推送「支付成功」事件（含订单号、实付金额、商品明细） |
| **反馈** | 系统内部处理，不直接打扰用户；积分到账后会员端余额更新 |
| **规则** | 匹配生效积分规则（按类目/等级取倍率，默认 1 元 = 1 积分）；特殊品类不计分；按实付金额向下取整；运费不计分 |
| **循环** | 事件驱动，每笔订单触发一次；事件重复推送需幂等去重 |

##### 2. 积分入账与流水生成

| 四步 | 说明 |
|------|------|
| **触发** | 积分计算结果通过校验 |
| **反馈** | 可用余额增加，生成 earn 流水，会员端明细可见 |
| **规则** | 账户更新与流水写入须原子；积分有效期按入账日滚动（默认 12 个月） |
| **循环** | 入账后监听订单退款事件，进入回收流程 |

##### 异常分支

| 异常类型 | 触发条件 | 系统行为 | 用户提示 |
|---------|---------|---------|---------|
| 网络异常 | 订单事件推送失败/超时 | 重试（≥3 次），仍失败进告警 | 无（后台告警） |
| 数据异常 | 订单金额缺失/为 0/规则未命中 | 不发放积分并记录原因 | 无 |
| 权限异常 | 事件来源未授权 | 拒绝消费并告警 | 无 |
| 并发冲突 | 同一订单事件重复推送 | 幂等校验（按订单号去重） | 无 |
| 业务异常 | 订单含不计分商品 | 仅对计分部分计算 | 无 |

##### 业务规则
- 规则 1：积分计算以「实付金额」为基数，运费不计分
- 规则 2：默认倍率 1 元 = 1 积分，按类目/等级可覆盖
- 规则 3：积分发放为异步事件驱动，延迟 ≤ 5 分钟
- 规则 4：同一订单仅入账一次（幂等）

##### 全局状态

| 状态 | 呈现方式 |
|------|---------|
| 加载态 | 会员端余额加载用骨架屏 |
| 空状态 | 无流水时展示「暂无积分记录」+ 去下单引导 |
| 错误态 | 余额展示异常时显示「--」并支持刷新 |
| 成功态 | 入账不主动打扰；明细中出现 earn 流水 |
| 确认操作 | 积分回收为系统行为，不要求用户确认 |
| 撤销操作 | 入账错误由管理员用 adjust 流水冲正，保留审计 |

#### 4.3.2 积分商城（余额查看与兑换）

##### 1. 查看积分余额与规则

| 四步 | 说明 |
|------|------|
| **触发** | 会员进入积分商城首页 |
| **反馈** | 展示可用积分、累计积分、冻结积分及积分规则说明 |
| **规则** | 未登录不可见，跳登录；余额实时读取账户服务 |
| **循环** | 停留页面，可跳转明细/兑换列表 |

##### 2. 兑换优惠券

| 四步 | 说明 |
|------|------|
| **触发** | 会员点击「兑换」优惠券，余额 ≥ 所需积分 |
| **反馈** | 弹出确认框（消耗积分/券面值/有效期），确认后显示兑换成功 |
| **规则** | 校验余额、券库存、上架状态；成功后原子扣积分、生成兑换单、发放券到卡包 |
| **循环** | 兑换成功后可继续兑换其他券；余额不足置灰并提示差额 |

##### 3. 兑换商品

| 四步 | 说明 |
|------|------|
| **触发** | 会员在商品详情页点击「立即兑换」，实物商品填写收货信息 |
| **反馈** | 确认框展示积分+现金合计，确认后提示「兑换成功，等待发货」 |
| **规则** | 校验余额/库存/上架状态；混合支付时同时发起积分扣减与现金支付；成功后生成待发货订单 |
| **循环** | 兑换后进入兑换记录跟踪物流；发货前可取消退回积分 |

##### 4. 查看兑换记录与明细

| 四步 | 说明 |
|------|------|
| **触发** | 会员进入兑换记录页/积分明细页 |
| **反馈** | 分页展示订单状态、时间、消耗积分；明细展示收支流水 |
| **规则** | 仅展示本人数据；状态实时刷新 |
| **循环** | 可下拉刷新、点击订单看详情 |

##### 异常分支

| 异常类型 | 触发条件 | 系统行为 | 用户提示 |
|---------|---------|---------|---------|
| 网络异常 | 兑换请求超时 | 前端防重复提交，提示稍后重试；已扣分未出单时自动补偿 | Toast「网络异常，请重试」 |
| 数据异常 | 兑换商品已下架/库存为 0 | 拦截兑换，列表置灰 | 「该商品已兑完/已下架」 |
| 权限异常 | 未登录/登录态过期 | 拦截并跳登录 | 登录引导 |
| 并发冲突 | 多人同时抢兑最后库存 | 乐观锁/库存预扣，失败回滚 | 「手慢了，库存不足」 |
| 业务异常 | 积分余额不足 | 拦截并提示差额 | 「积分不足，还差 X 分」 |

##### 业务规则
- 规则 1：兑换扣积分与库存扣减须原子（先冻结后扣减）
- 规则 2：优惠券兑换即时发放，有效期默认 30 天（可配置）
- 规则 3：实物商品兑换需填收货信息；虚拟商品免填
- 规则 4：发货前取消兑换 → 积分原路退回；发货后退款 → 走售后
- 规则 5：积分不可转让、不可提现

##### 全局状态

| 状态 | 呈现方式 |
|------|---------|
| 加载态 | 商品列表骨架屏 / 兑换按钮 Loading |
| 空状态 | 无可兑换商品展示空态 + 运营文案 |
| 错误态 | 兑换失败弹窗展示具体原因 |
| 成功态 | 兑换成功弹窗 + 跳转兑换记录 |
| 确认操作 | 兑换前二次确认（展示消耗与所得） |
| 撤销操作 | 发货前可取消兑换（窗口期 = 发货前） |

#### 4.3.3 运营管理（规则配置与商品库）

##### 1. 配置积分规则

| 四步 | 说明 |
|------|------|
| **触发** | 管理员进入积分规则配置页，新增/编辑规则 |
| **反馈** | 表单校验通过后保存，规则列表即时更新 |
| **规则** | 同一 scope 仅一条生效规则；规则生效区间不可重叠；修改后新订单按新规则执行，存量积分不受影响 |
| **循环** | 可随时停用规则；变更记录留痕（操作人/时间） |

| 四步 | 说明 |
|------|------|

| **反馈** | 保存后商品在商城端按状态展示（草稿不可见，上架可见） |
| **规则** | 库存 ≥0；下架商品不可兑换但历史订单保留；修改积分价只影响后续兑换 |
| **循环** | 支持批量上下架与库存调整 |

##### 3. 处理兑换订单

| 四步 | 说明 |
|------|------|
| **触发** | 管理员在兑换订单处理页查看待发货订单，点击发货填写物流单号 |
| **反馈** | 订单状态更新为已发货，会员端可见物流 |
| **规则** | 仅实物商品需发货；取消/退款需二次确认并注明原因；退款自动退回积分 |
| **循环** | 发货后可跟踪物流直至完成；售后单可继续处理 |

##### 4. 查看数据报表

| 四步 | 说明 |
|------|------|
| **触发** | 管理员进入数据报表页，选择时间范围 |

## 五、验收标准

### AC-01：下单支付成功自动累积积分（正常）
- **Given**：会员已登录，存在生效积分规则（默认 1 元 = 1 积分）；订单 A 实付 100 元且已支付成功
- **When**：订单系统推送支付成功事件
- **Then**：会员积分余额增加 100；积分明细新增 1 条 earn 流水（金额 100、余额对账一致）；重复推送同事件不重复入账

### AC-02：积分兑换优惠券并即时到账（正常）
- **Given**：会员积分余额 500；优惠券 B 兑换价 100 积分，库存充足且上架
- **When**：会员确认兑换优惠券 B
- **Then**：余额扣减 100 变为 400；生成 spend 流水；券即时出现在「我的优惠券」；券有效期正确

### AC-03：积分不足时兑换被拦截（异常）
- **Given**：会员积分余额 50；商品 C 兑换价 100 积分
- **When**：会员点击兑换商品 C
- **Then**：兑换被拦截；提示「积分不足，还差 50 分」；余额与库存均不变

### AC-04：并发抢兑最后 1 件库存（边界）
- **Given**：商品 D 库存 1；两名会员同时发起兑换
- **When**：两人几乎同时提交
- **Then**：仅 1 人兑换成功并扣积分；另一人收到「库存不足」提示，积分未扣减；库存不为负

### AC-05：订单退款按比例回收积分（异常）
- **Given**：订单 A 已发放 100 积分；订单发生部分退款 50 元（原实付 100 元）
- **When**：订单系统推送退款完成事件
- **Then**：积分按 50% 比例回收 50 分；生成 refund 流水；余额正确扣减；回收后余额不为负

### AC-06：发货前取消兑换退回积分（正常）
- **Given**：兑换订单处于待发货状态，消耗 200 积分
- **When**：会员取消兑换订单
- **Then**：订单状态变为已取消；200 积分原路退回；生成 refund 流水；商品库存回补 1

### AC-07：管理员配置规则即时生效（正常）
- **Given**：管理员将某类目积分倍率从 1 改为 2
- **When**：新规则保存后，会员购买该类目商品 100 元并支付成功
- **Then**：积分按新倍率发放 200 分；改规则前已入账积分不受影响

### AC-08：权限控制（异常）
- **Given**：非管理员账号访问积分规则配置页
- **When**：发起配置请求
- **Then**：返回无权限提示；操作被拒绝并记录审计日志

## 六、数据指标

### 6.1 核心成功指标（North Star）
- **指标名**：积分消耗率
- **计算方式**：累计消耗积分（兑换 + 过期）/ 累计发放积分 × 100%
- **目标值**：上线 8 周后 ≥ 30%
- **数据来源**：积分流水表聚合

### 6.2 过程指标

| 指标名 | 计算方式 | 基准值 | 目标值 | 数据来源 |
|-------|---------|-------|-------|---------|
| 积分发放覆盖率 | 获得过积分用户 / 活跃下单用户 | 0% | ≥80%（4 周） | 流水 + 订单 |
| 兑换参与率 | 参与兑换用户 / 有积分用户 | 0% | ≥15%（8 周） | 兑换订单 |
| 优惠券核销率 | 已核销券 / 已发放券 | — | ≥40% | 券系统 |
| 兑换商品售罄率 | 售罄商品数 / 上架商品数 | — | 20%~60%（健康区间） | 商品库 |
| 退款积分回收率 | 回收积分 / 应回收积分 | — | ≥99% | 流水 |
| 兑换失败率 | 兑换失败次数 / 兑换请求次数 | — | <2% | 兑换服务 |

### 6.3 异常告警阈值

| 监控项 | 告警条件 | 告警级别 | 处理 SOP |
|-------|---------|---------|---------|
| 积分入账失败率 | 入账失败率 > 1% 或事件积压 > 1000 | P0 | 查事件通道与账户服务，人工补偿 |
| 兑换失败率 | 失败率 > 5%（持续 10 分钟） | P1 | 查库存/余额服务，必要时熔断兑换入口 |
| 库存超卖 | 库存出现负数 | P0 | 冻结该商品兑换，对账并修正 |
| 积分扣减不一致 | 流水余额与账户余额对不上 | P1 | 跑对账任务，定位差异单 |
| 退款回收缺口 | 应回收未回收积分单量 > 50 | P2 | 定时任务重试回收 |
