## 一、概述与背景

##### 背景
当前交易体系缺少统一的用户激励与留存机制：用户下单后没有沉淀资产，忠诚度难以量化，优惠券与商品发放分散在各业务线、无法统一运营。积分作为通用激励载体，可将「下单 → 累积 → 兑换 → 复购」串成闭环，同时为管理员提供可配置的运营抓手。

##### 目标
- 目标 1：上线后 4 周内，积分发放覆盖率（获得过积分的用户 / 活跃下单用户）≥ 80%
- 目标 2：上线后 8 周内，积分消耗率（累计消耗积分 / 累计发放积分）≥ 30%
- 目标 3：上线后 8 周内，参与兑换用户占有效积分用户比例 ≥ 15%
- 目标 4：兑换优惠券核销率 ≥ 40%

##### 角色清单

| 角色 | 职责 | 核心诉求 |
|------|------|---------|
| 普通会员 | 下单累积积分；在积分商城查看余额、兑换优惠券/商品；查看积分与兑换记录 | 积分看得清、算得对、兑得顺 |
| 管理员 | 配置积分规则（倍率/有效期）；管理兑换商品库（上架/下架/库存/定价）；处理兑换订单发货与售后；查看运营数据 | 规则可配、商品库易维护、账实一致、异常可追溯 |

##### 场景清单

### 场景 1：下单累积积分（核心）
- **发生时态**：日常
- **角色**：普通会员
- **目标**：订单支付完成后，系统按生效规则自动发放积分
- **前置条件**：会员已登录；订单已支付完成；订单商品属于计分范围（特殊品类除外）

### 场景 2：积分商城查看与兑换（核心）
- **发生时态**：日常
- **角色**：普通会员
- **目标**：查看积分余额与明细，用积分兑换优惠券或商品
- **前置条件**：会员已登录；积分余额 ≥ 兑换所需积分；目标兑换商品有库存且处于上架状态

### 场景 3：订单退款触发积分回收（边缘）
- **发生时态**：异常
- **角色**：普通会员（系统自动处理）
- **目标**：订单退款/取消后，已发放积分按规则回收，保证账实一致
- **前置条件**：已产生积分的订单发生退款/取消；会员积分账户存在可用余额

### 场景 4：管理员配置规则与维护兑换商品库（核心）
- **发生时态**：日常
- **角色**：管理员
- **目标**：配置积分累积倍率与有效期；上架/下架/编辑兑换商品、维护库存；处理兑换订单发货与售后
- **前置条件**：管理员已登录运营后台，具备运营管理权限

### 2.2 层级说明

| 层级 | 节点 | 说明 |
|------|------|------|
| L0 | 会员积分系统 | 打通「下单累积 → 商城兑换 → 运营配置」的会员积分闭环 |
| L1 | 积分账户与明细 | 职责：维护每个会员的积分余额与全量流水，保证账实一致 |
| L1 | 积分累积 | 职责：与订单系统联动，按规则计算、入账、回收积分 |
| L1 | 积分商城 | 职责：面向会员的兑换入口，支持优惠券与商品兑换 |
| L1 | 运营管理 | 职责：管理员配置积分规则、维护兑换商品库、处理兑换订单、查看报表 |
| L2 | 积分余额查询 | 所属域：积分账户与明细；展示可用/冻结/累计积分 |
| L2 | 积分明细记录 | 所属域：积分账户与明细；记录每一笔发放/消耗/回收/过期流水 |
| L2 | 积分计算入账 | 所属域：积分累积；订单支付完成触发，按规则计算并异步入账 |
| L2 | 退款积分回收 | 所属域：积分累积；订单退款/取消时按比例扣回积分 |
| L2 | 优惠券兑换 | 所属域：积分商城；积分兑换优惠券，即时发放至会员卡包 |
| L2 | 商品兑换 | 所属域：积分商城；积分（或积分+现金）兑换实物/虚拟商品 |
| L2 | 兑换记录查询 | 所属域：积分商城；会员查看历史兑换订单与状态 |
| L2 | 积分规则配置 | 所属域：运营管理；配置积分倍率、计分范围、有效期策略 |
| L2 | 兑换商品库管理 | 所属域：运营管理；商品上架/下架、定价、库存维护 |
| L2 | 兑换订单处理 | 所属域：运营管理；兑换订单发货、取消、退款售后 |
| L2 | 数据报表 | 所属域：运营管理；发放/消耗/兑换转化等运营指标 |
