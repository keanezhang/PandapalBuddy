# PRD · 宠物领养平台

> 版本：v1.0 | 日期：2026-08-11 | 复杂度：复杂

---

## 一、概述与背景

##### 背景

当前宠物领养流程依赖线下公告栏与社交群组，信息分散、健康档案缺失，领养人无法判断宠物健康状况，管理员难以追踪申请进度，兽医的检查结果也无法沉淀为可查证的档案。平台希望将「信息发布 → 领养申请 → 审核 → 健康档案」全流程线上化，形成可追踪、可信赖的领养闭环。

##### 目标

- 目标 1：上线 4 周内完成 200 只宠物领养信息线上化发布，信息完整度 ≥ 90%
- 目标 2：领养申请平均审核时长 ≤ 24 小时，审核通过率稳定在 40%~60%
- 目标 3：在库宠物健康档案覆盖率 ≥ 95%（兽医录入），用户详情页档案查看率 ≥ 60%
- 目标 4：申请-审核-结果通知全链路可追踪，用户可在「我的申请」实时查看状态

##### 角色清单

| 角色 | 职责 | 核心诉求 |
|------|------|---------|
| 普通用户（领养申请人） | 浏览/搜索宠物、查看健康档案、提交领养申请、跟进申请状态 | 快速找到健康、合适的宠物并成功领养 |
| 平台管理员 | 审核领养申请、维护宠物上下架、管理用户与内容 | 审核高效准确、无纠纷、数据可追踪 |
| 兽医 | 为在库宠物录入/更新健康档案 | 档案录入高效、专业信息不被篡改 |

##### 场景清单

### 场景 1：浏览与搜索领养信息（核心）

- **发生时态**：日常
- **角色**：普通用户
- **目标**：按品种/年龄/地区筛选宠物，查看详情与健康档案，决定是否申请
- **前置条件**：平台已发布宠物信息（含档案），用户可匿名浏览

### 场景 2：提交领养申请（核心）

- **发生时态**：日常
- **角色**：普通用户
- **目标**：填写领养理由、居住与饲养条件，提交申请并收到回执
- **前置条件**：用户已登录，目标宠物状态为「待领养」

### 场景 3：管理员审核申请（核心）

- **发生时态**：日常
- **角色**：平台管理员
- **目标**：查看申请人资料与宠物信息，通过/驳回申请并给出结论，必要时电话回访
- **前置条件**：存在「待审核/审核中」的申请单，管理员有审核权限

### 场景 4：兽医上传健康档案（核心）

- **发生时态**：日常
- **角色**：兽医
- **目标**：为指定宠物录入疫苗接种、体检、绝育等健康档案，供领养人查看
- **前置条件**：兽医已实名认证并绑定机构，宠物在库且档案未锁定

### 场景 5：申请被驳回后重新申请（边缘）

- **发生时态**：异常
- **角色**：普通用户
- **目标**：查看驳回原因，修改资料后重新提交申请
- **前置条件**：原申请状态为「已驳回」，宠物仍为「待领养」

### 场景 6：新用户首次使用（边缘）

- **发生时态**：首次
- **角色**：普通用户
- **目标**：完成注册/登录，了解领养流程，收藏心仪宠物
- **前置条件**：无账号，需手机号注册或第三方登录

### 场景 7：热门宠物多人同时申请（边缘）

- **发生时态**：峰值
- **角色**：普通用户、管理员
- **目标**：同一宠物短时间内收到多份申请，管理员按规则择优审核
- **前置条件**：宠物被多人同时申请，系统需保证申请不丢单、状态不串号

##### 场景-角色矩阵

| 场景 | 角色 | 核心/边缘 | 发生时态 |
|------|------|----------|---------|
| 浏览与搜索领养信息 | 普通用户 | 核心 | 日常 |
| 提交领养申请 | 普通用户 | 核心 | 日常 |
| 管理员审核申请 | 管理员 | 核心 | 日常 |
| 兽医上传健康档案 | 兽医 | 核心 | 日常 |
| 申请被驳回后重新申请 | 普通用户 | 边缘 | 异常 |
| 新用户首次使用 | 普通用户 | 边缘 | 首次 |
| 热门宠物多人同时申请 | 普通用户、管理员 | 边缘 | 峰值 |

## 1. 产品概述

### 1.1 背景与问题

线下宠物领养存在信息分散、流程不透明、健康信息缺失等问题：领养人难以找到真实可靠的待领养宠物信息；救助机构/管理员靠人工登记、线下沟通审核，效率低且无留痕；宠物的疫苗接种、体检等健康档案缺乏统一管理入口，领养人无法在决策前了解宠物健康状况。

### 1.2 产品定位

一个连接「待领养宠物信息发布方（管理员）— 领养人 — 兽医」三方角色的在线领养平台，实现**信息浏览 → 在线申请 → 管理员审核 → 健康档案共享**的完整闭环。

### 1.3 产品目标

1. 让领养人快速、可信地浏览待领养宠物信息并发起领养申请；
2. 让管理员在线完成申请审核，流程留痕、状态可追踪；
3. 让兽医为宠物建立并维护健康档案，为领养决策提供健康依据。

### 1.4 本期范围（In Scope）

- 宠物领养信息浏览（列表 + 筛选 + 详情）
- 领养人提交领养申请与状态查询
- 管理员审核领养申请（通过/驳回）
- 兽医上传/维护宠物健康档案
- 基础用户注册登录与角色权限控制（权限矩阵）

### 1.5 不在本期范围（Out of Scope）

- 线上支付 / 领养押金交易
- 宠物寄养、宠物用品商城
- 移动端 App（本期仅适配 Web 响应式）
- 与外部救助机构系统的对接

| 角色 | 角色编码 | 说明 |
| --- | --- | --- |
| 访客 | GUEST | 未登录用户，仅可浏览公开信息 |
| 领养人 | ADOPTER | 注册登录用户，可浏览信息、提交/查看领养申请 |
| 兽医 | VET | 经管理员认证的兽医账号，可上传/编辑宠物健康档案 |
| 管理员 | ADMIN | 平台运营人员，管理宠物信息、审核领养申请、管理用户 |

## 3. 功能需求

### FR-1 宠物领养信息浏览

**FR-1.1 宠物列表页**
- 展示待领养宠物卡片：照片、昵称、品种、性别、年龄、所在地区、领养状态（待领养/审核中/已领养）。
- 支持按品种、性别、年龄区间、地区、状态进行筛选；支持关键字搜索（昵称/品种）。

**FR-1.2 宠物详情页**
- 展示宠物照片集、基本信息（品种、年龄、性别、毛色、体型、性格描述、救助故事）、领养要求（如领养人需有稳定住所）。
- 展示「健康档案」区块：疫苗记录、绝育状态、体检记录、驱虫记录（由兽医维护，见 FR-4）。
- 展示领养状态与「申请领养」入口（未登录访客点击后跳转登录页）。

### FR-2 领养申请

**FR-2.1 提交申请**
- 领养人填写申请表：姓名、联系电话、微信号、所在城市、居住情况（自有住房/租房）、是否有养宠经验、家庭其他成员情况、领养理由、期望领养时间。
- 同一领养人对同一宠物**同时仅可存在 1 条「待审核/审核中」申请**（防重复提交）。
- 提交成功后生成申请单号，状态为「待审核」，系统通知管理员。

**FR-2.2 申请状态查询**
- 领养人可在「我的申请」列表查看申请单状态及管理员审核意见。
- 状态流转：待审核 → 审核中 →（已通过 | 已驳回）→ 已完成（领养确认）。

**FR-2.3 撤回申请**
- 在「待审核/审核中」状态下，领养人可撤回申请；撤回后宠物状态若为「审核中」则回退为「待领养」。

### FR-3 管理员审核

**FR-3.1 审核列表**
- 管理员在后台查看全部申请单，支持按状态（待审核/审核中/已通过/已驳回）、宠物、提交时间筛选。

**FR-3.2 审核操作**
- 管理员可将申请标记为「审核中」；执行「通过」或「驳回」并**必须填写审核意见**。
- 审核通过后，对应宠物状态自动变为「已领养」，同一宠物的其他「待审核」申请自动变为「已驳回」（驳回原因：宠物已被领养）。
- 审核结果实时通知申请人（站内信/短信，短信为可选能力）。

### FR-4 兽医上传健康档案

**FR-4.1 档案创建**
- 兽医可为关联宠物创建健康档案，含字段：疫苗记录（疫苗名称、接种日期、下次接种日期）、绝育状态、最近体检日期与体检结论、驱虫记录（药品、日期）、慢性病史/注意事项。
- 支持上传附件（体检报告 PDF / 图片），单个附件 ≤ 10MB。

**FR-4.2 档案编辑与可见性**
- 兽医可编辑自己创建的档案；管理员可编辑/删除任意档案。
- 档案在宠物详情页对**所有访客可见**（公开健康信息），附件可设「仅领养人可见」标记。
- 档案变更记录操作人、时间（审计留痕）。

### FR-5 用户与权限管理（基础）

- 注册/登录：手机号 + 验证码或邮箱 + 密码。
- 兽医角色由管理员在后台开通（审核兽医资质后授予 VET 角色）。
- 后端基于 RBAC 按权限矩阵（见第 5 节）做接口级鉴权，未授权请求返回 403。

## 4. 业务规则与状态流转

### 4.1 领养申请状态机

```
待审核 --(管理员标记)--> 审核中 --(通过)--> 已通过 --(领养确认)--> 已完成
                            |--(驳回)--> 已驳回
待审核/审核中 --(领养人撤回)--> 已撤回
```

### 4.2 宠物状态机

```
待领养 --(申请审核中)--> 审核中 --(审核通过)--> 已领养
审核中 --(申请驳回/撤回)--> 待领养
```

### 4.3 关键业务规则

- BR-1：同一领养人同一宠物同时仅 1 条有效申请。
- BR-2：管理员驳回/通过必须填写审核意见，否则不可提交。
- BR-3：宠物「已领养」后自动驳回该宠物其余待审核申请。
- BR-4：非管理员不可访问后台审核接口（权限矩阵强制）。
- BR-5：健康档案仅 VET / ADMIN 可写，其余角色只读。

| 领养申请 | 撤回自己的申请 | ❌ | ✅ | ❌ | ✅ |
| 领养申请 | 查看全部申请 | ❌ | ❌ | ❌ | ✅ |
| 领养申请 | 审核（通过/驳回） | ❌ | ❌ | ❌ | ✅ |

判定要求：
- 对每条断言，分别对 A 和 B 给出 score：1=完全满足（有明确证据）；0.5=部分满足；0=不满足或相反。
- evidence 必须引用 A.md/B.md 或对应产出文件的具体原文（引用位置 + 原文），不允许空证据。
- assertion_index 为断言清单中的编号（1 到 4），不要用 0 开始的索引。
- 输出纯 JSON（不要多余文字），格式：
{
  "A": [
    {"assertion_index": 1, "score": 1, "evidence": "A.md: '原文引用'", "evidence_ref": "A.md:12"}
  ],
  "B": [...]
}
- 若某条断言在输出中完全找不到对应内容，score 记 0，evidence 写 "A.md/B.md 中未找到相关内容"。
