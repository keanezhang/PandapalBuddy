## 1. 产品概述

### 1.1 背景

城市流浪动物与待领养宠物数量持续增长，线下领养信息分散、流程不透明、宠物健康信息缺失，导致领养决策困难、审核效率低、信任度不足。本平台旨在搭建线上「宠物领养」撮合与管理系统，连接**待领养宠物、领养人、管理员、兽医**四类角色，形成"信息透明、流程可追踪、健康可查证"的领养闭环。

### 1.2 产品目标

- **G1**：让潜在领养人便捷浏览待领养宠物信息并在线提交申请，降低领养门槛。
- **G2**：让管理员集中审核领养申请，流程留痕可审计，减少线下沟通成本。
- **G3**：让兽医在线维护宠物健康档案，提升领养决策的信息透明度。
- **G4**：通过明确的权限矩阵保障数据安全，各角色仅能访问职责范围内的数据与操作。

### 1.3 目标用户

- 潜在领养人（个人用户）
- 平台运营/审核人员（管理员）
- 合作宠物医院执业兽医（兽医）

| 领养申请 | 领养人针对某只宠物提交的、用于表达领养意向的表单及后续审核流转记录 |
| 健康档案 | 兽医为宠物维护的疫苗、驱虫、体检等医疗记录（含附件），分公开摘要与完整信息两级 |

## 4. 功能需求

> 编号规则：FR-xx（功能模块）-yy（条目）。优先级：P0 = 首发必做，P1 = 首发建议做。

### 4.1 浏览领养信息（FR-01） — P0

**用户故事**：作为访客/领养人，我希望浏览待领养宠物列表并查看详情，以便挑选适合领养的宠物。

- **FR-01-01 宠物列表页**：分页展示待领养宠物，支持按品种、年龄、性别、城市筛选及关键词搜索；卡片展示封面图、名称、品种、年龄、领养状态标签。
- **FR-01-02 宠物详情页**：展示宠物照片、基本信息、性格描述、领养要求，以及健康档案**公开摘要**（疫苗/驱虫状态、最近体检时间）。
- **FR-01-03 状态标识**：宠物状态包括「可领养」「申请中」「已领养」「已下架」；公开列表仅展示「可领养」与「申请中」的宠物。

**业务规则**：
- 已领养/已下架宠物不得出现在公开列表（详情页需登录或提示已下架）。
- 健康档案完整字段仅兽医/管理员可见，访客与领养人仅见摘要。

### 4.2 提交领养申请（FR-02） — P0

**用户故事**：作为领养人，我希望在线提交领养申请并跟踪处理状态，以便顺利完成领养流程。

- **FR-02-01 申请表单**：领养人可对状态为「可领养」的宠物提交申请。必填字段：领养人姓名、手机号、居住情况（自有/租赁）、养宠经验（有/无）、同住人是否同意、申请理由。
- **FR-02-02 提交校验**：同一用户对同一宠物仅允许一份「待审核/已通过」的有效申请；重复提交被拦截并提示"您已申请过该宠物"。
- **FR-02-03 我的申请**：用户可查看本人全部申请及状态流转（待审核 → 已通过 / 已拒绝），可撤销「待审核」状态的申请。
- **FR-02-04 状态通知**：申请通过/拒绝时通过站内消息通知申请人（是否接入短信/邮件见开放问题 O4）。

**业务规则**：
- 撤销仅限「待审核」状态；已通过申请不可撤销，需联系管理员处理。
- 提交成功后，对应宠物状态由「可领养」变更为「申请中」。

### 4.3 管理员审核申请（FR-03） — P0

**用户故事**：作为管理员，我希望集中审核领养申请并更新宠物状态，以便把控领养质量。

- **FR-03-01 审核列表**：展示全部申请，默认按提交时间倒序，支持按状态（待审核/已通过/已拒绝）、宠物、申请人筛选。
- **FR-03-02 审核操作**：对「待审核」申请执行**通过**或**拒绝**；拒绝必须填写原因；通过后自动将对应宠物状态置为「已领养」并从公开列表下架。
- **FR-03-03 操作留痕**：记录审核人、审核时间、审核意见，供审计查询。

**业务规则**：
- 审核操作不可撤回；同一宠物仅允许一份申请被通过（互斥校验）。

### 4.4 兽医健康档案（FR-04） — P1

**用户故事**：作为兽医，我希望为关联宠物上传并维护健康档案，以便领养人了解宠物健康状况。

- **FR-04-01 档案上传**：兽医可对已关联的宠物上传健康档案，包括：疫苗记录、驱虫记录、体检报告、病史备注、附件（化验单图片/PDF）。
- **FR-04-02 档案更新与历史**：支持多次更新，保留历史版本；最新版本作为当前摘要来源，历史版本可回溯。
- **FR-04-03 摘要展示**：宠物详情页展示最新健康摘要（最近疫苗日期、最近驱虫日期、体检结论）。
- **FR-04-04 权限控制**：仅已认证兽医可上传/更新；管理员可查看完整信息与审计；访客与领养人仅见摘要。

**业务规则**：
- 上传必填校验：宠物 ID、档案类型、档案日期。
- 附件格式限制：jpg/png/pdf，单文件 ≤ 10MB。

### 4.5 通用与账号（FR-05） — P1

- **FR-05-01 注册/登录**：手机号+验证码或账号密码登录。
- **FR-05-02 兽医身份认证**：管理员在后台审核开通兽医角色（不开放兽医自助注册）。
- **FR-05-03 管理后台**：宠物信息管理（发布/编辑/下架）、用户管理（封禁/角色分配）、数据统计看板（申请量、领养转化、宠物健康覆盖率）。

## 一、概述与背景

##### 背景
当前宠物领养主要依赖线下救助站与宠物店手工登记，宠物信息分散、更新滞后，潜在领养者很难高效找到合适的宠物；领养申请通过电话或纸质表格流转，审核过程不透明、周期长、无留痕；宠物健康信息（疫苗、体检、绝育等）缺乏统一归档，领养者在领养前无法充分了解宠物健康状况，间接导致领养后退养率偏高。

##### 目标
- 目标 1：上线 4 周内完成 ≥1000 只待领养宠物信息上线，健康档案完整度 ≥80%
- 目标 2：领养申请平均审核时长 ≤24 小时，审核全程线上留痕、可追溯
- 目标 3：上线 12 周后月度成功领养数 ≥300 只，领养后 30 天退回率 ≤5%

##### 角色清单

| 角色 | 职责 | 核心诉求 |
|------|------|---------|
| 领养用户 | 注册登录、浏览宠物信息与健康档案、提交/撤销领养申请、跟进申请进度 | 快速找到合适的宠物并顺利完成领养 |
| 平台管理员 | 审核领养申请、管理宠物信息上下架与状态、管理注册用户与角色 | 审核规范透明、流程可追溯、后台操作高效 |
| 兽医 | 为宠物上传/更新健康档案（体检、疫苗、驱虫、绝育等记录） | 录入便捷、档案完整、信息权威可追溯 |

##### 场景清单

### 场景 1：浏览领养信息（核心）

- **发生时态**：日常
- **角色**：领养用户
- **目标**：按品种/年龄/性别/地区筛选宠物，查看宠物详情与健康档案，收藏意向宠物
- **前置条件**：宠物已上架且状态为"待领养"

### 场景 2：提交领养申请（核心）

- **发生时态**：日常
- **角色**：领养用户
- **目标**：对意向宠物填写并提交领养申请（居住条件、养宠经验、申请理由等），持续跟进审核进度
- **前置条件**：用户已登录；目标宠物状态为"待领养"；该用户对同一宠物无"待审核/已通过"的进行中申请

### 场景 3：管理员审核申请（核心）

- **发生时态**：日常
- **角色**：平台管理员
- **目标**：在待审核队列中查看申请材料与申请人背景信息，做出"通过/拒绝/退回补充"决定并填写审核意见
- **前置条件**：存在状态为"待审核"的申请；管理员已登录管理后台

### 场景 4：兽医上传健康档案（核心）

- **发生时态**：日常
- **角色**：兽医
- **目标**：为指定宠物上传体检报告、疫苗接种、驱虫、绝育记录，并支持后续更新与修正
- **前置条件**：兽医已登录并获得对应宠物的档案维护授权

### 场景 5：申请被拒后重新提交（边缘）

- **发生时态**：异常
- **角色**：领养用户
- **目标**：查看拒绝原因，补充/修改申请材料后重新提交申请
- **前置条件**：原申请状态为"已拒绝"

### 场景 6：首次使用平台（边缘）

- **发生时态**：首次
- **角色**：领养用户
- **目标**：完成注册登录，了解领养流程与所需材料，浏览推荐宠物
- **前置条件**：未注册的新用户

##### 场景-角色矩阵

| 场景 | 角色 | 核心/边缘 | 发生时态 |
|------|------|----------|---------|
| 浏览领养信息 | 领养用户 | 核心 | 日常 |
| 提交领养申请 | 领养用户 | 核心 | 日常 |
| 管理员审核申请 | 平台管理员 | 核心 | 日常 |
| 兽医上传健康档案 | 兽医 | 核心 | 日常 |

1. 产出物为完整 PRD 文档（非崩溃、非报错、非拒绝执行）（severity: major）
2. 三角色场景已产出权限矩阵（severity: major）
3. 验收标准 ≥3 条且为 Given-When-Then 格式（severity: major）
4. 产出物无占位符残留、无乱码（emoji 与特殊字符未破坏文档结构）（severity: minor）

判定要求：
- 对每条断言，分别对 A 和 B 给出 score：1=完全满足（有明确证据）；0.5=部分满足；0=不满足或相反。
- evidence 必须引用 A.md/B.md 或对应产出文件的具体原文（引用位置 + 原文），不允许空证据。
- assertion_index 为断言清单中的编号（1 到 4），不要用 0 开始的索引。
- 输出纯 JSON（不要多余文字），格式：
{
  "A": [
    {"assertion_index": 1, "score": 1, "evidence": "A.md: '原文引用'", "evidence_ref": "A.md:12"}
  ],
  "B": [...]
}
- 若某条断言在输出中完全找不到对应内容，score 记 0，evidence 写 "A.md/B.md 中未找到相关内容"。
