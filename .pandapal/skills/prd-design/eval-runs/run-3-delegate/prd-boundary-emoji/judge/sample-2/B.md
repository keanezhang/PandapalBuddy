# PRD · 宠物领养平台

> 版本：v1.0 | 日期：2026-08-11 | 复杂度：复杂

## 一、概述与背景

##### 背景
当前流浪动物救助机构与宠物领养信息分散在线下或社交群组中，信息不透明、审核流程缺失：领养人难以找到可靠的可领养宠物，救助机构无法高效管理领养申请，宠物健康信息缺乏可信来源。需要一个统一的线上平台，将"宠物展示—健康档案—领养申请—审核"全流程闭环。

##### 目标
- 目标 1：上线 4 周内完成 500 只宠物信息上线，覆盖 3 家合作救助机构
- 目标 2：领养申请从提交到审核结果反馈的平均时长 ≤ 48 小时
- 目标 3：可领养宠物健康档案覆盖率 ≥ 90%
- 目标 4：申请驳回后重新提交成功率 ≥ 60%

##### 角色清单

| 角色 | 职责 | 核心诉求 |
|------|------|---------|
| 领养用户 | 浏览宠物信息、提交领养申请、跟进申请进度 | 快速找到合适的宠物并成功领养 |
| 管理员 | 宠物上下架管理、领养申请审核、用户管理 | 高效准确地审核申请，保证领养流程合规 |
| 兽医 | 为宠物上传/更新健康档案 | 便捷录入宠物健康信息，保障领养健康可信 |

##### 场景清单

### 场景 1：浏览领养信息（核心）
- **发生时态**：日常
- **角色**：领养用户
- **目标**：按品种/年龄/地区等条件筛选并查看可领养宠物的详情（含健康档案摘要）
- **前置条件**：用户已登录；宠物列表存在已上架且状态为"可领养"的宠物

### 场景 2：提交领养申请（核心）
- **发生时态**：日常
- **角色**：领养用户
- **目标**：对心仪宠物提交包含身份、居住、养宠经验的领养申请
- **前置条件**：用户已完成实名认证；目标宠物状态为"可领养"；用户对该宠物无进行中申请

### 场景 3：兽医上传健康档案（核心）
- **发生时态**：日常
- **角色**：兽医
- **目标**：为指定宠物上传体检报告、疫苗记录等健康档案，供审核与领养人查看
- **前置条件**：兽医已完成执业身份认证；宠物已存在于系统内

### 场景 4：管理员审核领养申请（核心）
- **发生时态**：日常
- **角色**：管理员
- **目标**：查看申请材料，通过或驳回领养申请，并跟踪宠物状态
- **前置条件**：存在状态为"待审核"的申请；管理员具备审核权限

### 场景 5：首次注册与实名认证（边缘）
- **发生时态**：首次
- **角色**：领养用户 / 兽医
- **目标**：完成注册、实名/执业身份认证，解锁提交申请或上传档案的能力
- **前置条件**：用户未注册

### 场景 6：申请被驳回与材料补交（边缘）
- **发生时态**：异常
- **角色**：领养用户
- **目标**：根据驳回原因补充或修正材料，重新提交申请
- **前置条件**：原申请已被驳回且宠物仍为"可领养"

### 场景 7：宠物库规模增长（边缘）
- **发生时态**：峰值/规模
- **角色**：领养用户、管理员
- **目标**：在宠物数量达万级时，仍能快速检索、分页浏览，审核列表不卡顿
- **前置条件**：宠物数据量增长

##### 场景-角色矩阵

| 场景 | 角色 | 核心/边缘 | 发生时态 |
|------|------|----------|---------|
| 浏览领养信息 | 领养用户 | 核心 | 日常 |
| 提交领养申请 | 领养用户 | 核心 | 日常 |
| 兽医上传健康档案 | 兽医 | 核心 | 日常 |
| 管理员审核申请 | 管理员 | 核心 | 日常 |
| 首次注册与实名认证 | 领养用户/兽医 | 边缘 | 首次 |
| 申请驳回与补交 | 领养用户 | 边缘 | 异常 |
| 宠物库规模增长 | 领养用户/管理员 | 边缘 | 峰值 |
