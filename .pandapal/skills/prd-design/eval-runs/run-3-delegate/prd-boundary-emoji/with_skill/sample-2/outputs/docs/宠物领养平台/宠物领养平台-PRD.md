# PRD · 宠物领养平台

> 版本：v1.0 | 日期：2026-08-11 | 复杂度：复杂

---

## 一、概述与背景

##### 背景
当前流浪动物救助机构与宠物领养信息分散在线下或社交群组中，信息不透明、审核流程缺失：领养人难以找到可靠的可领养宠物，救助机构无法高效管理领养申请，宠物健康信息缺乏可信来源。需要一个统一的线上平台，将"宠物展示—健康档案—领养申请—审核"全流程闭环。

##### 目标
- 目标 1：上线 4 周内完成 500 只宠物信息上线，覆盖 3 家合作救助机构
- 目标 2：领养申请从提交到审核结果反馈的平均时长 ≤ 48 小时
- 目标 3：可领养宠物健康档案覆盖率 ≥ 90%
- 目标 4：申请驳回后重新提交成功率 ≥ 60%

##### 角色清单

| 角色 | 职责 | 核心诉求 |
|------|------|---------|
| 领养用户 | 浏览宠物信息、提交领养申请、跟进申请进度 | 快速找到合适的宠物并成功领养 |
| 管理员 | 宠物上下架管理、领养申请审核、用户管理 | 高效准确地审核申请，保证领养流程合规 |
| 兽医 | 为宠物上传/更新健康档案 | 便捷录入宠物健康信息，保障领养健康可信 |

##### 场景清单

### 场景 1：浏览领养信息（核心）
- **发生时态**：日常
- **角色**：领养用户
- **目标**：按品种/年龄/地区等条件筛选并查看可领养宠物的详情（含健康档案摘要）
- **前置条件**：用户已登录；宠物列表存在已上架且状态为"可领养"的宠物

### 场景 2：提交领养申请（核心）
- **发生时态**：日常
- **角色**：领养用户
- **目标**：对心仪宠物提交包含身份、居住、养宠经验的领养申请
- **前置条件**：用户已完成实名认证；目标宠物状态为"可领养"；用户对该宠物无进行中申请

### 场景 3：兽医上传健康档案（核心）
- **发生时态**：日常
- **角色**：兽医
- **目标**：为指定宠物上传体检报告、疫苗记录等健康档案，供审核与领养人查看
- **前置条件**：兽医已完成执业身份认证；宠物已存在于系统内

### 场景 4：管理员审核领养申请（核心）
- **发生时态**：日常
- **角色**：管理员
- **目标**：查看申请材料，通过或驳回领养申请，并跟踪宠物状态
- **前置条件**：存在状态为"待审核"的申请；管理员具备审核权限

### 场景 5：首次注册与实名认证（边缘）
- **发生时态**：首次
- **角色**：领养用户 / 兽医
- **目标**：完成注册、实名/执业身份认证，解锁提交申请或上传档案的能力
- **前置条件**：用户未注册

### 场景 6：申请被驳回与材料补交（边缘）
- **发生时态**：异常
- **角色**：领养用户
- **目标**：根据驳回原因补充或修正材料，重新提交申请
- **前置条件**：原申请已被驳回且宠物仍为"可领养"

### 场景 7：宠物库规模增长（边缘）
- **发生时态**：峰值/规模
- **角色**：领养用户、管理员
- **目标**：在宠物数量达万级时，仍能快速检索、分页浏览，审核列表不卡顿
- **前置条件**：宠物数据量增长

##### 场景-角色矩阵

| 场景 | 角色 | 核心/边缘 | 发生时态 |
|------|------|----------|---------|
| 浏览领养信息 | 领养用户 | 核心 | 日常 |
| 提交领养申请 | 领养用户 | 核心 | 日常 |
| 兽医上传健康档案 | 兽医 | 核心 | 日常 |
| 管理员审核申请 | 管理员 | 核心 | 日常 |
| 首次注册与实名认证 | 领养用户/兽医 | 边缘 | 首次 |
| 申请驳回与补交 | 领养用户 | 边缘 | 异常 |
| 宠物库规模增长 | 领养用户/管理员 | 边缘 | 峰值 |

### 3.2 业务链路

#### 核心链路 1：领养申请流转链路

```text
┌────────────┐   提交申请     ┌────────────┐   待审核申请    ┌────────────┐
│  领养用户   │ ────────────► │  申请模块    │ ────────────► │  审核模块    │
└────────────┘               └─────┬──────┘                └─────┬──────┘
                                   │                              │
                                   │ <异常> 校验失败               │ 通过/驳回
                                   ▼                              ▼
                             ┌────────────┐                ┌────────────┐
                             │ 表单校验拦截 │                │ 结果通知用户 │
                             └────────────┘                └────────────┘
```

**链路说明**：领养用户在宠物详情页提交申请 → 申请模块做唯一性/格式校验（异常则拦截并提示）→ 生成"待审核"申请 → 管理员在审核模块通过/驳回 → 结果通知用户；通过后同步变更宠物状态为"已领养"。

#### 核心链路 2：健康档案上传与消费链路

```text
┌────────────┐  体检/疫苗数据  ┌────────────┐   关联宠物     ┌────────────┐
│    兽医     │ ────────────► │  档案模块    │ ────────────► │  宠物档案    │
└────────────┘                └─────┬──────┘                └─────┬──────┘
                                    │                              │
                                    │ <异常> 校验失败               │ 展示
                                    ▼                              ▼
                              ┌────────────┐                ┌────────────┐
                              │ 档案校验拦截 │                │ 详情页聚合  │
                              └────────────┘                └────────────┘
```

**链路说明**：兽医在健康档案工作台录入体检/疫苗数据 → 档案模块校验（日期、附件格式、必填项）→ 关联到指定宠物 → 宠物详情页聚合展示档案摘要，管理员审核时可见附件。

### 3.3 状态流转

#### 领养申请状态机

```text
      ┌──────────┐   提交申请    ┌──────────┐   审核通过    ┌──────────┐
 ────►│  待审核   │ ───────────►│  已通过   │ ───────────►│  已完成   │
      └────┬─────┘              └──────────┘              └──────────┘
           │ 审核驳回
           ▼
      ┌──────────┐
      │  已驳回   │
      └────┬─────┘
           │ 补充材料后重新提交
           ▼
      ┌──────────┐
      │  待审核   │（回到初始态）
      └──────────┘
```

##### 状态定义

| 状态 | 含义 | 允许的下一状态 | 触发迁移的动作/条件 |
|------|------|---------------|-------------------|
| 待审核 | 申请已提交，等待管理员审核 | 已通过, 已驳回 | 管理员审核通过 / 审核驳回 |
| 已通过 | 审核通过，进入领养安排 | 已完成 | 管理员确认领养交接完成 |
| 已驳回 | 材料不符合要求被驳回 | 待审核 | 用户补充材料重新提交（宠物仍可领养） |
| 已完成 | 领养交接完成，流程结束 | — | 管理员确认线下交接完成 |

##### 非法迁移

| 从 | 到 | 拒绝原因 | 系统行为 |
|----|-----|---------|---------|
| 已通过 | 已驳回 | 已通过的申请不允许再驳回 | 拒绝操作，提示联系客服线下处理 |
| 已完成 | 任何状态 | 流程已结束不可回退 | 拒绝操作并留痕 |

#### 宠物状态机

```text
      ┌──────────┐   管理员上架   ┌──────────┐   申请审核通过 ┌──────────┐
 ────►│  待上架   │ ───────────► │  可领养   │ ───────────► │  已领养   │
      └──────────┘               └────┬─────┘               └──────────┘
                                      │ 管理员下架
                                      ▼
                                ┌──────────┐
                                │  已下架   │
                                └──────────┘
```

##### 状态定义

| 状态 | 含义 | 允许的下一状态 | 触发迁移的动作/条件 |
|------|------|---------------|-------------------|
| 待上架 | 救助机构录入但未公开展示 | 可领养 | 管理员审核后上架 |
| 可领养 | 公开展示，可被申请 | 已领养, 已下架 | 申请审核通过 / 管理员下架 |
| 已领养 | 已被成功领养 | — | 管理员确认领养完成 |
| 已下架 | 不再公开展示 | 可领养 | 管理员重新上架 |

##### 非法迁移

| 从 | 到 | 拒绝原因 | 系统行为 |
|----|-----|---------|---------|
| 已领养 | 可领养 | 领养完成后不可回退 | 拒绝操作，提示联系客服 |
| 待上架 | 已领养 | 未上架不可被领养 | 拒绝操作 |

### 3.5 流转规则

| 规则 | 触发条件 | 行为 |
|------|---------|------|
| 唯一有效申请 | 同一用户对同一宠物存在"待审核/已通过"申请 | 拒绝再次提交，提示已有进行中申请 |
| 宠物状态锁定 | 宠物进入"已领养" | 禁止新申请提交，列表不再展示 |
| 驳回后重提 | 申请被驳回且宠物仍为"可领养" | 允许用户修改材料重新提交，生成新申请 |
| 自动驳回并发申请 | 某申请审核通过、宠物变"已领养" | 该宠物其余"待审核"申请自动驳回 |
| 档案可见性 | 宠物"可领养"且存在档案 | 详情页展示档案摘要，附件需登录后查看 |

### 3.6 缺口标注

- 🟡 **当前状态**：健康档案字段级规范（疫苗批号、抗体滴度等）未定义；多救助机构之间的数据权限隔离规则待确认。
- 🟢 **需补充的内容**：疫苗记录结构化明细、多机构管理员的机构级数据范围、线下领养交接的确认方式。
- 🔵 **影响范围**：健康档案模块、后台宠物管理、数据字典扩展、审核模块。

## 四、需求详细描述

### 4.1 背景与目标

从第一章概述提取：平台将"宠物展示—健康档案—领养申请—审核"闭环线上化，三个角色（领养用户、管理员、兽医）各司其职。

##### 本期范围
- ✅ 包含：宠物信息浏览与检索、领养申请提交与审核、健康档案上传与查看、用户角色与权限管理、审核结果通知
- ❌ 不包含：线下领养交接流程、支付/押金、多救助机构独立门户、原生移动端 App（本期仅 Web/H5）、数据埋点方案设计

### 4.2 用户故事

#### Story 1：浏览可领养宠物（P0）
- **作为** 领养用户
- **我希望** 按品种、年龄、地区筛选并查看可领养宠物的详情与健康档案摘要
- **以便** 快速判断哪只宠物适合自己
- **没有这个功能，用户会怎样？** 只能依赖线下或社交群组信息，无法高效决策
- **优先级**：P0

#### Story 2：提交领养申请（P0）
- **作为** 领养用户
- **我希望** 在宠物详情页填写身份、居住与养宠经验信息并提交领养申请
- **以便** 救助机构评估我是否适合领养该宠物
- **没有这个功能，用户会怎样？** 领养流程无法线上化，闭环不成立
- **优先级**：P0

#### Story 3：审核领养申请（P0）
- **作为** 管理员
- **我希望** 查看待审核申请的完整材料并作出通过/驳回决策（驳回需填写原因）
- **以便** 筛选合适的领养人、保障宠物福利
- **没有这个功能，用户会怎样？** 申请无人处理，流程停滞
- **优先级**：P0

#### Story 4：上传健康档案（P0）
- **作为** 兽医
- **我希望** 为指定宠物上传疫苗、体检、治疗等健康档案
- **以便** 管理员审核和领养人决策时有可信的健康依据
- **没有这个功能，用户会怎样？** 健康信息缺失，领养风险无法评估
- **优先级**：P0

#### Story 5：跟踪申请进度（P1）
- **作为** 领养用户
- **我希望** 在我的申请页查看每个申请的状态与审核结果
- **以便** 及时了解进展、必要时补充材料
- **没有这个功能，用户会怎样？** 只能电话询问，体验差
- **优先级**：P1

#### Story 6：驳回后补充材料重新提交（P1）
- **作为** 领养用户
- **我希望** 根据驳回原因修改材料后重新提交申请
- **以便** 修正问题、完成领养
- **没有这个功能，用户会怎样？** 一次失败即流程终止，转化率低
- **优先级**：P1

#### Story 7：审核结果通知（P2）
- **作为** 领养用户
- **我希望** 申请通过或驳回时收到站内信/短信通知
- **以便** 不用反复刷新页面
- **没有这个功能，用户会怎样？** 需要主动查询，时效性差
- **优先级**：P2

### 4.3 功能清单

#### 4.3.2 领养申请提交（领养申请管理）

##### 异常分支

| 异常类型 | 触发条件 | 系统行为 | 用户提示 |
|---------|---------|---------|---------|
| 网络异常 | 提交超时/断网 | 保留表单内容并提示重试 | Toast「提交失败，请重试」 |
| 数据异常 | 必填字段缺失/格式错误 | 前端校验拦截，标红错误字段 | 「请完善 X 字段」 |
| 权限异常 | 未实名认证用户提交 | 拦截并引导实名认证 | 「请先完成实名认证」 |

- 规则 1：未完成实名认证的用户不可提交申请
- 规则 2：同一用户对同一宠物最多有 1 条非终态（待审核/已通过）申请
- 规则 3：申请提交后 48 小时内未审核，自动提醒管理员

##### 全局状态

#### 4.3.3 申请审核（领养申请管理·管理员）

| **规则** | 通过后宠物状态变更为"已领养"并锁定，该宠物其余待审核申请自动驳回；驳回必须填写原因（≤200 字） |

| 异常类型 | 触发条件 | 系统行为 | 用户提示 |

| 业务异常 | 宠物已领养但申请仍待审核 | 禁止通过 | 「该宠物已领养，无法通过此申请」 |

##### 业务规则
- 规则 1：通过操作不可撤销（误操作走客服线下处理）
- 规则 2：驳回原因必填且对用户可见
- 规则 3：宠物"已领养"后，该宠物所有"待审核"申请自动驳回

##### 全局状态

| 状态 | 呈现方式 |
|------|---------|
| 加载态 | 审核操作按钮 loading |
| 空状态 | 无待审核申请时展示空状态插画「今日申请已处理完」 |

| 确认操作 | 通过/驳回均需二次确认弹窗 |

#### 4.3.4 健康档案管理（健康档案管理·兽医）

##### 1. 上传健康档案

| 四步 | 说明 |
|------|------|
| **触发** | 兽医进入健康档案工作台，按名称/ID 检索宠物，点击「新增档案」 |
| **反馈** | 弹出档案表单：类型（疫苗/体检/治疗）、日期、结论摘要、附件上传 |
| **规则** | 记录日期不可晚于今天；附件 ≤5 个、单文件 ≤10MB、支持 jpg/pdf；疫苗类型需填写疫苗名称与下次接种日期（可选） |
| **循环** | 保存成功后清空表单，可继续为同一宠物添加档案 |

##### 2. 维护与查看档案

| 四步 | 说明 |
|------|------|
| **触发** | 兽医在宠物档案页查看历史档案，点击「编辑」修改摘要或补充附件 |
| **反馈** | 编辑表单回填原数据，保存后更新档案并记录更新时间 |
| **规则** | 仅档案录入兽医本人可编辑；已关联"已领养"宠物的档案只读；修改留痕（记录 updated_at 与修改人） |
| **循环** | 档案列表按记录日期倒序，可反复维护 |

##### 异常分支

| 异常类型 | 触发条件 | 系统行为 | 用户提示 |
|---------|---------|---------|---------|
| 网络异常 | 上传附件中断 | 断点续传/重试 | 「上传失败，请重试」 |
| 数据异常 | 附件格式/大小不符 | 前端拦截 | 「仅支持 jpg/pdf，单文件不超过 10MB」 |
| 权限异常 | 非兽医角色访问工作台 | 拦截 | 403 无权限页面 |
| 并发冲突 | 两名兽医同时编辑同一档案 | 乐观锁，后保存者提示刷新 | 「档案已被他人更新」 |
| 业务异常 | 宠物不存在/已删除 | 检索不到或提示 | 「未找到该宠物，请核对编号」 |

##### 业务规则
- 规则 1：兽医需完成执业身份认证后方可上传
- 规则 2：疫苗记录至少包含疫苗名称与接种日期

## 五、验收标准

### AC-01：用户成功浏览并筛选宠物（正常场景）
- **Given**：系统存在 ≥2 只"可领养"状态的宠物，用户已登录
- **When**：用户在列表页选择"猫咪 + 1 岁以内"筛选并点击搜索，点击第一只宠物进入详情
- **Then**：列表展示符合条件的结果且按上架时间倒序；详情页展示宠物基本信息与健康档案摘要区块（无档案时展示占位说明）

### AC-02：用户提交领养申请成功（正常场景）
- **Given**：用户已完成实名认证，目标宠物为"可领养"，该用户对同一宠物无进行中申请
- **When**：用户填写完整申请表单并勾选领养须知后点击「提交申请」
- **Then**：申请状态变为"待审核"，跳转「我的申请」页并提示「申请已提交」；管理员审核列表出现该申请；同一用户对同一宠物无法再次提交

### AC-03：管理员通过申请后宠物锁定（正常场景）
- **Given**：存在一条"待审核"申请，宠物状态为"可领养"
- **When**：管理员点击「通过」并确认
- **Then**：申请状态变为"已通过"并通知用户；宠物状态变为"已领养"，列表不再展示；该宠物其他"待审核"申请自动驳回

### AC-04：申请被驳回后用户可补充材料重新提交（异常场景）
- **Given**：用户申请被驳回（驳回原因已填写），宠物仍为"可领养"
- **When**：用户在「我的申请」查看驳回原因，修改材料后重新提交
- **Then**：生成一条新申请且状态为"待审核"；驳回原因对用户可见；旧申请保留为"已驳回"记录

### AC-05：无权限用户访问审核功能被拦截（权限异常场景）
- **Given**：普通领养用户已登录，手动输入管理员审核列表地址
- **When**：用户尝试访问申请审核页面
- **Then**：返回 403 无权限页面，不展示任何申请数据

### AC-06：未实名用户提交申请被引导（边界场景）
- **Given**：用户已登录但未完成实名认证
- **When**：用户点击「申请领养」并尝试提交
- **Then**：系统拦截提交并弹出实名认证引导，完成认证后可继续原申请流程

## 六、数据指标

### 6.1 核心成功指标（North Star）
- **指标名**：成功领养数（月度）
- **计算方式**：每月申请状态变为"已完成"的申请数量
- **目标值**：上线第 4 周起，月成功领养 ≥ 100 只
- **数据来源**：领养申请状态表

### 6.2 过程指标

| 指标名 | 计算方式 | 基准值 | 目标值 | 数据来源 |

| 申请提交数 | 每月新提交申请数 | 0 | ≥300 | 申请状态表 |
