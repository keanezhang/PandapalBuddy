# PRD · 宠物领养平台

> 版本：v1.0 | 日期：2026-02-06（假设值，见文末说明） | 复杂度：复杂

## 一、概述与背景

##### 背景
当前宠物领养主要依赖线下救助站与宠物店手工登记，宠物信息分散、更新滞后，潜在领养者很难高效找到合适的宠物；领养申请通过电话或纸质表格流转，审核过程不透明、周期长、无留痕；宠物健康信息（疫苗、体检、绝育等）缺乏统一归档，领养者在领养前无法充分了解宠物健康状况，间接导致领养后退养率偏高。

##### 目标
- 目标 1：上线 4 周内完成 ≥1000 只待领养宠物信息上线，健康档案完整度 ≥80%
- 目标 2：领养申请平均审核时长 ≤24 小时，审核全程线上留痕、可追溯
- 目标 3：上线 12 周后月度成功领养数 ≥300 只，领养后 30 天退回率 ≤5%

##### 角色清单

| 角色 | 职责 | 核心诉求 |
|------|------|---------|
| 领养用户 | 注册登录、浏览宠物信息与健康档案、提交/撤销领养申请、跟进申请进度 | 快速找到合适的宠物并顺利完成领养 |
| 平台管理员 | 审核领养申请、管理宠物信息上下架与状态、管理注册用户与角色 | 审核规范透明、流程可追溯、后台操作高效 |
| 兽医 | 为宠物上传/更新健康档案（体检、疫苗、驱虫、绝育等记录） | 录入便捷、档案完整、信息权威可追溯 |

##### 场景清单

### 场景 1：浏览领养信息（核心）

- **发生时态**：日常
- **角色**：领养用户
- **目标**：按品种/年龄/性别/地区筛选宠物，查看宠物详情与健康档案，收藏意向宠物
- **前置条件**：宠物已上架且状态为"待领养"

### 场景 2：提交领养申请（核心）

- **发生时态**：日常
- **角色**：领养用户
- **目标**：对意向宠物填写并提交领养申请（居住条件、养宠经验、申请理由等），持续跟进审核进度
- **前置条件**：用户已登录；目标宠物状态为"待领养"；该用户对同一宠物无"待审核/已通过"的进行中申请

### 场景 3：管理员审核申请（核心）

- **发生时态**：日常
- **角色**：平台管理员
- **目标**：在待审核队列中查看申请材料与申请人背景信息，做出"通过/拒绝/退回补充"决定并填写审核意见
- **前置条件**：存在状态为"待审核"的申请；管理员已登录管理后台

### 场景 4：兽医上传健康档案（核心）

- **发生时态**：日常
- **角色**：兽医
- **目标**：为指定宠物上传体检报告、疫苗接种、驱虫、绝育记录，并支持后续更新与修正
- **前置条件**：兽医已登录并获得对应宠物的档案维护授权

### 场景 5：申请被拒后重新提交（边缘）

- **发生时态**：异常
- **角色**：领养用户
- **目标**：查看拒绝原因，补充/修改申请材料后重新提交申请
- **前置条件**：原申请状态为"已拒绝"

### 场景 6：首次使用平台（边缘）

- **发生时态**：首次
- **角色**：领养用户
- **目标**：完成注册登录，了解领养流程与所需材料，浏览推荐宠物
- **前置条件**：未注册的新用户

##### 场景-角色矩阵

| 场景 | 角色 | 核心/边缘 | 发生时态 |
|------|------|----------|---------|
| 浏览领养信息 | 领养用户 | 核心 | 日常 |
| 提交领养申请 | 领养用户 | 核心 | 日常 |
| 管理员审核申请 | 平台管理员 | 核心 | 日常 |
| 兽医上传健康档案 | 兽医 | 核心 | 日常 |
| 申请被拒后重新提交 | 领养用户 | 边缘 | 异常 |
| 首次使用平台 | 领养用户 | 边缘 | 首次 |

### 3.3 状态流转

#### 领养申请 状态机

```text
      ┌──────────┐   提交    ┌──────────┐   审核通过   ┌──────────┐   确认领养   ┌──────────┐
 ────►│   草稿    │ ────────► │  待审核   │ ──────────► │  已通过   │ ──────────► │  已完成   │
      └──────────┘           └────┬─────┘              └──────────┘            └──────────┘
                                   │
                    ┌──────────────┼──────────────┐
                    │ 审核拒绝      │ 审核退回      │ 用户撤销
                    ▼              ▼              ▼
              ┌──────────┐   ┌──────────┐   ┌──────────┐
              │  已拒绝   │   │  已退回   │   │  已撤销   │
              └────┬─────┘   └────┬─────┘   └──────────┘
                   │ 重新提交      │ 修改后重提
                   ▼              ▼
              ┌──────────┐   ┌──────────┐
              │  待审核   │   │  待审核   │
              └──────────┘   └──────────┘
```

##### 状态定义

| 状态 | 含义 | 允许的下一状态 | 触发迁移的动作/条件 |
|------|------|---------------|-------------------|
| 草稿 | 用户已填写部分内容但未提交 | 待审核 | 用户点击"提交申请" |
| 待审核 | 申请已提交，等待管理员审核 | 已通过、已拒绝、已退回、已撤销 | 管理员审核；用户撤销 |
| 已通过 | 审核通过，进入领养确认阶段 | 已完成 | 管理员确认完成领养 |
| 已拒绝 | 审核不通过 | 待审核 | 用户修改材料后重新提交 |
| 已退回 | 材料不齐被退回 | 待审核 | 用户补充材料后重新提交 |
| 已撤销 | 用户主动取消 | — | 用户撤销申请 |
| 已完成 | 领养流程完结 | — | 管理员确认领养完成 |

##### 非法迁移

| 从 | 到 | 拒绝原因 | 系统行为 |
|----|-----|---------|---------|
| 草稿 | 已通过 | 未提交不可审核 | 拒绝：审核列表不可见草稿 |
| 已拒绝 | 已完成 | 未通过不可完成 | 拒绝：仅已通过可确认完成 |
| 已撤销 | 待审核 | 撤销不可逆 | 拒绝：需重新发起申请 |
| 已完成 | 任意状态 | 流程已终结 | 拒绝：状态锁定 |

#### 宠物信息 状态机

```text
      ┌──────────┐  管理员上架  ┌──────────┐  有申请审核中  ┌──────────┐  审核通过  ┌──────────┐
 ────►│   草稿     │ ─────────► │  待领养   │ ────────────► │  申请中   │ ─────────► │  已领养   │
      └──────────┘             └────┬─────┘               └──────────┘           └──────────┘
                                    │ 管理员下架
                                    ▼
                              ┌──────────┐
                              │  已下架   │
                              └──────────┘
```

##### 宠物状态定义

| 状态 | 含义 | 允许的下一状态 | 触发迁移 |
|------|------|---------------|---------|
| 草稿 | 信息录入未上架 | 待领养、已下架 | 管理员上架 |
| 待领养 | 对外展示可申请 | 申请中、已下架 | 用户提交申请；管理员下架 |
| 申请中 | 存在进行中的申请 | 待领养、已领养、已下架 | 申请被拒后释放；审核通过；管理员下架 |
| 已领养 | 领养完成 | — | 审核通过并确认领养 |
| 已下架 | 不再对外展示 | 待领养 | 管理员重新上架 |

### 3.5 流转规则

| 规则 | 触发条件 | 行为 |
|------|---------|------|
| 申请互斥 | 同一用户对同一宠物存在 pending/approved 申请 | 禁止重复提交，提示"已有进行中的申请" |
| 宠物单线程 | 宠物存在 pending 申请时 | 详情页申请按钮置灰，提示"该宠物正在审核中" |
| 档案同步 | 兽医上传/更新档案后 | 宠物详情页 health_status 按最新档案刷新 |
| 审核超时提醒 | 申请 pending 超过 24 小时 | 向管理员推送催办提醒 |
| 状态锁定 | 申请 completed / revoked | 禁止再次变更，仅可查看 |

### 3.6 缺口标注

- 🟡 **当前状态**：申请审核所需的具体材料清单（收入证明/住房证明等）尚未确定 [待确认]，本期以居住条件、养宠经验、申请理由三类文本材料为准
- 🟢 **需补充的内容**：审核材料字段清单与是否要求附件上传，需运营侧确认
- 🔵 **影响范围**：领养申请表单页字段、审核详情页展示、数据字典 application 表
- 🟡 **当前状态**：通知渠道（短信/站内信/邮件）未定 [待确认]，本期先以站内信 + 列表状态刷新为主
- 🟢 **需补充的内容**：是否接入短信网关
- 🔵 **影响范围**：用户通知体验、管理员催办提醒

## 四、需求详细描述

### 4.1 背景与目标

核心诉求：打通"宠物信息 → 领养申请 → 审核 → 健康档案"的线上闭环，让领养者找得到、看得清、申得了，让管理员审得规范、留痕可查，让兽医录得便捷、档案完整。

##### 本期范围

- ✅ 包含：用户端浏览/申请/进度查询；管理后台审核/宠物管理；兽医工作台档案上传/更新；账号与角色权限
- ❌ 不包含：领养费用线上支付、宠物用品商城、领养后回访提醒（短信）、多救助机构入驻流程

### 4.2 用户故事

#### Story 1：浏览并筛选宠物
- **作为** 领养用户
- **我希望** 按品种、年龄、地区筛选待领养宠物，并查看详情与健康档案
- **以便** 快速找到适合自己的宠物
- **没有这个功能，用户会怎样？** 只能逐条翻阅，效率低，易错过合适宠物
- **优先级**：P0

#### Story 2：提交领养申请
- **作为** 领养用户
- **我希望** 对意向宠物在线填写并提交领养申请
- **以便** 不用线下跑机构，随时完成申请
- **没有这个功能，用户会怎样？** 领养流程断裂，用户只能电话/线下申请
- **优先级**：P0

#### Story 3：跟进进度与撤销申请
- **作为** 领养用户
- **我希望** 在"我的申请"中查看审核进度，必要时撤销申请
- **以便** 掌握流程状态、及时调整计划
- **没有这个功能，用户会怎样？** 申请状态不可见，体验焦虑
- **优先级**：P1

#### Story 4：审核领养申请
- **作为** 平台管理员
- **我希望** 在后台查看待审核申请与申请人材料，做出通过/拒绝/退回决定并填写意见
- **以便** 审核规范透明、全程留痕
- **没有这个功能，用户会怎样？** 申请无人处理，流程停滞
- **优先级**：P0

#### Story 5：宠物信息管理
- **作为** 平台管理员
- **我希望** 对宠物信息进行上架/下架与领养状态维护
- **以便** 保证前台展示数据准确
- **没有这个功能，用户会怎样？** 已领养宠物仍展示，用户白跑一趟
- **优先级**：P1

#### Story 6：上传健康档案
- **作为** 兽医
- **我希望** 为指定宠物上传体检、疫苗、驱虫、绝育记录及附件
- **以便** 领养者在领养前了解宠物健康状况
- **没有这个功能，用户会怎样？** 健康信息缺失，用户不敢领养，退养风险高
- **优先级**：P0

#### Story 7：更新健康档案
- **作为** 兽医
- **我希望** 对已上传档案进行更新/修正并保留变更记录
- **以便** 保证档案信息始终准确
- **没有这个功能，用户会怎样？** 档案过期或错误无法修正，误导领养决策
- **优先级**：P1

#### Story 8：首次使用引导
- **作为** 领养用户
- **我希望** 首次进入时了解领养流程与所需材料
- **以便** 明确申请门槛、减少无效申请
- **没有这个功能，用户会怎样？** 材料不齐导致申请被退回，体验受挫
- **优先级**：P2

### 4.3 功能清单

#### 4.3.1 宠物信息浏览

| 四步 | 说明 |
|------|------|

| 四步 | 说明 |
|------|------|
| **触发** | 用户在详情页点击收藏图标 |
| **反馈** | 图标变为已收藏态，用户中心"我的收藏"可查看 |
| **规则** | 需登录；同一宠物不可重复收藏；宠物下架后收藏仍保留但标注"已下架" |
| **循环** | 可取消收藏，取消后可再次收藏 |

##### 异常分支

| 异常类型 | 触发条件 | 系统行为 | 用户提示 |
|---------|---------|---------|---------|
| 网络异常 | 列表/详情请求超时 | 自动重试 1 次，失败后展示重试按钮 | Toast"网络开小差了" + 重试按钮 |
| 数据异常 | 宠物详情字段缺失/图片加载失败 | 缺失字段展示默认值/占位图 | 空状态占位图 |
| 权限异常 | 未登录点击收藏 | 跳转登录页，登录后回到原页面 | 引导登录弹窗 |
| 并发冲突 | 宠物刚被领养，状态已变更 | 刷新后详情页展示"已被领养"并置灰按钮 | 提示"该宠物已找到家" |
| 业务异常 | 宠物已下架仍被访问（收藏链接进入） | 展示"宠物已下架"页 | 提示 + 返回列表引导 |

##### 业务规则

- 规则 1：列表仅展示 status=available 的宠物
- 规则 2：健康档案对已登录用户全量可见，未登录用户可见概要（如健康状态标签）
- 规则 3：宠物下架后详情页不可申请

##### 全局状态

| 状态 | 呈现方式 |
|------|---------|
| 加载态 | 列表骨架屏 / 详情页 Loading |
| 空状态 | "暂无符合条件的宠物" + 清除筛选引导 |
| 错误态 | 网络错误页 + 重试按钮 |
| 成功态 | 收藏成功 Toast + 图标变化 |
| 确认操作 | 收藏/取消收藏无需二次确认 |
| 撤销操作 | 取消收藏即时生效，不可撤销（重新收藏即可） |

## 五、验收标准

### AC-01：用户提交领养申请（正常场景）
- **Given**：用户已登录，目标宠物状态为"待领养"，且该用户对该宠物无进行中申请
- **When**：用户填写申请表单（申请理由/居住条件/养宠经验/联系电话）并点击提交
- **Then**：系统创建申请（状态=待审核），"我的申请"出现该记录，宠物状态变为"申请中"，管理员待审核队列出现该申请

### AC-02：管理员审核通过（正常场景）
- **Given**：存在一条"待审核"申请，管理员已登录后台
- **When**：管理员打开审核详情并点击"通过"，填写审核意见后确认
- **Then**：申请状态变为"已通过"，宠物状态变为"已领养"，申请人收到站内通知，审核记录（审核人/时间/意见）完整留存

### AC-03：申请被拒后重新提交（异常场景）
- **Given**：申请状态为"已拒绝"（附拒绝原因）
- **When**：用户修改申请材料后点击"重新提交"
- **Then**：系统生成新申请并置为"待审核"，宠物状态回到"申请中"，原拒绝记录保留可查

### AC-04：健康档案缺失（边界场景）
- **Given**：宠物无任何健康档案记录
- **When**：领养用户打开该宠物详情页
- **Then**：健康档案 Tab 展示"健康档案待补充"空状态，不出现报错，且申请按钮仍可用

### AC-05：兽医越权访问审核（权限异常场景）
- **Given**：兽医已登录，尝试直接访问管理后台申请审核 URL
- **When**：发起访问请求
- **Then**：系统返回无权限提示，不暴露任何审核数据

### AC-06：同一宠物并发申请（并发场景）
- **Given**：宠物 A 已有一条"待审核"申请
- **When**：另一用户对宠物 A 提交申请
- **Then**：系统拦截提交并提示"该宠物正在审核中"，宠物 A 详情页申请按钮置灰
