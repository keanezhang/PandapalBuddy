# 宠物领养平台 产品需求文档（PRD）

| 项目 | 内容 |
|---|---|
| 产品名称 | 宠物领养平台 |
| 文档版本 | v1.0 |
| 文档状态 | 评审稿 |
| 适用范围 | MVP（Web 端 + 移动端 H5） |

---

## 1. 项目背景与目标

### 1.1 背景
流浪宠物数量逐年上升，领养信息分散在社交群、线下门店，缺乏统一、可信、可追踪的线上渠道；领养审核依赖人工线下沟通，健康信息不透明。本平台旨在打通"浏览宠物 → 提交申请 → 管理员审核 → 兽医健康档案背书"的完整链路。

### 1.2 产品目标
- **G1**：为领养者提供宠物信息浏览、筛选与在线申请能力，降低领养门槛。
- **G2**：为管理员提供申请审核、宠物信息与用户管理能力，提升审核效率与可追溯性。
- **G3**：为兽医提供健康档案上传能力，为领养者提供权威健康背书，提升平台可信度。

### 1.3 成功指标（建议）
- 月度宠物信息浏览量、领养申请转化率；
- 申请平均审核时长（目标 < 48 小时）；
- 健康档案覆盖率（已上线宠物 ≥ 60%）。

## 2. 术语定义

| 术语 | 定义 |
|---|---|
| 领养帖 / 宠物信息 | 平台上一只待领养宠物的完整信息卡片（照片、品种、年龄、性格、城市、状态等） |
| 领养申请 | 领养者对某只宠物提交的申请记录，包含资质信息与状态 |
| 健康档案 | 兽医上传的疫苗、体检、病历等记录，与宠物绑定 |
| 状态机 | 宠物与申请的可流转状态集合及流转规则 |

## 3. 用户角色

| 角色 | 说明 |
|---|---|
| 访客 | 未登录用户，仅可浏览宠物信息 |
| 领养者（注册用户） | 注册登录后可浏览、提交领养申请、查看本人申请 |
| 兽医 | 通过管理员认证的角色，可上传/维护健康档案 |
| 管理员 | 平台运营人员，审核申请、管理宠物/用户/角色、查看审计日志 |

**角色分配规则**：默认注册用户为"领养者"；"兽医"与"管理员"由管理员后台分配（MVP 阶段人工分配，不做自助申请）。

## 4. 功能需求

### FR-1 浏览领养信息
- **FR-1.1 宠物列表**：以卡片形式展示宠物（照片、名称、品种、年龄、城市、领养状态），支持分页/无限滚动。
- **FR-1.2 宠物详情**：展示完整信息（性格描述、健康摘要、所在机构）、健康档案摘要与"申请领养"入口；宠物状态非"待领养"时不展示申请入口。
- **FR-1.3 搜索与筛选**：支持按品种、年龄区间、城市、性别筛选，支持关键词搜索。

### FR-2 提交领养申请
- **FR-2.1 申请表单**：姓名、手机号、居住情况（自有/租赁）、养宠经验、申请理由（必填）；提交前校验必填项与手机号格式。
- **FR-2.2 去重限制**：同一用户对同一宠物仅可存在一条非终态申请（终态：已拒绝/已取消）。
- **FR-2.3 我的申请**：领养者可查看本人全部申请及状态、审核结果与备注；待审核状态下可撤销（状态流转为"已取消"）。
- **FR-2.4 通知**：申请提交成功、审核结果变化时向领养者发送站内通知（MVP 阶段站内信即可）。

### FR-3 管理员审核申请
- **FR-3.1 审核列表**：管理员可见全部申请，可按状态/宠物/申请人筛选；详情展示宠物信息、申请人资料、健康档案。
- **FR-3.2 审核操作**：通过（可填备注）或拒绝（**必填**原因）；审核后不可重复操作同一申请。
- **FR-3.3 状态联动**：申请"已通过"时，对应宠物状态自动流转为"审核中"（锁定，防止他人在审核期间重复申请成功）；领养完成确认后宠物状态为"已领养"。

### FR-4 兽医健康档案
- **FR-4.1 上传档案**：兽医对已绑定宠物上传健康档案（疫苗记录、体检报告、病历），支持 PDF/JPG/PNG，单文件 ≤ 10MB，需填写档案类型与摘要。
- **FR-4.2 档案管理**：兽医可编辑/更新本人上传的档案，不可修改他人档案；档案记录上传时间与兽医署名。
- **FR-4.3 档案查看**：访客/领养者仅可见档案摘要（如"已接种狂犬疫苗"）；完整文件仅对已提交该宠物申请的领养者、兽医、管理员可见。

### FR-5 用户与权限管理
- **FR-5.1 注册/登录**：手机号 + 验证码注册登录（MVP 假设）。
- **FR-5.2 角色分配**：管理员可查看用户列表、分配/回收兽医与管理员角色、禁用用户。
- **FR-5.3 审计日志**：记录申请审核、宠物信息变更、健康档案上传、角色变更等关键操作（操作人、时间、对象、结果）。

## 5. 权限矩阵（RBAC）

> 说明：✓ 允许；✗ 不允许。UI 层对不允许的功能不渲染入口，**服务端必须执行二次鉴权**（防止绕过前端直接调用接口），越权访问返回 403。

| 编号 | 功能模块 | 功能点 | 访客 | 领养者 | 兽医 | 管理员 |
|---|---|---|---|---|---|---|
| P1 | 宠物信息 | 浏览宠物列表/详情 | ✓ | ✓ | ✓ | ✓ |
| P2 | 宠物信息 | 搜索/筛选 | ✓ | ✓ | ✓ | ✓ |
| P3 | 宠物信息 | 查看健康档案摘要 | ✓ | ✓ | ✓ | ✓ |
| P4 | 宠物信息 | 查看健康档案完整文件 | ✗ | ✓（仅限本人申请的宠物） | ✓ | ✓ |
| P5 | 宠物信息 | 发布/编辑/下架宠物信息 | ✗ | ✗ | ✗ | ✓ |
| P6 | 领养申请 | 提交领养申请 | ✗ | ✓ | ✗ | ✗ |
| P7 | 领养申请 | 查看本人申请/撤销 | ✗ | ✓ | ✗ | ✗ |
| P8 | 领养申请 | 查看全部申请 | ✗ | ✗ | ✗ | ✓ |
| P9 | 领养申请 | 审核（通过/拒绝） | ✗ | ✗ | ✗ | ✓ |
| P10 | 健康档案 | 上传/编辑健康档案 | ✗ | ✗ | ✓（仅本人上传） | ✓ |
| P11 | 健康档案 | 查看全部健康档案 | ✗ | ✗ | ✓ | ✓ |
| P12 | 用户管理 | 查看用户列表/角色分配/禁用 | ✗ | ✗ | ✗ | ✓ |
| P13 | 系统管理 | 查看审计日志 | ✗ | ✗ | ✗ | ✓ |
| P14 | 系统管理 | 站内通知发送 | ✗ | ✗ | ✗ | ✓（系统自动） |

**补充规则**：
1. 所有鉴权在服务端强制执行；未授权访问返回 403。
2. 管理员拥有全部权限，但不可提交领养申请（P6 除外场景见第 11 节 Q1）。
3. 兽医需先经管理员认证（角色分配）后方具备 P10/P11 权限。
4. 已禁用账号不可登录，所有权限即时失效。

## 6. 状态流转

### 6.1 领养申请状态机
```
待审核(pending) ──通过──▶ 已通过(approved) ──确认完成──▶ 已完成(completed)
      │
      ├──拒绝（必填原因）──▶ 已拒绝(rejected)
      └──申请人撤销──▶ 已取消(cancelled)
```

### 6.2 宠物状态机
```
待领养(available) ──申请通过──▶ 审核中(under_review) ──确认完成──▶ 已领养(adopted)
      │                                │
      └─────────管理员下架─────────────┴──▶ 已下架(archived)
```

## 7. 非功能需求

| 类别 | 要求 |
|---|---|
| 性能 | 宠物列表页 P95 响应 ≤ 2s；详情页 P95 ≤ 1.5s |
| 安全 | 全站 HTTPS；服务端鉴权；用户敏感信息（手机号）脱敏展示；健康档案文件访问 URL 鉴权 |
| 可用性 | 核心流程（浏览-申请-审核）月可用性 ≥ 99.9% |
| 合规 | 宠物与健康数据隐私保护，遵循个人信息保护相关法规 |
| 兼容性 | 主流浏览器最新两个版本；iOS/Android 主流版本 H5 |

## 8. 验收标准

- **AC-1 浏览与筛选**：访客打开"领养中心"页，2 秒内可见宠物卡片列表（含照片、名称、品种、年龄、城市、状态）；按品种/城市/年龄筛选与关键词搜索均返回正确结果；状态为"已领养/已下架"的宠物不展示"申请领养"入口。
- **AC-2 提交申请**：已登录领养者在宠物详情页点击"申请领养"并完整填写表单后提交，系统生成"待审核"申请并发送站内通知；同一用户对同一宠物重复提交时提示"您已提交过申请"；未填必填项或手机号格式错误时表单校验拦截并提示。
- **AC-3 管理员审核**：管理员对"待审核"申请点击"通过"，申请状态变为"已通过"、对应宠物状态变为"审核中"，领养者收到通知；点击"拒绝"必须填写原因否则无法提交；审核完成后同一申请不可重复审核。
- **AC-4 健康档案**：认证兽医登录后可在宠物详情页上传健康档案（PDF/JPG ≤ 10MB），成功后档案在健康档案模块可见，展示档案类型、摘要、上传时间与兽医署名；访客仅见摘要，完整文件仅对领养者（本人申请的宠物）/兽医/管理员可见。
- **AC-5 权限隔离**：普通领养者与兽医直接访问管理后台 URL 返回 403，且 UI 不渲染任何管理入口；未登录用户提交领养申请被引导至登录页；服务端对所有写操作执行鉴权校验。
- **AC-6 状态与审计闭环**：申请/宠物状态每一步流转均记录操作人、时间、备注，审计日志可检索；"已通过"的申请在领养完成确认后，宠物变为"已领养"。

## 9. 数据模型概要

- **users**：id、手机号、昵称、角色（adopter/vet/admin）、状态（正常/禁用）、创建时间
- **pets**：id、名称、物种（cat/dog/other）、品种、年龄、性别、城市、性格描述、状态（available/under_review/adopted/archived）、封面图、创建人
- **adoption_applications**：id、pet_id、user_id、状态、居住情况、养宠经验、申请理由、审核人、审核时间、审核备注、创建时间
- **health_records**：id、pet_id、vet_id、档案类型（vaccine/checkup/medical）、摘要、文件地址、创建时间、更新时间
- **audit_logs**：id、操作人、操作类型、对象类型、对象 id、结果、详情、时间

## 10. 边界与假设

- **假设一**：MVP 阶段采用手机号 + 验证码注册登录，不支持第三方登录。
- **假设二**：宠物信息由管理员代录（救助机构/送养人暂不直接入驻，后续版本开放）。
- **假设三**：通知采用站内信，不做短信/邮件/小程序推送。
- **假设四**：健康档案"完整文件可见性"以申请关联为界：领养者仅能查看其申请关联宠物的完整档案。
- **边界**：本版本不含支付/押金、线下回访、社区/论坛、多机构独立后台、兽医资质自助认证。

## 11. 风险与开放问题

- **R1**：审核状态联动依赖人工确认"领养完成"，存在宠物长期停留"审核中"的风险 → 增加超时提醒机制。
- **R2**：兽医上传档案格式不规范 → 上传时提供模板与必填摘要字段。
- **R3**：健康档案隐私泄露风险 → 权限矩阵 P4 限制 + 文件访问 URL 鉴权。
- **Q1**：管理员是否允许以领养者身份提交申请？（默认不允许，见 P6）
- **Q2**：申请通过后是否需要"领养协议签署/电子签"？（本版本不包含）
