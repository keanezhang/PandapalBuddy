## 1. 产品概述

### 1.1 背景与问题

线下宠物领养存在信息分散、流程不透明、健康信息缺失等问题：领养人难以找到真实可靠的待领养宠物信息；救助机构/管理员靠人工登记、线下沟通审核，效率低且无留痕；宠物的疫苗接种、体检等健康档案缺乏统一管理入口，领养人无法在决策前了解宠物健康状况。

### 1.2 产品定位

一个连接「待领养宠物信息发布方（管理员）— 领养人 — 兽医」三方角色的在线领养平台，实现**信息浏览 → 在线申请 → 管理员审核 → 健康档案共享**的完整闭环。

### 1.3 产品目标

1. 让领养人快速、可信地浏览待领养宠物信息并发起领养申请；
2. 让管理员在线完成申请审核，流程留痕、状态可追踪；
3. 让兽医为宠物建立并维护健康档案，为领养决策提供健康依据。

### 1.4 本期范围（In Scope）

- 宠物领养信息浏览（列表 + 筛选 + 详情）
- 领养人提交领养申请与状态查询
- 管理员审核领养申请（通过/驳回）
- 兽医上传/维护宠物健康档案
- 基础用户注册登录与角色权限控制（权限矩阵）

### 1.5 不在本期范围（Out of Scope）

- 线上支付 / 领养押金交易
- 宠物寄养、宠物用品商城
- 移动端 App（本期仅适配 Web 响应式）
- 与外部救助机构系统的对接

## 2. 用户角色定义

| 角色 | 角色编码 | 说明 |
| --- | --- | --- |
| 访客 | GUEST | 未登录用户，仅可浏览公开信息 |
| 领养人 | ADOPTER | 注册登录用户，可浏览信息、提交/查看领养申请 |
| 兽医 | VET | 经管理员认证的兽医账号，可上传/编辑宠物健康档案 |
| 管理员 | ADMIN | 平台运营人员，管理宠物信息、审核领养申请、管理用户 |

## 3. 功能需求

### FR-1 宠物领养信息浏览

**FR-1.1 宠物列表页**
- 展示待领养宠物卡片：照片、昵称、品种、性别、年龄、所在地区、领养状态（待领养/审核中/已领养）。
- 支持按品种、性别、年龄区间、地区、状态进行筛选；支持关键字搜索（昵称/品种）。

**FR-1.2 宠物详情页**
- 展示宠物照片集、基本信息（品种、年龄、性别、毛色、体型、性格描述、救助故事）、领养要求（如领养人需有稳定住所）。
- 展示「健康档案」区块：疫苗记录、绝育状态、体检记录、驱虫记录（由兽医维护，见 FR-4）。
- 展示领养状态与「申请领养」入口（未登录访客点击后跳转登录页）。

### FR-2 领养申请

**FR-2.1 提交申请**
- 领养人填写申请表：姓名、联系电话、微信号、所在城市、居住情况（自有住房/租房）、是否有养宠经验、家庭其他成员情况、领养理由、期望领养时间。
- 同一领养人对同一宠物**同时仅可存在 1 条「待审核/审核中」申请**（防重复提交）。
- 提交成功后生成申请单号，状态为「待审核」，系统通知管理员。

**FR-2.2 申请状态查询**
- 领养人可在「我的申请」列表查看申请单状态及管理员审核意见。
- 状态流转：待审核 → 审核中 →（已通过 | 已驳回）→ 已完成（领养确认）。

**FR-2.3 撤回申请**
- 在「待审核/审核中」状态下，领养人可撤回申请；撤回后宠物状态若为「审核中」则回退为「待领养」。

### FR-3 管理员审核

**FR-3.1 审核列表**
- 管理员在后台查看全部申请单，支持按状态（待审核/审核中/已通过/已驳回）、宠物、提交时间筛选。

**FR-3.2 审核操作**
- 管理员可将申请标记为「审核中」；执行「通过」或「驳回」并**必须填写审核意见**。
- 审核通过后，对应宠物状态自动变为「已领养」，同一宠物的其他「待审核」申请自动变为「已驳回」（驳回原因：宠物已被领养）。
- 审核结果实时通知申请人（站内信/短信，短信为可选能力）。

### FR-4 兽医上传健康档案

**FR-4.1 档案创建**
- 兽医可为关联宠物创建健康档案，含字段：疫苗记录（疫苗名称、接种日期、下次接种日期）、绝育状态、最近体检日期与体检结论、驱虫记录（药品、日期）、慢性病史/注意事项。
- 支持上传附件（体检报告 PDF / 图片），单个附件 ≤ 10MB。

**FR-4.2 档案编辑与可见性**
- 兽医可编辑自己创建的档案；管理员可编辑/删除任意档案。
- 档案在宠物详情页对**所有访客可见**（公开健康信息），附件可设「仅领养人可见」标记。
- 档案变更记录操作人、时间（审计留痕）。

### FR-5 用户与权限管理（基础）

- 注册/登录：手机号 + 验证码或邮箱 + 密码。
- 兽医角色由管理员在后台开通（审核兽医资质后授予 VET 角色）。
- 后端基于 RBAC 按权限矩阵（见第 5 节）做接口级鉴权，未授权请求返回 403。

## 4. 业务规则与状态流转

### 4.1 领养申请状态机

```
待审核 --(管理员标记)--> 审核中 --(通过)--> 已通过 --(领养确认)--> 已完成
                            |--(驳回)--> 已驳回
待审核/审核中 --(领养人撤回)--> 已撤回
```

### 4.2 宠物状态机

```
待领养 --(申请审核中)--> 审核中 --(审核通过)--> 已领养
审核中 --(申请驳回/撤回)--> 待领养
```

### 4.3 关键业务规则

- BR-1：同一领养人同一宠物同时仅 1 条有效申请。
- BR-2：管理员驳回/通过必须填写审核意见，否则不可提交。
- BR-3：宠物「已领养」后自动驳回该宠物其余待审核申请。
- BR-4：非管理员不可访问后台审核接口（权限矩阵强制）。
- BR-5：健康档案仅 VET / ADMIN 可写，其余角色只读。

## 5. 权限矩阵（RBAC）

> ✅ = 允许，❌ = 禁止。所有角色默认可查看公开宠物信息与健康档案。

| 功能模块 | 操作 | 访客 GUEST | 领养人 ADOPTER | 兽医 VET | 管理员 ADMIN |
| --- | --- | :-: | :-: | :-: | :-: |
| 宠物信息浏览 | 查看列表/详情 | ✅ | ✅ | ✅ | ✅ |
| 宠物信息管理 | 新增 / 编辑 / 下架 | ❌ | ❌ | ❌ | ✅ |
| 领养申请 | 提交申请 | ❌ | ✅ | ❌ | ✅ |
| 领养申请 | 查看自己的申请 | ❌ | ✅ | ❌ | ✅ |
| 领养申请 | 撤回自己的申请 | ❌ | ✅ | ❌ | ✅ |
| 领养申请 | 查看全部申请 | ❌ | ❌ | ❌ | ✅ |
| 领养申请 | 审核（通过/驳回） | ❌ | ❌ | ❌ | ✅ |
| 健康档案 | 上传 / 编辑 | ❌ | ❌ | ✅（自己创建） | ✅ |
| 健康档案 | 查看 | ✅ | ✅ | ✅ | ✅ |
| 健康档案 | 删除 | ❌ | ❌ | ❌ | ✅ |
| 用户管理 | 开通兽医账号 / 禁用用户 | ❌ | ❌ | ❌ | ✅ |
| 后台管理入口 | 访问管理后台 | ❌ | ❌ | ❌ | ✅ |

**权限矩阵说明**
- 越权访问判定：未登录访问需登录接口 → 302 跳转登录；已登录但角色不符 → HTTP 403 + 错误提示。
- 权限校验在后端接口层强制执行，前端隐藏入口仅作体验优化，不作为安全边界。

## 6. 非功能需求

| 类别 | 需求 |
| --- | --- |
| 性能 | 列表页 P95 响应时间 ≤ 3s；支持 ≥ 100 并发在线浏览 |
| 安全 | 密码加密存储（bcrypt）；接口鉴权（JWT + RBAC）；附件上传做类型/大小校验与病毒扫描；操作留痕（审核、档案变更） |
| 合规 | 用户个人信息（手机号、住址等）遵循最小化采集与隐私保护要求；提供隐私政策与用户协议 |
| 可用性 | Web 端适配主流浏览器（Chrome / Edge / Safari 最新两个版本）；移动端响应式适配 |
| 数据 | 每日全量备份，RPO ≤ 24h，RTO ≤ 4h |

## 7. 验收标准（Acceptance Criteria）

- **AC-1 浏览功能**：访客无需登录即可浏览宠物列表，可按品种/性别/年龄/地区/状态筛选并查看宠物详情页；详情页正确展示健康档案区块；未登录点击「申请领养」跳转登录页。
- **AC-2 申请与审核闭环**：登录领养人可对「待领养」宠物提交申请，系统生成申请单号并通知管理员；管理员可审核（通过/驳回，驳回或通过必须填写审核意见）；审核结果在领养人「我的申请」中实时可见；同一宠物被通过后，其余待审核申请自动驳回并给出原因。
- **AC-3 健康档案管理**：兽医可上传/编辑健康档案（含疫苗、绝育、体检、驱虫字段与附件），档案变更可审计；档案在宠物详情页对所有访客可见；越权写入（领养人/访客调用档案写接口）返回 403。
- **AC-4 权限矩阵生效**：按第 5 节矩阵逐项验证——访客提交申请、领养人访问管理后台、非管理员执行审核均被拒绝（403/302 跳转），管理员可执行全部授权操作；矩阵中 12 个功能模块 × 4 角色组合全部符合预期。
- **AC-5 非功能验收**：列表页在 100 并发下 P95 响应 ≤ 3s；上传 >10MB 附件被拦截并给出提示；非法文件类型（如 .exe）被拒绝。

## 8. 关键假设（Assumptions）

1. 本期为 Web 端产品，移动端后续版本覆盖。
2. 兽医账号由管理员人工认证开通，暂不做兽医自助入驻审核流。
3. 审核通知以站内信为准，短信通知为可选能力（依赖第三方短信服务开通）。
4. 健康档案对访客公开，默认不涉及隐私脱敏处理（附件可选「仅领养人可见」）。

---

## 9. 风险与应对

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 宠物信息虚假/重复 | 信任度下降 | 管理员审核宠物上架；展示救助来源 |
| 审核效率低 | 申请积压、用户流失 | 审核列表筛选/排序、待办提醒、SLA 48h 内处理 |
| 健康档案数据不准确 | 领养纠纷 | 档案审计留痕、兽医实名认证、免责声明 |
| 恶意注册/刷单申请 | 系统资源浪费 | 手机号实名、单宠物单用户有效申请限制（BR-1） |

## 10. 附录

### 10.1 核心数据实体

- **pet（宠物）**：id、name、breed、gender、age、region、status（待领养/审核中/已领养）、description、photos、created_at
- **adoption_application（领养申请）**：id、application_no、pet_id、applicant_id、fields（姓名/电话/居住情况/经验/理由…）、status（待审核/审核中/已通过/已驳回/已撤回/已完成）、review_comment、created_at、updated_at
- **health_record（健康档案）**：id、pet_id、vet_id、vaccines、neutered、last_checkup、deworming、notes、attachments、visibility、created_at、updated_at、operator_id
- **user（用户）**：id、phone/email、password_hash、role（GUEST/ADOPTER/VET/ADMIN）、status
