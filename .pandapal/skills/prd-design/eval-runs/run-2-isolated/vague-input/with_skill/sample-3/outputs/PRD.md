## 一、概述与背景

##### 背景

客服团队目前通过邮件、IM 和口头方式零散接收客户问题，工单散落在各渠道，缺乏统一台账，导致「谁在处理、处理到哪一步、何时能解决」无法实时看清。问题跟进依赖个人记忆，超时无人提醒、升级无规则，主管无法量化团队工作量与服务时效，复盘只能靠手工统计，效率低且口径不一。

##### 目标

- 目标 1：客户问题 100% 收敛到统一工单系统，实现工单全流程线上化、可追踪。
- 目标 2：首次响应时效可控，SLA 达成率（按时解决率）≥ 90%。
- 目标 3：队列与积压可视化，主管实时掌握全局，团队人均日处理量提升 30%。

##### 角色清单

| 角色 | 职责 | 核心诉求 |
|------|------|---------|
| 客服专员 | 接收分派给自己的工单，跟进处理、回复客户、推进状态直至关闭 | 清楚自己有哪些待处理工单、优先级与时限，处理过程不丢信息 |
| 客服主管 | 创建并分派工单、监控队列与 SLA、处理升级与仲裁、查看报表复盘 | 全局看清工单分布与积压、超时及时预警、量化团队绩效 |

##### 场景清单

### 场景 1：客服专员处理分派工单（核心）

- **发生时态**：日常
- **角色**：客服专员
- **目标**：在自己名下工单列表中接单、回复客户、推进状态并关闭工单
- **前置条件**：已登录，且主管已将至少一张工单分派给本人

### 场景 2：客服主管创建并分派工单（核心）

- **发生时态**：日常
- **角色**：客服主管
- **目标**：把新收到的客户问题固化为工单，选择处理人分派出去，保证有人负责
- **前置条件**：已登录，具有主管权限，团队内至少有一名可用的客服专员

### 场景 3：高峰期工单积压应对（边缘）

- **发生时态**：峰值
- **角色**：客服主管、客服专员
- **目标**：工单量突增时，主管通过队列看板识别积压与超时风险，临时调整分派
- **前置条件**：新工单创建速度高于处理速度，队列出现积压

### 场景 4：工单超时与疑难升级（边缘）

- **发生时态**：异常
- **角色**：客服主管
- **目标**：工单临近/超过 SLA 时限或问题疑难时，自动升级给主管仲裁后重新分派
- **前置条件**：工单超过首次响应/解决时限，或专员标记为「疑难」

##### 场景-角色矩阵

| 场景 | 角色 | 核心/边缘 | 发生时态 |
|------|------|----------|---------|
| 处理分派工单 | 客服专员 | 核心 | 日常 |
| 创建并分派工单 | 客服主管 | 核心 | 日常 |
| 高峰期积压应对 | 客服主管、客服专员 | 边缘 | 峰值 |
| 超时与疑难升级 | 客服主管 | 边缘 | 异常 |

### 3.2 业务链路

#### 核心链路 1：工单创建与分派

```text
┌──────────┐  录入并提交  ┌──────────┐  手动/自动分派  ┌──────────┐   专员接单  ┌──────────┐
│ 主管在工单 │ ───────────►│ 工单创建  │ ─────────────►│ 工单进入  │ ──────────►│ 专员开始  │
│ 工作台新建 │             │ 表单     │               │ 处理中队列│            │ 处理工单  │
└──────────┘              └────┬─────┘               └────┬─────┘            └────┬─────┘
                              │                          │                       │
                              │ <校验失败: 客户信息缺失/  │ <分派对象非在岗专员>   │ 输出
                              │  优先级非法>             ▼                       ▼
                              ▼                    ┌──────────┐           ┌──────────┐
                        ┌──────────┐               │ 提示并回退 │           │ 通知专员  │
                        │ 表单报错  │               └──────────┘           │ 有新增工单│
                        └──────────┘                                       └──────────┘
```

**链路说明**：主管在工作台新建工单（校验客户联系方式、优先级等必填项）→ 提交后系统按优先级登记 SLA 时限并生成工单 → 主管手动选择或系统按负载自动分派给在岗专员 → 专员收到通知后接单，工单进入「处理中」。

#### 核心链路 2：工单处理与关闭

```text
┌──────────┐  回复客户  ┌──────────┐  标记解决  ┌──────────┐  客户确认  ┌──────────┐
│ 专员处理工单│ ─────────►│ 工单回复  │ ─────────►│ 工单置为  │ ─────────►│ 工单关闭  │
└──────────┘            └────┬─────┘            │ 已解决   │            └────┬─────┘
                             │                  └────┬─────┘                 │
                             │ <客户追问>           │ <SLA 超时/疑难>        │ 输出
                             ▼                      ▼                        ▼
                       ┌──────────┐            ┌──────────┐            ┌──────────┐
                       │ 继续处理  │            │ 自动升级  │            │ 满意度评价│
                       └──────────┘            └──────────┘            └──────────┘
```

**链路说明**：专员在详情页回复客户（每次回复记录可见/不可见类型）→ 问题解决后标记「已解决」→ 客户确认或超时默认确认后工单「已关闭」→ 关闭时系统邀请客户进行满意度评价；若客户追问则回到处理中，若临近/超过 SLA 时限或专员标记疑难，则自动升级给主管。

### 3.3 状态流转

#### 工单状态机

```text
      ┌──────────┐  主管分派   ┌──────────┐  专员接单   ┌──────────┐  标记解决  ┌──────────┐
 ────►│  待分派   │ ──────────►│  处理中   │ ──────────►│  已解决   │ ─────────►│  已关闭   │
      └────┬─────┘            └─────┬────┘            └────┬─────┘            └──────────┘
           │                        │                      │
           │ <误建作废>             │ <超时/疑难>           │ <客户反馈未解决>
           ▼                        ▼                      ▼
     ┌──────────┐            ┌──────────┐            ┌──────────┐
     │  已关闭   │            │  已升级   │            │  处理中   │
     └──────────┘            └─────┬────┘            └──────────┘
                                   │ <主管仲裁后重新分派>
                                   ▼
                             ┌──────────┐
                             │  处理中   │
                             └──────────┘
```

##### 状态定义

| 状态 | 含义 | 允许的下一状态 | 触发迁移的动作/条件 |
|------|------|---------------|-------------------|
| 待分派 | 工单已创建，等待分派处理人 | 处理中, 已关闭 | 主管分派；误建由主管作废关闭 |
| 处理中 | 专员已接单，正在处理 | 已解决, 已升级 | 专员标记解决；超时/疑难触发升级 |
| 已升级 | 工单升级给主管，等待仲裁 | 处理中 | 主管仲裁后重新分派给专员 |
| 已解决 | 专员已答复/解决，等待客户确认 | 已关闭, 处理中 | 客户确认关闭；客户反馈未解决回到处理中 |
| 已关闭 | 工单终结 | — | — |

##### 非法迁移

| 从 | 到 | 拒绝原因 | 系统行为 |
|----|-----|---------|---------|
| 已关闭 | 处理中 | 已关闭工单不允许直接复活 | 拒绝并提示「请新建工单或由主管重开工单」 |
| 已解决 | 待分派 | 已进入处理流程的工单不可回退分派 | 拒绝并提示「已解决的工单只能关闭或回到处理中」 |
| 待分派 | 已解决 | 未分派不可直接标记解决 | 拒绝并提示「请先分派处理人」 |

### 3.5 流转规则

| 规则 | 触发条件 | 行为 |
|------|---------|------|
| SLA 首次响应计时 | 工单分派给专员 | 首次响应时限：紧急 1h、高 4h、中 24h、低 48h |
| SLA 解决计时 | 工单创建 | 解决时限：紧急 8h、高 24h、中 3 天、低 7 天 |
| 自动升级 | 距 SLA 截止剩余 25% 时间仍处理中 | 标记「临近超时」并通知主管；超时则自动升级 |
| 疑难升级 | 专员在处理中标记「疑难」 | 升级给主管，附疑难原因 |
| 默认关闭 | 已解决后 72 小时客户未反馈 | 自动关闭并记为中性评价（满意度留空） |
| 自动分派（可选） | 主管开启自动分派 | 按在岗专员当前负载最低者分派 |

### 3.6 缺口标注

- 🟡 **当前状态**：模糊输入假设下，渠道接入（电话/邮件/IM/官网）与第三方客服系统对接细节缺失。
- 🟢 **需补充的内容**：各渠道的接入方式、工单自动生成规则、客户侧自助查询入口（本期未包含）。
- 🔵 **影响范围**：工单创建模块的来源字段、SLA 计时起点、客户确认与满意度评价链路。

## 四、需求详细描述

### 4.1 背景与目标

客服团队缺乏统一工单台账，问题处理不可追踪、超时无预警、绩效无数据。本期间目标是把工单「创建 → 分派 → 处理 → 关闭 → 复盘」跑通，重点保障**时效可控**与**责任到人**。

##### 本期范围
- ✅ 包含：工单创建与分派、专员处理与关闭、队列与 SLA 监控、升级管理、报表中心（含绩效看板）、满意度评价（关闭时邀请）。
- ❌ 不包含：客户自助查询工单进度门户、多渠道自动接入（本期先人工录入）、智能客服机器人、多租户与计费。

### 4.2 用户故事

#### Story 1：主管创建并分派工单（P0）
- **作为** 客服主管
- **我希望** 在收到客户问题后，能在一个表单里完整录入客户信息与问题描述，并选择处理人一键分派
- **以便** 问题快速有人负责、信息不散落在聊天记录里
- **没有这个功能，用户会怎样？** 问题继续散落在各渠道，无台账、无责任归属，后续无法追踪
- **优先级**：P0

#### Story 2：专员接单处理并推进状态（P0）
- **作为** 客服专员
- **我希望** 在工单工作台看到分派给我的工单及优先级/时限，能接单、回复客户、上传附件并推进状态
- **以便** 我按优先级有序处理，处理过程全程留痕，不漏单
- **没有这个功能，用户会怎样？** 处理依赖个人记忆，重复沟通、遗漏跟进、无凭据可查
- **优先级**：P0

#### Story 3：主管查看队列与 SLA 预警（P1）
- **作为** 客服主管
- **我希望** 在队列看板与 SLA 监控页实时看到各状态工单数量、临近超时与已超时工单
- **以便** 及时调配人手、在超时前介入，保证整体 SLA
- **没有这个功能，用户会怎样？** 超时无法提前发现，只能事后补救，SLA 无法保障
- **优先级**：P1

#### Story 4：超时/疑难工单自动升级（P1）
- **作为** 客服主管
- **我希望** 超时或疑难工单能自动升级到我这里，由我仲裁后重新分派
- **以便** 卡住的工单不被搁置，疑难问题有人兜底
- **没有这个功能，用户会怎样？** 卡单长期滞留，客户流失，责任无人认领
- **优先级**：P1

#### Story 5：关闭后满意度与报表复盘（P2）
- **作为** 客服主管
- **我希望** 工单关闭后能邀请客户评价，并在报表中心按时效/工作量/满意度多维查看
- **以便** 量化团队绩效、定位薄弱环节、支撑月度复盘
- **没有这个功能，用户会怎样？** 绩效复盘靠手工统计，口径不一、耗时且不准确
- **优先级**：P2

### 4.3 功能清单

#### 4.3.1 工单创建与分派

##### 1. 新建工单（弹窗表单）

| 四步 | 说明 |

| **规则** | 校验：标题、描述、客户姓名、联系方式、分类、优先级必填；联系方式需符合邮箱/手机格式；优先级非法值拒绝 |

|------|------|

##### 异常分支

| 异常类型 | 触发条件 | 系统行为 | 用户提示 |
|---------|---------|---------|---------|

- 规则 1：工单编号由系统生成，格式 `TK-YYYYMMDD-序号`，全局唯一。

| 状态 | 呈现方式 |
|------|---------|
| 加载态 | 提交按钮 Loading，弹窗内骨架屏 |
| 空状态 | 无在岗专员可选时，分派下拉显示「暂无可分派专员」 |

##### 1. 接单与回复客户

## 五、验收标准

### AC-01：主管创建并分派工单（正常）
- **Given**：主管已登录，团队内有在岗专员，工单列表为空
- **When**：主管点击新建工单，填写完整必填信息并选择处理人提交
- **Then**：工单创建成功并出现在「处理中」队列，SLA 截止时间按优先级正确计算，专员收到新增工单通知

### AC-02：专员处理并关闭工单（正常）
- **Given**：专员已登录，名下有一张「处理中」工单
- **When**：专员接单、回复客户、标记已解决，客户确认
- **Then**：工单状态依次「处理中→已解决→已关闭」，first_response_at / resolved_at / closed_at 正确记录，关闭后邀请客户评价

### AC-03：SLA 超时自动升级（异常）
- **Given**：一张「处理中」工单已超过解决时限
- **When**：系统定时任务扫描到超时工单
- **Then**：工单自动升级为「已升级」并通知主管，升级记录留痕，主管仲裁后可重新分派且时限重置为原时限 50%

### AC-04：越权访问拦截（权限异常）
- **Given**：客服专员已登录
- **When**：专员尝试访问队列看板、新建工单入口，或直接打开非本人工单详情
- **Then**：入口隐藏、请求被拦截，提示「无权限」；非本人工单详情仅展示只读摘要或拒绝访问

### AC-05：空队列与无数据边界（边界）
- **Given**：系统内无任何工单
- **When**：主管打开队列看板，专员打开工作台
- **Then**：展示空状态插画与引导文案，不报错、不出现空白页

### AC-06：并发更新冲突（并发）
- **Given**：专员与主管同时打开同一张「处理中」工单
- **When**：专员提交回复的同时，主管执行改派
- **Then**：后提交的操作收到冲突提示并强制刷新，工单状态与操作记录保持一致，无覆盖丢失

## 六、数据指标

### 6.1 核心成功指标（North Star）
- **指标名**：工单 SLA 按时解决率
- **计算方式**：`按期关闭工单数 ÷ 应关闭工单总数 × 100%`（排除因客户原因延期的工单）
- **目标值**：上线 4 周后达到 ≥ 90%
- **数据来源**：工单台账 + SLA 计时记录（报表中心取数）

### 6.2 过程指标

| 指标名 | 计算方式 | 基准值 | 目标值 | 数据来源 |
|-------|---------|-------|-------|---------|
| 首次响应时长中位数 | 分派到首次回复的时间中位数 | 无（新系统） | ≤ 4h | first_response_at 记录 |
| 平均解决时长 | 创建到关闭的平均时长 | 无 | ≤ 24h | resolved_at/closed_at |
| 积压工单数 | 状态非关闭且处理中/待分派的工单数 | 无 | ≤ 30 | 工单队列 |
| 升级率 | 升级工单数 ÷ 工单总数 | 无 | ≤ 10% | 升级记录 |
| 客户满意度 | 满意度评分均值（1~5） | 无 | ≥ 4.2 | 满意度评价 |
| 人均日处理量 | 关闭工单数 ÷ 在岗专员数 ÷ 工作日 | 无 | ≥ 15 张/人/天 | 工单关闭记录 |

### 6.3 异常告警阈值

| 监控项 | 告警条件 | 告警级别 | 处理 SOP |
|-------|---------|---------|---------|
