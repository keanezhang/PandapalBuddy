## 一、概述与背景

##### 背景

小型团队日常使用表格、聊天群和口头沟通来推进任务，任务散落在各处，缺乏统一视图，导致「谁在做什么、做到哪一步、何时交付」无法一眼看清。任务状态靠人工口头同步，遗漏和重复频繁，管理者难以了解项目整体进度。

##### 目标

- 目标 1：任务创建到完成全流程线上化，任务完成率提升至 85% 以上。
- 目标 2：团队任务状态同步耗时降低 50%（从口头同步改为看板实时可见）。
- 目标 3：项目进度可视化，管理者每周查看进度的时间投入减少 30%。

##### 角色清单

| 角色 | 职责 | 核心诉求 |
|------|------|---------|
| 普通成员 | 创建并推进自己负责的任务，参与协作 | 快速记录任务、清楚知道自己下一步做什么 |
| 项目管理员 | 创建项目、分配成员与权限、维护项目生命周期 | 掌控全局进度、保证成员职责清晰 |

##### 场景清单

### 场景 1：成员创建任务并推进看板流转（核心）

- **发生时态**：日常
- **角色**：普通成员
- **目标**：把新产生的待办事项固化为任务卡片，随工作推进更新状态
- **前置条件**：已登录，且已加入至少一个项目

### 场景 2：管理员创建项目并配置成员（核心）

- **发生时态**：日常
- **角色**：项目管理员
- **目标**：为新项目建好容器、邀请成员、划分角色，使成员可开始协作
- **前置条件**：已登录，具有管理员权限

### 场景 3：新成员首次加入项目（边缘）

- **发生时态**：首次
- **角色**：普通成员
- **目标**：进入项目后快速理解现状并认领任务
- **前置条件**：管理员已完成邀请，成员已接受邀请并登录

### 场景 4：断网/并发冲突下的任务更新（边缘）

- **发生时态**：异常
- **角色**：普通成员、项目管理员
- **目标**：任务状态/字段更新失败时不丢数据，冲突时明确提示
- **前置条件**：成员正在编辑任务，网络中断或他人同时修改同一任务

##### 场景-角色矩阵

| 场景 | 角色 | 核心/边缘 | 发生时态 |
|------|------|----------|---------|
| 创建任务并推进流转 | 普通成员 | 核心 | 日常 |
| 创建项目并配置成员 | 项目管理员 | 核心 | 日常 |
| 新成员首次加入 | 普通成员 | 边缘 | 首次 |
| 断网/并发冲突更新 | 普通成员、项目管理员 | 边缘 | 异常 |

### 3.2 业务链路

#### 核心链路 1：任务创建与流转

```text
┌──────────┐  填写并提交  ┌──────────┐  指派成员   ┌──────────┐   状态变更   ┌──────────┐
│ 成员在看板 │ ────────────►│ 任务创建  │ ──────────►│ 任务进入   │ ───────────►│ 任务推进  │
│ 页点击新建 │             │ 表单     │            │ 待处理列  │             │ 至完成   │
└──────────┘              └────┬─────┘            └────┬─────┘             └────┬─────┘
                              │                        │                       │
                              │ <校验失败: 标题为空/     │ <指派非项目成员>       │ 输出
                              │  项目已归档>            ▼                       ▼
                              ▼                  ┌──────────┐            ┌──────────┐
                        ┌──────────┐             │ 提示并回退 │            │ 通知相关  │
                        │ 表单报错  │             └──────────┘            │ 成员     │
                        └──────────┘                                      └──────────┘
```

**链路说明**：成员在看板页新建任务 → 提交表单（校验项目未归档、标题非空）→ 任务进入「待处理」列并指派给项目内成员 → 成员推进任务状态（待处理→进行中→已完成）→ 每次状态变更向相关成员（创建人、指派人、关注人）发送通知。

#### 核心链路 2：项目创建与成员加入

```text
┌──────────┐  创建项目   ┌──────────┐  邀请成员  ┌──────────┐  接受邀请  ┌──────────┐
│ 管理员在  │ ───────────►│ 项目创建  │ ─────────►│ 成员邀请  │ ─────────►│ 成员进入  │
│ 项目列表页 │            │ 完成     │           │ 发出     │           │ 项目     │
└──────────┘             └────┬─────┘           └────┬─────┘           └────┬─────┘
                             │                      │                       │
                             │ <管理员校验: 项目名   │ <邀请发送失败>         │ 输出
                             │  重复>               ▼                       ▼
                             ▼               ┌──────────┐            ┌──────────┐
                       ┌──────────┐          │ 提示重试  │            │ 首次进入  │
                       │ 表单报错  │          └──────────┘            │ 看板空状态│
                       └──────────┘                                   └──────────┘
```

**链路说明**：管理员创建项目（校验项目名唯一）→ 在成员管理页邀请成员（通过邮箱/链接，默认角色普通成员）→ 成员接受邀请后进入项目 → 首次进入看到看板空状态引导 → 管理员可随时调整成员角色或移除成员。

### 3.3 状态流转

#### 任务状态机

```text
      ┌──────────┐  指派并开始  ┌──────────┐   标记完成   ┌──────────┐
 ────►│  待处理   │ ───────────►│  进行中   │ ───────────►│  已完成   │
      └──────────┘             └─────┬────┘              └──────────┘
            ▲                        │
            │   重新打开             │ 取消任务
            │                        ▼
            │                  ┌──────────┐
            └──────────────────│  已取消   │
                               └──────────┘
```

##### 状态定义

| 状态 | 含义 | 允许的下一状态 | 触发迁移的动作/条件 |
|------|------|---------------|-------------------|
| 待处理 | 任务已创建，尚未开始 | 进行中, 已取消 | 成员点击「开始」；创建人/管理员取消 |
| 进行中 | 任务正在被执行 | 已完成, 已取消, 待处理 | 成员标记完成；取消；拖回待处理 |
| 已完成 | 任务交付验收通过 | 待处理 | 成员/管理员「重新打开」 |
| 已取消 | 任务被终止，不再推进 | 待处理 | 创建人/管理员「重新打开」 |

##### 非法迁移

| 从 | 到 | 拒绝原因 | 系统行为 |
|----|-----|---------|---------|
| 待处理 | 已完成 | 未开始的任务不可直接标记完成 | 拒绝并提示「请先将任务置为进行中」 |
| 已完成 | 已取消 | 已完成的交付物不可直接取消 | 拒绝并提示「请先重新打开任务」 |
| 已取消 | 已完成 | 已取消任务不可直接完成 | 拒绝并提示「请先重新打开任务」 |

### 3.5 流转规则

| 规则 | 触发条件 | 行为 |
|------|---------|------|
| 项目归档冻结 | 项目状态置为 archived | 全部任务进入只读，禁止新建/流转/评论；归档可撤销 |
| 指派成员校验 | 指派时 assignee 非项目成员 | 拒绝指派，提示「该用户不在项目内」 |
| 状态变更通知 | 任务状态发生迁移 | 向创建人、指派人、评论关注人发送站内通知 |
| 到期提醒 | 任务 due_at 临近（24h/1h） | 向指派人发送提醒；逾期任务在看板高亮 |
| 删除保护 | 删除已包含评论/附件的任务 | 二次确认弹窗，确认后任务连同评论删除 |

### 3.6 缺口标注

- 🟡 **当前状态**：附件上传功能（文件大小/类型限制）尚未定义；项目级「关注人」机制待明确。
- 🟢 **需补充的内容**：附件单文件大小上限与允许类型；关注人与评论 @ 的触发规则。
- 🔵 **影响范围**：任务详情页、通知中心、任务删除级联行为。

## 四、需求详细描述

### 4.1 背景与目标

团队任务散落在聊天与表格中，缺乏统一管理和进度可见性。本期目标是建设一个 Web 端团队任务协作平台，覆盖项目创建、任务流转、成员权限与通知触达，让团队在单一空间内推进任务。

##### 本期范围

- ✅ 包含：项目创建/编辑/归档；任务创建/流转/删除/评论；看板视图（拖拽流转）；成员邀请与角色管理；站内通知与到期提醒。
- ❌ 不包含：甘特图/日历视图；任务依赖与子任务；移动端 App；第三方 IM/邮箱集成；数据导出报表。

### 4.2 用户故事

#### Story 1：创建任务
- **作为** 普通成员
- **我希望** 在所属项目看板页快速新建任务并填写标题、优先级、指派人和截止时间
- **以便** 把脑海中的待办固化为可追踪的卡片
- **没有这个功能，用户会怎样？** 任务只能靠口头或外部工具记录，无统一追踪
- **优先级**：P0

#### Story 2：推进任务状态
- **作为** 普通成员
- **我希望** 在看板页拖拽任务卡片或在详情页点击「开始/完成」，让状态在待处理→进行中→已完成间流转
- **以便** 让团队实时看到任务进度
- **没有这个功能，用户会怎样？** 进度仍需人工口头同步，看板失去意义
- **优先级**：P0

#### Story 3：创建项目并邀请成员
- **作为** 项目管理员
- **我希望** 创建项目、邀请成员并分配角色（管理员/普通成员）
- **以便** 为新项目搭好协作容器并明确成员职责
- **没有这个功能，用户会怎样？** 无法界定项目边界与成员权限
- **优先级**：P0

#### Story 4：任务讨论与资料沉淀
- **作为** 普通成员
- **我希望** 在任务详情页发表评论、@ 同事并上传附件
- **以便** 把与任务相关的沟通和资料沉淀在任务上
- **没有这个功能，用户会怎样？** 讨论又回到聊天群，信息再度分散
- **优先级**：P1

#### Story 5：接收变更与到期提醒
- **作为** 普通成员
- **我希望** 任务被指派/状态变更时收到站内通知，截止前收到到期提醒
- **以便** 不错过与我相关的任务动态
- **没有这个功能，用户会怎样？** 重要变更被遗漏，交付延期
- **优先级**：P1

#### Story 6：首次加入项目快速上手
- **作为** 新加入项目的普通成员
- **我希望** 首次进入看板时看到空状态引导（「如何创建第一个任务」）
- **以便** 快速理解用法并开始认领任务
- **没有这个功能，用户会怎样？** 新成员上手成本高，可能放弃使用
- **优先级**：P2

### 4.3 功能清单

#### 4.3.1 任务创建与流转

##### 1. 新建任务

| 四步 | 说明 |
|------|------|
| **触发** | 成员在看板页点击「+ 新建任务」按钮，弹出创建表单；前置：已加入未归档项目 |
| **反馈** | 弹出表单弹窗，标题输入框自动聚焦；提交成功后卡片立即出现在「待处理」列并高亮 1 秒 |
| **规则** | 标题必填（1~100 字符）；指派对象只能从项目成员中选择；所属项目不可更改（跟随当前项目）；项目已归档时新建按钮置灰 |
| **循环** | 提交成功后弹窗关闭，可再次点击新建；连续创建无冷却 |

##### 2. 拖拽流转任务状态

| 四步 | 说明 |
|------|------|
| **触发** | 成员拖拽任务卡片从当前列到目标列（或点击卡片内「开始/完成」按钮） |
| **反馈** | 拖拽过程中卡片跟随鼠标并有占位提示；松手后卡片落入目标列并触发 300ms 过渡动画 |
| **规则** | 仅允许合法迁移（见 3.3 状态机）；非指派人/创建人/管理员拖拽时提示无权限；「待处理→已完成」等非法迁移被拒绝并 toast 提示原因 |
| **循环** | 迁移完成后状态立即落库；拖拽操作可连续进行，每次均触发通知 |

##### 3. 编辑与删除任务

| 四步 | 说明 |
|------|------|
| **触发** | 成员在任务详情页编辑字段（标题/描述/优先级/指派人/截止时间）或点击「删除任务」 |
| **反馈** | 编辑保存后字段即时更新并显示「已保存」；删除弹二次确认框 |
| **规则** | 普通成员仅可编辑自己创建的任务，管理员可编辑项目内任意任务；删除有评论/附件的任务需二次确认；项目归档后编辑/删除入口隐藏 |
| **循环** | 编辑可反复保存；删除确认后任务连同评论/附件一并移除，不可恢复 |

##### 异常分支

| 异常类型 | 触发条件 | 系统行为 | 用户提示 |
|---------|---------|---------|---------|
| 网络异常 | 提交/保存时断网或超时 | 保留表单内容，自动重试 2 次后放弃 | Toast「网络异常，请重试」，表单不关闭 |
| 数据异常 | 标题为空/超长；截止时间早于创建时间 | 前端校验拦截 | 字段红框 + 具体错误文案 |
| 权限异常 | 非管理员操作仅管理员可用的入口 | 隐藏入口/置灰按钮 | 无提示（隐藏）或「仅项目管理员可操作」 |
| 并发冲突 | 两人同时编辑同一任务 | 乐观锁：后保存者被拦截并提示刷新 | 弹窗「任务已被他人修改，请刷新后重试」 |
| 业务异常 | 非法状态迁移 / 指派非项目成员 | 拒绝操作 | 「请先将任务置为进行中」「该用户不在项目内」 |

##### 业务规则
- 规则 1：任务必须归属一个未归档项目，项目归档后任务只读。
- 规则 2：任务状态迁移仅允许状态机中定义的合法路径。
- 规则 3：指派人、创建人、管理员可推进任务；其余成员只读。
- 规则 4：删除任务采用二次确认，删除后数据不可恢复。

##### 全局状态

| 状态 | 呈现方式 |
|------|---------|
| 加载态 | 看板/详情页首屏 Loading 骨架屏；列表分页加载占位 |
| 空状态 | 看板列无任务时显示虚线占位 + 「拖入或新建任务」引导 |
| 错误态 | 加载失败显示错误页 + 「重试」按钮；操作失败用 Toast |
| 成功态 | 保存成功 Toast「已保存」；新建成功卡片高亮 |
| 确认操作 | 删除任务、归档项目、移除成员需二次确认 |
| 撤销操作 | 状态拖拽误操作支持 5 秒内「撤销」气泡；删除/归档不支持撤销 |

#### 4.3.2 项目创建与成员管理

##### 1. 创建项目

| 四步 | 说明 |
|------|------|
| **触发** | 管理员在项目列表页点击「+ 新建项目」 |
| **反馈** | 弹出创建表单；成功后跳转至新项目看板页 |
| **规则** | 项目名必填且平台内唯一（1~50 字符）；创建人自动成为项目管理员（owner） |
| **循环** | 创建后可继续邀请成员或新建任务；项目创建无数量限制 |

##### 2. 邀请与移除成员

| 四步 | 说明 |
|------|------|
| **触发** | 管理员在成员管理页输入邮箱/手机号发送邀请，或对已有成员点击「移除」 |
| **反馈** | 邀请发出后成员列表出现「待接受」状态；接受后转为「已加入」；移除弹二次确认 |
| **规则** | 仅管理员可邀请/移除；不可移除项目 owner；被移除成员名下未完成任务指派清空并提示重新指派 |
| **循环** | 邀请链接 7 天有效，过期可重新发送；移除后成员不可再访问项目 |

##### 3. 调整成员角色

| 四步 | 说明 |
|------|------|
| **触发** | 管理员在成员管理页将成员角色在「管理员/普通成员」间切换 |
| **反馈** | 角色切换即时生效，权限变化实时反映到各页面入口 |
| **规则** | 至少保留一名项目管理员；owner 角色不可被降级 |
| **循环** | 可反复调整；角色变更记录写入项目动态 |

##### 异常分支

| 异常类型 | 触发条件 | 系统行为 | 用户提示 |
|---------|---------|---------|---------|
| 网络异常 | 邀请/移除请求失败 | 重试 2 次后放弃，状态回滚 | Toast「操作失败，请重试」 |
| 数据异常 | 邮箱格式错误 / 邀请已存在 | 校验拦截 | 表单错误提示「邮箱格式不正确」「该成员已在项目中」 |
| 权限异常 | 普通成员访问成员管理页 | 页面不可见（IA 层已隐藏） | 无提示 |
| 并发冲突 | 两人同时调整同一成员角色 | 后提交者提示刷新 | 弹窗「成员角色已被修改，请刷新」 |
| 业务异常 | 移除项目内唯一管理员 | 拒绝移除 | 「项目需至少保留一名管理员」 |

##### 业务规则
- 规则 1：成员管理入口仅对项目管理员开放。
- 规则 2：项目至少保留一名管理员，owner 不可被移除或降级。
- 规则 3：邀请链接 7 天有效；接受后默认角色为普通成员。

##### 全局状态

| 状态 | 呈现方式 |
|------|---------|
| 加载态 | 成员列表加载骨架屏 |
| 空状态 | 无成员时显示「邀请第一位成员」引导按钮 |
| 错误态 | 邀请失败 Toast + 保留表单输入 |
| 成功态 | 邀请成功 Toast「邀请已发送」 |
| 确认操作 | 移除成员、归档项目二次确认 |
| 撤销操作 | 移除成员后 10 秒内可「撤销」恢复 |

## 五、验收标准

### AC-01：创建任务并流转至完成（正常场景）
- **Given**：普通成员已登录并加入一个未归档项目，看板页「待处理」列为空
- **When**：成员点击「新建任务」，填写标题「整理季度汇报材料」、指派给自己、点击提交，随后在看板将该卡片从「待处理」拖到「进行中」，再标记为「已完成」
- **Then**：卡片依次出现在对应列；任务详情页状态依次为 todo→in_progress→done；创建人与指派人收到状态变更通知；看板实时更新

### AC-02：断网时保存任务不丢数据（异常场景）
- **Given**：成员在任务详情页编辑描述，此时网络中断
- **When**：成员点击「保存」
- **Then**：表单内容保留不关闭；系统自动重试 2 次；重试仍失败后提示「网络异常，请重试」；网络恢复后成员可再次点击保存成功

### AC-03：并发编辑同一任务的冲突处理（异常/边界场景）
- **Given**：成员 A 与管理员 B 同时打开同一任务详情页并各自编辑描述
- **When**：A 先保存成功，B 随后点击保存
- **Then**：B 的保存被拦截，弹出「任务已被他人修改，请刷新后重试」；B 刷新后看到 A 的最新内容

### AC-04：非法状态迁移被拒绝（边界场景）
- **Given**：任务处于「待处理」状态
- **When**：成员尝试将该任务直接标记为「已完成」
- **Then**：系统拒绝该操作，Toast 提示「请先将任务置为进行中」；任务状态保持不变

### AC-05：非管理员无法访问成员管理（权限场景）
- **Given**：普通成员已登录并进入项目
- **When**：成员尝试访问成员管理页
- **Then**：成员管理入口不可见，直接访问 URL 时被重定向至看板页且无报错

### AC-06：项目归档后任务冻结（边界场景）
- **Given**：项目被管理员归档，其中包含 3 个进行中任务
- **When**：任一成员尝试新建任务或拖拽流转
- **Then**：新建按钮置灰、拖拽无效；任务详情页编辑入口隐藏，全部字段只读

## 六、数据指标

### 6.1 核心成功指标（North Star）
- **指标名**：周任务完成率
- **计算方式**：本周完成任务数 ÷ 本周应到期任务数 × 100%
- **目标值**：上线 4 周后达到 85%
- **数据来源**：任务表状态埋点 + 数据看板

### 6.2 过程指标

| 指标名 | 计算方式 | 基准值 | 目标值 | 数据来源 |
|-------|---------|-------|-------|---------|
| 任务按时完成率 | 在 due_at 前完成的任务 ÷ 全部完成任务 | 无（新品） | ≥ 80% | 任务表 |
| 平均流转时长 | 任务从创建到完成的中位时长 | 无 | ≤ 5 天 | 任务表 |
| 成员周活跃度 | 周内有任务操作（创建/流转/评论）的成员占比 | 无 | ≥ 70% | 操作埋点 |
| 看板使用率 | 周内访问看板页的成员占比 | 无 | ≥ 90% | 页面埋点 |
| 首次任务创建时长 | 新成员从加入项目到创建首个任务的时间 | 无 | ≤ 1 天 | 事件埋点 |

### 6.3 异常告警阈值

| 监控项 | 告警条件 | 告警级别 | 处理 SOP |
|-------|---------|---------|---------|
| 任务保存失败率 | 保存/流转接口失败率 > 5% 持续 10 分钟 | P1 | 检查服务日志 → 定位接口错误 → 回滚最近发布 |
| 看板首屏耗时 | 首屏 P95 耗时 > 3s 持续 15 分钟 | P2 | 检查接口耗时与数据库慢查询 → 优化索引/缓存 |
| 通知投递延迟 | 状态变更通知延迟 > 5s 占比超 10% | P2 | 检查通知队列积压 → 扩容消费者 |
| 任务数据异常 | 同一任务状态在 1 分钟内变更超 10 次 | P2 | 排查脚本/异常调用 → 封禁异常来源 |
