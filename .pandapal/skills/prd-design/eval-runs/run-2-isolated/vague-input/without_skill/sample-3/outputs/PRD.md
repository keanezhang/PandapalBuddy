# PRD：PandaPal Buddy 桌面端「会话管理增强」

| 字段 | 内容 |

---

## 1. 背景与问题

PandaPal Buddy 定位为企业级 Python Agent 框架，核心理念是「让 Agent 的每一步都看得见、管得住」。当前桌面端已具备基础会话交互能力（流式打字机、HITL 审批、IPC 桥接本地 sidecar 后端），但会话生命周期管理能力薄弱，具体痛点如下：

1. **会话不可检索**：历史会话仅停留在当次运行的内存中，重启后无法按关键词/时间回溯，审计与复盘成本高。
2. **会话易丢失**：缺少显式的持久化与归档机制，重要对话（如 HITL 审批结论、排障过程）没有可靠的留痕通道。
3. **协作与交接困难**：无法将会话导出为可分享的格式（Markdown / JSON / PDF），团队成员间知识传递依赖人工复制粘贴。
4. **观测与记忆割裂**：`pandaren` 已有 `AuditLog`、`Tracer`、`LongTermMemory` 等能力，但桌面端没有统一的会话视图把这些信息串起来，违背「看得见、管得住」的产品承诺。

本 PRD 旨在通过「会话管理增强」补齐上述缺口，使会话成为可检索、可归档、可导出、可审计的一等公民。

---

## 2. 目标与非目标

### 2.1 目标（Goals）

- **G1**：会话自动持久化到本地，重启应用后会话完整可恢复。
- **G2**：提供会话列表 + 全文搜索，支持按时间、按 Agent、按 HITL 状态过滤。
- **G3**：支持会话归档（不删除、只移出默认列表）与一键导出（Markdown / JSON）。
- **G4**：会话视图与观测数据打通（关键步骤、工具调用、HITL 审批记录可回看）。
- **G5**：企业场景下的留痕与合规：所有会话数据可导出审计包。

### 2.2 非目标（Non-Goals）

- 不做多用户/多设备间的会话云同步（属于后续版本，依赖 `pandapal_relay` 的账号体系）。
- 不做会话内消息的编辑/删除（保持审计完整性，与 HC4「AuditLog 不可关闭」一致）。
- 不做对话内容的摘要/总结生成（独立能力，另行评估）。
- 不改变现有 IPC 协议与 Agent 调度核心逻辑。

## 3. 用户与使用场景

| 角色 | 描述 | 核心诉求 |
|------|------|----------|
| 企业开发者 | 使用 SDK 构建内部 Agent 的工程师 | 回看排障过程、复用历史提示词、导出会话给同事 |
| 运维/审计人员 | 负责合规与安全审计 | 导出不可篡改的会话审计包、追溯 HITL 审批结论 |
| 普通业务用户 | 通过桌面端与 Agent 协作的终端用户 | 快速找回上次的对话、不丢失重要上下文 |

**典型场景**：

- **S1（找回上下文）**：用户上周与 Agent 讨论过某部署方案，本周重启电脑后想继续，可在搜索框输入关键词定位并继续会话。
- **S2（审计留痕）**：审计人员需要导出某次涉及敏感工具调用（高权限 DEFERRED 工具）的完整会话记录，含审批人、审批时间、审批结果。
- **S3（知识交接）**：开发者将一段 Agent 调试会话导出为 Markdown，附在工单/文档中传给同事。
- **S4（合规清理）**：管理员按企业保留策略归档超过 180 天的会话。

## 4. 需求详述

### 4.1 功能需求（Functional Requirements）

**FR1：会话持久化**
- FR1.1 每条会话在首次产生消息时即在本地持久化（写入应用数据目录，参考 `--app-data-dir` 机制）。
- FR1.2 会话元数据与消息正文分离存储：元数据（会话 ID、标题、创建/更新时间、Agent 标识、HITL 状态）走轻量索引；消息正文按 JSON Lines 追加写。
- FR1.3 应用启动时自动恢复会话索引，桌面端会话列表在 500ms 内可渲染（见 NFR2）。
- FR1.4 会话标题默认取首条用户消息的前 24 个字符，允许用户重命名。

**FR2：会话列表与搜索**
- FR2.1 左侧边栏提供会话列表，支持分组视图：按日期（今天/昨天/近 7 天/更早）与按状态（进行中/已归档）。
- FR2.2 顶部搜索框支持全文检索（消息内容 + 标题），支持过滤器：时间范围、Agent 名称、是否含 HITL 审批。
- FR2.3 搜索结果高亮命中片段，点击即定位到会话内对应消息。
- FR2.4 搜索在本地完成，不将会话内容上传云端（离线可用）。

**FR3：会话归档与恢复**
- FR3.1 用户可归档/取消归档会话；归档仅改变可见性，不删除数据。
- FR3.2 提供「全部归档」与「批量归档」操作，批量操作需二次确认。
- FR3.3 归档会话可在「已归档」视图中检索与恢复。

**FR4：会话导出**
- FR4.1 支持导出为 Markdown（含时间戳、角色、工具调用摘要）与 JSON（完整结构化，含元数据、消息、HITL 记录、观测事件引用）。
- FR4.2 导出为 JSON 时附带 SHA-256 校验清单，供审计比对（满足 G5）。
- FR4.3 导出为 Markdown 时提供「仅对话」「含工具调用详情」两种粒度选项。

**FR5：会话与观测打通**
- FR5.1 会话详情页支持按流式事件类型（`StreamEventType` 16 种）筛选回看关键节点（LLM 请求、工具调用、HITL 审批、异常熔断）。
- FR5.2 HITL 审批记录（请求时间、审批人、结论、备注）在会话时间轴中可视化展示，不可编辑。
- FR5.3 会话视图提供「关联审计日志」入口，跳转到对应 `AuditLog` 片段。

**FR6：数据与权限**
- FR6.1 会话数据仅保存在本机应用数据目录，遵循现有 `.env` / 权限模型，不新增网络传输。
- FR6.2 会话存储写入失败时，Agent 主流程不受影响（非阻塞），仅提示用户。

### 4.2 非功能需求（Non-Functional Requirements）

| 编号 | 维度 | 要求 |
|------|------|------|
| NFR1 | 性能 | 万级消息量下，列表滚动与消息渲染保持 60fps；搜索响应 < 300ms（10 万条消息量级） |
| NFR2 | 启动 | 应用冷启动到会话列表可交互 < 1.5s（含索引恢复） |
| NFR3 | 可靠性 | 会话写入采用追加写 + 周期性 flush；异常断电最多丢失最后 1 条消息 |
| NFR4 | 安全 | 会话数据本地加密存储（可选开关）；导出文件不含 API Key 等敏感凭据（脱敏） |
| NFR5 | 兼容 | 后端协议向后兼容：不支持会话管理的旧版后端可降级为「仅当前会话」模式 |
| NFR6 | 可维护 | 新增模块遵循现有分层（桌面端 UI / IPC / 后端存储），核心逻辑放后端便于复用 |

## 5. 用户故事

- 作为企业开发者，我希望重启应用后还能找到上周的排障会话，以便继续调试，而不必重新描述上下文。
- 作为审计人员，我希望一键导出带审批记录的完整会话 JSON 及校验清单，以便完成合规审计。
- 作为业务用户，我希望把误操作的会话归档而不是删除，以便需要时还能找回。
- 作为管理员，我希望本地全文搜索不依赖网络，以便在内网离线环境使用。

## 6. 关键交互与数据流

### 6.1 会话生命周期

```
新建会话 → 首条消息触发持久化 → 消息流式追加（IPC JSON Lines）→ 会话更新（标题/时间/HITL状态）
   → 用户归档 / 恢复 → 用户导出（Markdown/JSON）→ 按保留策略清理（可选）
```

### 6.2 数据流（变更点）

- **现状**：桌面端 ↔ `pandapal` 后端通过 stdin/stdout JSON Lines IPC 交互；消息仅存在于当次运行内存，无持久化。
- **变更后**：
  1. `pandapal` 后端新增 `SessionStore` 模块，消费 AgentLoop 产生的流式事件（`pandaren/engine/stream.py`），把消息与关键事件追加写入本地存储；
  2. 桌面端通过新增 IPC 消息（`session.list`、`session.search`、`session.archive`、`session.export`）与后端交互，不在前端落盘业务数据；
  3. 导出与审计数据直接由后端读取 `SessionStore` + `AuditLog` 生成，保证单一数据源。

### 6.3 模块归属建议

| 变更点 | 归属 | 说明 |
|--------|------|------|
| `SessionStore`（持久化/索引/搜索） | `pandapal` 后端 | 复用现有 app-data-dir 与日志基础设施 |
| IPC 协议扩展（session.* 消息） | `pandapal` 后端 + `pandapal_desktop` | 遵循现有 JSON Lines 协议 |
| 会话列表 UI / 搜索框 / 详情时间轴 | `pandapal_desktop`（React） | 新增页面组件与状态管理 |
| 导出生成（MD/JSON + 校验清单） | `pandapal` 后端 | 读取 `SessionStore` + `AuditLog` |
| 敏感信息脱敏 | `pandapal` 后端 | 导出前过滤凭据字段 |

## 7. 验收标准（含指标）

1. **P1（持久化恢复）**：新建会话产生 ≥ 3 条消息后强杀进程，重启应用会话完整恢复，消息零丢失。
2. **P2（搜索）**：在 10 万条消息的测试库中，关键词搜索 P95 延迟 < 300ms，命中结果高亮正确。
3. **P3（导出审计）**：导出 JSON 后按 SHA-256 校验清单逐项比对，全部通过；导出文件中不存在 `api_key` / `token` / `secret` 等敏感字段（脱敏验证）。
4. **P4（HITL 回看）**：含审批记录的会话，时间轴中审批人、时间、结论与 `AuditLog` 记录完全一致，且不可编辑。
5. **P5（降级兼容）**：旧版后端（不支持 session.*）接入时，桌面端自动降级为「仅当前会话」，不报错、不丢功能。
6. **P6（性能）**：冷启动到列表可交互 < 1.5s；万级消息列表滚动不掉帧。

| 里程碑 | 内容 | 预估周期 |
|--------|------|----------|
| M1：MVP | FR1 持久化 + FR2 列表/搜索（本地）+ FR4 Markdown 导出 | 2 周 |
| M2：增强 | FR3 归档/恢复 + FR4 JSON 导出与校验 + FR5 观测打通 | 2 周 |
| M3：打磨 | 脱敏、性能优化（NFR）、降级兼容、批量操作与二次确认 | 1 周 |

## 9. 风险与依赖

| 风险/依赖 | 等级 | 应对 |
|-----------|------|------|
| 本地全文搜索在超大库下性能不达标 | 中 | 预研 SQLite FTS5 / 倒排索引方案，设置 NFR1 兜底阈值 |
| 会话存储与 `AuditLog` 数据一致性 | 中 | 以 `AuditLog` 为审计事实源，`SessionStore` 为展示层缓存，导出时交叉校验 |
| 敏感信息误入导出文件 | 高 | 导出前统一脱敏管线 + 自动化脱敏测试（P3） |
| 与现有 IPC 协议兼容 | 低 | 新增消息使用独立命名空间 `session.*`，旧字段不动 |
| 依赖 `pandaren` 流式事件结构稳定 | 低 | 只在 `pandapal` 层消费事件，不侵入 `pandaren` 核心 |

## 附录 A：术语

- **HITL**：Human-in-the-Loop，人工审批介入 Agent 执行流程。
- **IPC**：桌面端与后端 sidecar 之间的 stdin/stdout JSON Lines 进程间通信。
- **AuditLog**：`pandaren/observability/` 提供的不可关闭审计日志。
- **StreamEventType**：`pandaren/engine/stream.py` 定义的 16 种流式事件类型。
