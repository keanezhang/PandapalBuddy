# PRD · 连锁奶茶店会员积分系统

> 版本：v1.0 | 日期：2026-08-10 | 复杂度：中等

---

## 一、概述与背景

##### 背景
连锁奶茶门店目前缺乏统一的会员积分体系，顾客消费后无积分激励，复购与留存全靠促销活动驱动；各门店积分发放与兑换依靠人工登记，账目易错、数据分散，店长无法实时掌握本店积分经营情况。

##### 目标
- 目标 1：顾客每消费 1 元自动累积 1 积分（比例可由店长调整），积分实时到账，上线 12 周后会员复购率提升 15%。
- 目标 2：积分兑换饮品/优惠券全流程线上化，兑换成功率 ≥ 99%，积分账目误差 < 0.1%。
- 目标 3：店长可自助配置本店积分规则，并实时（T+0）查看本店积分发放与兑换报表。

##### 角色清单

| 角色 | 职责 | 核心诉求 |
|------|------|---------|
| 顾客（会员） | 到店消费时累积积分，使用积分兑换饮品或优惠券 | 积分真实到账、兑换顺畅、权益可核销 |
| 店长 | 配置本店积分规则，查看本店积分发放与兑换情况 | 规则可自助调整、数据实时准确 |

##### 场景清单

### 场景 1：顾客到店消费累积积分（核心）

- **发生时态**：日常
- **角色**：顾客
- **目标**：支付完成后积分自动、实时到账
- **前置条件**：顾客已注册会员并绑定手机号；门店 POS 已接入积分系统

### 场景 2：顾客使用积分兑换饮品或优惠券（核心）

- **发生时态**：日常
- **角色**：顾客
- **目标**：用积分换取饮品/优惠券，并到店核销使用
- **前置条件**：账户积分 ≥ 兑换所需积分；兑换项有库存且在有效期

### 场景 3：店长设置积分规则（核心）

- **发生时态**：首次/日常
- **角色**：店长
- **目标**：按本店经营策略配置积分累积比例与兑换项
- **前置条件**：店长已登录后台且拥有本店配置权限

### 场景 4：店长查看本店积分报表（核心）

- **发生时态**：日常
- **角色**：店长
- **目标**：掌握本店积分发放与兑换情况，支撑经营决策
- **前置条件**：店长已登录后台；本店已有积分流水数据

> 异常/边界场景（积分不足、网络中断、并发兑换、核销码重复使用等）在 4.3 异常分支与第五章验收标准中展开覆盖。

##### 场景-角色矩阵

| 场景 | 角色 | 核心/边缘 | 发生时态 |
|------|------|----------|---------|
| 顾客到店消费累积积分 | 顾客 | 核心 | 日常 |
| 顾客兑换饮品/优惠券 | 顾客 | 核心 | 日常 |
| 店长设置积分规则 | 店长 | 核心 | 首次/日常 |
| 店长查看积分报表 | 店长 | 核心 | 日常 |

### 3.2 业务链路

#### 核心链路 1：顾客消费 → 积分发放

```text
┌──────────────┐  支付成功事件   ┌──────────────┐  消费金额+门店规则  ┌──────────────┐
│  POS收银系统  │ ─────────────► │  积分发放模块  │ ────────────────► │  积分账户     │
└──────────────┘                └──────┬───────┘                   └──────┬───────┘
                                       │                                  │
                                       │ <异常：发放失败>                   │ 余额+积分，记流水
                                       ▼                                  ▼
                                ┌──────────────┐                   ┌──────────────┐
                                │ 失败重试队列   │                   │  积分变动明细  │
                                └──────────────┘                   └──────────────┘
```

**链路说明**：POS 支付成功后推送支付事件 → 积分发放模块按「本店累积规则（默认 1 元=1 积分，向下取整）」计算积分 → 更新会员账户余额并生成积分流水（状态=可使用）→ 会员端实时可见。发放失败进入重试队列（≤3 次），仍失败则告警并进入人工补录队列。

#### 核心链路 2：顾客积分兑换 → 门店核销

```text
┌──────────────┐  选择兑换项     ┌──────────────┐  校验余额并扣减  ┌──────────────┐
│  会员端兑换页  │ ─────────────► │  兑换模块      │ ─────────────► │  积分账户     │
└──────────────┘                └──────┬───────┘                  └──────┬───────┘
                                       │                                  │
                                       │ <异常：积分不足/并发冲突>          │ 扣减成功，生成订单
                                       ▼                                  ▼
                                ┌──────────────┐                   ┌──────────────┐
                                │ 兑换失败提示   │                   │  兑换订单     │
                                └──────────────┘                   └──────┬───────┘
                                                                          │ 到店出示核销码
                                                                          ▼
                                                                   ┌──────────────┐
                                                                   │  门店核销     │
                                                                   └──────────────┘
```

**链路说明**：顾客在兑换商城选择饮品/优惠券 → 兑换模块校验余额充足并做并发安全扣减（乐观锁）→ 原子生成「待核销」兑换订单（含唯一核销码）→ 顾客到店出示核销码 → 店长核销后订单变更为「已核销」，权益发放。

### 3.3 状态流转

#### 积分流水状态机（积分生命周期）

```text
        ┌──────────┐   兑换成功    ┌──────────┐
  ────► │  可使用   │ ───────────► │  已使用   │
        └─────┬────┘              └──────────┘
              │
              ├── 超过有效期（默认12个月）──► ┌──────────┐
              │                              │  已过期   │
              └── 差错人工撤销 ──────────────► └──────────┘
                                             ┌──────────┐
                                             │  已撤销   │
                                             └──────────┘
```

##### 状态定义

| 状态 | 含义 | 允许的下一状态 | 触发迁移的动作/条件 |
|------|------|---------------|-------------------|
| 可使用 | 积分已发放到账、可参与兑换 | 已使用, 已过期, 已撤销 | 顾客兑换；超过有效期；差错人工撤销 |
| 已使用 | 积分已用于兑换并核销 | — | 兑换订单核销成功 |
| 已过期 | 超过有效期未使用 | — | 有效期（默认 12 个月）届满 |
| 已撤销 | 因差错/投诉人工撤销 | — | 总部/超管审批后调账 |

##### 非法迁移

| 从 | 到 | 拒绝原因 | 系统行为 |
|----|-----|---------|---------|
| 已使用 | 可使用 | 积分已消费不可回退 | 拒绝，需走人工调账审批 |
| 已过期 | 可使用 | 过期积分不可恢复 | 拒绝，提示走人工申诉 |

#### 兑换订单状态机

```text
        ┌──────────┐   顾客取消    ┌──────────┐
        │  已取消   │ ◄─────────── │          │
        └──────────┘              │  待核销   │
        ┌──────────┐   超时未核销  │          │
        │  已过期   │ ◄─────────── │          │
        └──────────┘              └────┬─────┘
                                       │ 门店核销成功
                                       ▼
                                 ┌──────────┐
                                 │  已核销   │
                                 └──────────┘
```

##### 状态定义

| 状态 | 含义 | 允许的下一状态 | 触发迁移的动作/条件 |
|------|------|---------------|-------------------|
| 待核销 | 兑换成功生成核销码，等待门店核销 | 已核销, 已取消, 已过期 | 店长核销；顾客取消（核销前）；超过凭证有效期 |
| 已核销 | 门店已核销，权益已发放 | — | 店长在核销页完成核销 |
| 已取消 | 顾客主动取消 | — | 顾客在待核销状态下取消 |
| 已过期 | 超时未核销 | — | 超过凭证有效期（默认 72 小时） |

##### 非法迁移

| 从 | 到 | 拒绝原因 | 系统行为 |
|----|-----|---------|---------|
| 已核销 | 待核销 | 核销码已使用不可重复核销 | 拒绝，提示核销码无效 |
| 已取消 | 已核销 | 已取消订单不可核销 | 拒绝，提示订单已取消 |

| redeem_code | string | ✅ | 唯一，8 位 | 核销码 | 系统生成 |
| created_at | datetime | ✅ | — | 创建时间 | 系统生成 |
| redeemed_at | datetime | ❌ | — | 核销时间（已核销时必有） | 系统生成 |
| expires_at | datetime | ✅ | 创建后 72 小时 | 凭证有效期 | 系统计算 |

#### 积分规则（points_rule）

| 字段名 | 类型 | 必填 | 约束/取值域 | 业务含义 | 来源 |
|-------|------|-----|-------------|---------|------|
| rule_id | string | ✅ | 唯一 | 规则 ID | 系统生成 |
| store_id | string | ✅ | 引用门店，唯一 | 适用门店 | 上游模块 |
| earn_ratio | decimal | ✅ | >0，默认 1.0 | 1 元消费对应积分 | 店长配置 |
| expire_months | int | ✅ | 1~36，默认 12 | 积分有效期（月） | 店长配置 |
| redeem_enabled | bool | ✅ | — | 是否开启积分兑换 | 店长配置 |
| updated_by | string | ✅ | 引用店长账号 | 最后修改人 | 系统生成 |
| updated_at | datetime | ✅ | — | 最后修改时间 | 系统生成 |

**字段命名约定**：所有 ID 用 `xxx_id`，时间戳用 `xxx_at`，布尔值用 `is_xxx` / `xxx_enabled`，状态用 `status` 枚举。

**跨对象引用**：

| 引用字段 | 指向对象 | 引用类型 | 级联行为 |
|---------|---------|---------|---------|
| member_id（流水/订单） | member_account | 多对 1 | 会员注销时流水保留、账户冻结 |
| store_id（规则/流水） | 门店 | 多对 1 | 门店关闭后规则失效、历史流水保留 |
| biz_ref | 支付订单/兑换订单 | 1 对 1 | 不做级联删除 |

### 3.5 流转规则

| 规则 | 触发条件 | 行为 |
|------|---------|------|
| 积分发放规则 | POS 支付成功且会员已绑定 | 发放积分 = floor(实付金额 × earn_ratio)，向下取整 |
| 积分有效期规则 | 距发放满 expire_months | 到期积分批量转「已过期」，余额同步扣减 |
| 兑换扣减规则 | 顾客提交兑换 | 校验 balance ≥ points_cost，乐观锁防并发超扣 |
| 凭证核销规则 | 店长输入/扫描核销码 | 校验订单状态=pending 且未过期，核销后置为 redeemed |
| 取消退款规则 | 顾客取消待核销订单 | 订单置 cancelled，积分原路退回（流水 type=revoke） |

## 四、需求详细描述

### 4.1 背景与目标

本期聚焦打通「消费 → 积分 → 兑换 → 核销」闭环：让顾客积分可见可用、店长规则可配、数据实时可查，为后续总部运营与营销活动打基础。

##### 本期范围

- ✅ 包含：会员积分账户与明细、消费积分自动发放、积分兑换饮品/优惠券、门店核销、店长规则配置、店长本店报表
- ❌ 不包含：总部管理端/跨门店汇总报表、积分商城商品供应链、营销活动（满减/生日券等）、积分转赠、跨品牌积分联盟

### 4.2 用户故事

#### Story 1：消费自动累积积分

- **作为** 顾客
- **我希望** 在门店消费支付后，积分自动按规则到账，并在会员端看到余额变化
- **以便** 无需额外操作即可累积积分、感知积分价值
- **没有这个功能，用户会怎样？** 积分激励形同虚设，顾客无累积动力，复购率无法提升
- **优先级**：P0

#### Story 2：积分兑换饮品/优惠券

- **作为** 顾客
- **我希望** 用账户积分兑换门店饮品或优惠券，并到店出示核销码使用
- **以便** 积分能立即变成实际权益
- **没有这个功能，用户会怎样？** 积分只能看不能用，会员失去留存动力
- **优先级**：P0

#### Story 3：店长配置积分规则

- **作为** 店长
- **我希望** 在后台设置本店「1 元=？积分」、兑换项与积分有效期
- **以便** 按本店毛利与营销策略调节积分成本
- **没有这个功能，用户会怎样？** 规则固定死板，门店无法灵活运营，规则变更只能人工改系统
- **优先级**：P0

#### Story 4：店长查看本店积分报表

- **作为** 店长
- **我希望** 实时查看本店积分发放量、兑换量与兑换明细
- **以便** 掌握积分成本与兑换偏好，调整经营策略
- **没有这个功能，用户会怎样？** 积分账目不透明，门店无法评估活动效果
- **优先级**：P1

#### Story 5：异常时积分不丢失

- **作为** 顾客
- **我希望** 网络中断/系统异常时消费积分不丢失，恢复后自动补发
- **以便** 信任积分系统的可靠性
- **没有这个功能，用户会怎样？** 积分丢失引发投诉，损害品牌信任
- **优先级**：P1

### 4.3 功能清单

#### 4.3.1 消费积分累积

##### 1. POS 结账触发积分发放

| 四步 | 说明 |
|------|------|
| **触发** | 顾客在 POS 完成支付且已绑定会员（报手机号/扫码），系统收到支付成功事件 |
| **反馈** | 收银端显示「本次获得 X 积分」；会员端积分余额更新并推送到账通知 |
| **规则** | 仅「支付成功」事件触发；发放积分 = floor(实付金额 × 本店 earn_ratio)；同一订单只发放一次（幂等） |
| **循环** | 每笔新消费独立触发，无冷却；可连续累积 |

##### 2. 积分到账通知

| 四步 | 说明 |
|------|------|
| **触发** | 积分发放成功写入账户后 |
| **反馈** | 小程序推送/短信通知「到账 X 积分，当前余额 Y」 |
| **规则** | 通知按日合并避免骚扰；支持静默时段设置 |
| **循环** | 每次发放触发一次，用户可关闭通知 |

##### 异常分支

| 异常类型 | 触发条件 | 系统行为 | 用户提示 |
|---------|---------|---------|---------|
| 网络异常 | 支付成功事件推送超时/断网 | 进入重试队列（≤3 次，间隔递增）；仍失败告警并次日人工补录 | 会员端静默，补发后通知 |
| 数据异常 | 会员未绑定/手机号无效 | 拦截发放，标记「待绑定」 | 收银端提示「请先绑定会员」 |
| 权限异常 | 非本店 POS 设备上报 | 拒绝并记录审计 | 静默 + 告警 |
| 并发冲突 | 同一订单重复推送 | 幂等校验，重复事件直接丢弃 | 无 |
| 业务异常 | 实付金额为 0 / 退款单 | 不发放积分；退款订单按原单冲正 | 退款通知中说明 |

##### 业务规则

- 规则 1：积分按实付金额（优惠/折扣后）为基数计算，向下取整。
- 规则 2：同一支付订单仅发放一次，重试不重复发放。
- 规则 3：退款/退货时按原单冲正（type=revoke，负数流水）。
- 规则 4：积分默认有效期 12 个月（店长可配 1~36 个月），过期自动失效并从余额扣除。

##### 全局状态

| 状态 | 呈现方式 |
|------|---------|
| 加载态 | 会员端积分页骨架屏；收银端发放中显示 loading |
| 空状态 | 无积分记录时显示「去消费赚积分」引导 |
| 错误态 | 发放失败收银端 Toast「积分发放失败，将自动重试」 |

## 五、验收标准

### AC-01：消费自动累积积分（正常场景）

- **Given**：会员已绑定，POS 已接入，本店规则为 1 元=1 积分
- **When**：顾客实付 35 元完成支付
- **Then**：账户积分增加 35，流水 type=earn、状态=可使用，会员端实时可见，到账通知送达

### AC-02：积分不足兑换失败（异常场景）

- **Given**：账户余额 50 积分，兑换饮品需 100 积分
- **When**：顾客点击「立即兑换」并确认
- **Then**：兑换被拦截，积分不变，提示「积分不足，还差 50 积分」，不生成订单

### AC-03：并发兑换防超扣（边界场景）

- **Given**：账户余额 100 积分，两件商品各需 100 积分
- **When**：顾客在 A/B 两台设备同时提交兑换
- **Then**：仅一笔兑换成功，另一笔失败并提示「积分余额已变化，请刷新后重试」，最终余额为 0，无负余额

### AC-04：规则修改即时生效（正常场景）

- **Given**：店长将累积比例从 1.0 改为 1.5
- **When**：保存成功后顾客消费 10 元
- **Then**：本次发放 15 积分；修改前已发放积分不受影响；修改记录留痕

### AC-05：发放失败自动重试（异常场景）

- **Given**：POS 支付成功事件因网络中断未能送达积分系统
- **When**：网络恢复后
- **Then**：系统自动重试（≤3 次）完成发放，积分不丢失、不重复发放；仍失败则告警并进入人工补录队列

### AC-06：核销码一次性（边界场景）

- **Given**：兑换订单处于待核销状态
- **When**：店长核销成功后，再次输入同一核销码
- **Then**：第二次核销被拒绝，提示「核销码无效」，订单保持已核销

## 六、数据指标

### 6.1 核心成功指标（North Star）

- **指标名**：积分兑换率（月）
- **计算方式**：当月消耗积分 ÷ 当月发放积分 × 100%
- **目标值**：上线 12 周后 ≥ 25%
- **数据来源**：积分流水表（type=redeem / type=earn）

### 6.2 过程指标

| 指标名 | 计算方式 | 基准值 | 目标值 | 数据来源 |
|-------|---------|-------|-------|---------|
| 积分发放成功率 | 成功发放单 ÷ 支付成功单 | 人工登记 ~90% | ≥ 99.9% | 发放流水 |
| 积分到账时长 | P95（支付成功→余额可见） | 无 | < 5 秒 | 埋点 |
| 兑换成功率 | 兑换成功 ÷ 兑换请求 | 无 | ≥ 99% | 兑换日志 |
| 兑换核销率 | 已核销订单 ÷ 已生成订单 | 无 | ≥ 80% | 兑换订单表 |
| 会员积分活跃率 | 月内有积分变动的会员 ÷ 活跃会员 | 无 | ≥ 60% | 积分流水 |
| 门店规则配置完成率 | 已配置规则门店 ÷ 上线门店 | 无 | 100% | 规则表 |

### 6.3 异常告警阈值

| 监控项 | 告警条件 | 告警级别 | 处理 SOP |
|-------|---------|---------|---------|
| 积分发放失败率 | 单门店单日 > 1% 或连续 10 单失败 | P0 | 检查 POS 事件通道与重试队列，人工补录 |
| 积分账目对账 | 余额与流水汇总差异 > 0.1% | P0 | 冻结发放，拉取流水对账，定位差异单 |
| 兑换接口错误率 | > 1% 持续 5 分钟 | P1 | 检查兑换服务与数据库，必要时降级为只读 |
| 报表数据延迟 | T+0 报表延迟 > 10 分钟 | P2 | 检查聚合任务，触发重跑 |

### 6.4 上线检查清单
