## 1. 文档目的

本文档定义连锁奶茶店会员积分系统的完整产品需求，包括积分获取、积分兑换、积分规则设置、门店积分数据查询等核心功能，供研发、测试、运营及门店管理人员参考与评审。

## 2. 项目背景

### 2.1 业务背景

- 公司旗下拥有多家连锁奶茶门店，顾客消费频次高、客单价相对较低，适合通过积分体系提升复购率与顾客忠诚度。
- 当前各门店无统一会员积分体系，顾客跨店消费无法累计积分，店长无法了解本店积分运营情况。
- 需要一套总部统一管理、门店灵活运营的会员积分系统。

### 2.2 项目目标

1. 建立统一的会员积分账户体系，支持顾客跨店累积与使用积分。
2. 通过积分兑换饮品/优惠券，提升顾客复购与客单价。
3. 店长可在后台查看本店积分发放/兑换明细，并配置本店积分规则。
4. 为总部提供积分运营数据，支持后续精细化运营。

### 2.3 成功指标（核心 KPI）

| 指标 | 说明 | 目标 |
| --- | --- | --- |
| 会员开卡率 | 新增会员占门店订单比例 | ≥ 40% |
| 积分兑换率 | 已发放积分中被兑换的比例 | ≥ 30% |
| 复购率提升 | 开通会员后 30 天复购率较开通前 | +15% |
| 门店积分规则配置率 | 已配置积分规则的门店占比 | 100%（上线 1 个月内） |

## 3. 用户角色与权限

| 角色 | 描述 | 核心权限 |
| --- | --- | --- |
| 顾客（C 端会员） | 到店消费的普通用户 | 查看积分余额/明细、领取会员卡、兑换饮品/优惠券、查看优惠券 |
| 店长（单店） | 单店管理者 | 查看本店积分发放/兑换明细、设置本店积分规则、上下架本店兑换商品 |
| 总部运营/管理员（中心） | 总部运营人员 | 全局规则配置、积分商品库管理、数据看板、门店管理、审计 |

权限原则：店长仅能访问**本店**数据，不可跨店查看；总部可查看全部门店数据。

## 4. 术语定义

| 术语 | 定义 |
| --- | --- |
| 积分 | 顾客消费/活动获得的可用于兑换的虚拟货币，仅可兑换不可提现 |
| 积分账户 | 顾客在系统内的积分余额账户，全渠道统一 |
| 积分规则 | 定义消费金额与积分的换算关系（如 1 元 = 1 积分）及上下限 |
| 兑换商品 | 可使用积分兑换的饮品券/优惠券/实物等 |
| 积分明细 | 每笔积分增加/扣减的流水记录 |
| 优惠券 | 兑换后获得的折扣券/满减券/赠饮券等 |

## 5. 总体功能架构

```
会员积分系统
├── 顾客端小程序
│   ├── 会员卡（开卡、展示积分余额、二维码）
│   ├── 积分明细（流水查询）
│   ├── 积分商城（积分兑换）
│   └── 我的卡券（优惠券列表、核销状态）
├── 门店管理后台（店长）
│   ├── 积分规则设置
│   ├── 积分发放/兑换记录查询
│   ├── 兑换商品管理（本店）
│   └── 数据概览（本店）
└── 中心管理平台（总部）
    ├── 全局积分规则配置
    ├── 商品库/券模板管理
    ├── 门店管理
    ├── 会员管理
    └── 数据看板与审计
```

## 6. 功能需求

### 6.1 会员注册与开卡（顾客端）

| 编号 | 需求描述 | 优先级 |
| --- | --- | --- |
| FR-1.1 | 顾客可通过微信授权手机号完成会员注册，系统自动生成唯一会员 ID 并开通积分账户 | P0 |
| FR-1.2 | 会员卡展示：会员姓名/昵称、会员等级、当前积分余额、累计积分、二维码（用于门店识别） | P0 |
| FR-1.3 | 同一顾客跨门店消费时积分统一累计到同一账户 | P0 |
| FR-1.4 | 顾客可查看积分明细，包括时间、门店、业务类型（消费/兑换/活动/过期/调整）、积分变动数、余额 | P0 |

### 6.2 积分获取

| 编号 | 需求描述 | 优先级 |
| --- | --- | --- |
| FR-2.1 | 顾客到店消费（出示会员码或报手机号）后，按门店积分规则计算积分并发放 | P0 |
| FR-2.2 | 默认规则：1 元 = 1 积分，积分向下取整（如消费 15.8 元得 15 积分） | P0 |
| FR-2.3 | 积分发放时效：支付完成后实时到账；支持 T+0 实时到账与 T+1 结算两种模式（门店可配置） | P1 |
| FR-2.4 | 积分发放上限：单笔订单最高可获积分上限（默认 1000，可配置），防止异常大额发放 | P1 |
| FR-2.5 | 退款处理：整单退款时回收对应积分；部分退款按退款金额比例回收积分 | P0 |
| FR-2.6 | 支持总部配置的活动积分（如生日双倍积分、节日活动加赠），活动积分可设置有效期 | P2 |
| FR-2.7 | 积分有效期：默认永久有效；总部可开启"积分有效期"策略（如 12 个月滚动过期），过期积分自动扣减并记录明细 | P1 |

### 6.3 积分兑换

| 编号 | 需求描述 | 优先级 |
| --- | --- | --- |
| FR-3.1 | 顾客可在积分商城中浏览可兑换商品（饮品券、优惠券、实物），商品展示所需积分、库存、适用门店 | P0 |
| FR-3.2 | 顾客提交兑换时校验积分余额是否充足，不足则提示并引导充值/消费获取积分 | P0 |
| FR-3.3 | 兑换成功后即时扣减积分，生成兑换记录与卡券（券有唯一码与有效期） | P0 |
| FR-3.4 | 兑换订单支持取消：未使用的券在有效期内可申请取消兑换并退回积分（需门店/客服审核） | P1 |
| FR-3.5 | 饮品券/优惠券到店使用时由店员核销，核销后不可再次使用 | P0 |
| FR-3.6 | 防刷机制：同一顾客短时间高频兑换需触发风控校验（如频率限制、设备限制） | P1 |

兑换商品类型示例：

| 商品类型 | 示例 | 兑换所需积分（示例） |
| --- | --- | --- |
| 饮品券 | 招牌奶茶 1 杯（中杯） | 300 积分 |
| 满减券 | 满 20 减 5 元券 | 200 积分 |
| 折扣券 | 全场 9 折券 | 150 积分 |
| 赠饮券 | 第二杯半价券 | 250 积分 |
| 实物（可选） | 定制杯/帆布袋 | 2000 积分 |

> 注：以上积分面值为示例，实际由门店/总部配置。

### 6.4 积分规则设置（店长）

| 编号 | 需求描述 | 优先级 |
| --- | --- | --- |
| FR-4.1 | 店长可在后台设置本店积分规则：消费金额与积分换算比例（如 1 元 = 1 积分、1 元 = 2 积分） | P0 |
| FR-4.2 | 规则配置项：换算比例、单笔发放上限、是否开启活动积分、规则生效时间（立即/定时） | P0 |
| FR-4.3 | 规则修改需二次确认，修改记录留痕（谁改的、何时改的、改了什么），便于审计 | P0 |
| FR-4.4 | 规则变更只影响变更生效后的订单，历史订单按当时规则计算，不做追溯 | P1 |
| FR-4.5 | 总部可设定门店规则可调整的上下限（如换算比例上限 1 元 ≤ 5 积分），防止门店恶意设置 | P1 |
| FR-4.6 | 积分规则发布前支持预览（按示例金额试算可得积分） | P2 |

| FR-5.5 | 门店数据概览首页：今日发放积分、今日兑换积分、今日新增会员、积分成本估算 | P1 |
| FR-5.6 | 仅可查看本店数据，跨店数据不可见（权限隔离） | P0 |

## 7. 业务流程

### 7.1 积分获取流程（到店消费）

```
顾客到店 → 出示会员码/报手机号 → 店员识别会员
  → 收银台完成订单支付 → 系统按门店积分规则计算积分
  → 发放积分入账（实时或 T+1）→ 顾客积分余额增加 → 生成积分明细流水
```

### 7.2 积分兑换流程

```
顾客进入积分商城 → 浏览/搜索兑换商品 → 选择商品并确认兑换
  → 系统校验积分余额与库存 → 扣减积分 → 生成兑换记录与卡券
  → 卡券进入"我的卡券" → 到店使用时店员核销
```

### 7.3 积分规则设置流程（店长）

```
店长登录后台 → 进入积分规则设置 → 修改换算比例等参数
  → 二次确认 → 提交审核（总部规则内校验）→ 保存并留痕
  → 生效时间到达后新订单按新规则计算
```

## 8. 数据需求（关键数据字段）

### 8.1 会员表（member）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| member_id | string | 会员唯一 ID（主键） |
| phone | string | 手机号（脱敏存储） |
| nickname | string | 昵称 |
| level | int | 会员等级 |
| total_points | bigint | 累计获得积分 |
| balance_points | bigint | 当前可用积分余额 |
| status | int | 账户状态（正常/冻结/注销） |
| created_at | datetime | 开卡时间 |

### 8.2 积分明细表（points_transaction）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| txn_id | string | 流水唯一 ID（主键） |
| member_id | string | 会员 ID |
| store_id | string | 门店 ID |
| order_id | string | 关联订单号（消费/退款） |
| biz_type | string | 业务类型：CONSUME/EXCHANGE/ACTIVITY/REFUND/EXPIRE/ADJUST |
| change_amount | bigint | 变动积分数（正为增加，负为扣减） |
| balance_after | bigint | 变动后余额 |
| rule_version | string | 所依据的积分规则版本 |
| created_at | datetime | 发生时间 |

### 8.3 积分规则表（points_rule）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| rule_id | string | 规则唯一 ID（主键） |
| store_id | string | 门店 ID（全局规则时为空/总部） |
| ratio | decimal | 金额:积分换算比例（如 1 元 = 1 积分） |
| max_per_order | int | 单笔发放上限 |
| effective_time | datetime | 生效时间 |
| operator_id | string | 操作人 ID |
| status | int | 状态（草稿/生效/停用） |
| version | int | 规则版本号 |

### 8.4 兑换商品表 / 兑换记录表 / 卡券表（概要）

- 兑换商品（redeem_product）：商品 ID、名称、类型、所需积分、库存、适用门店、状态、上下架时间。
- 兑换记录（redeem_order）：兑换单号、会员 ID、商品 ID、消耗积分、状态（待核销/已核销/已取消/已过期）、创建时间。
- 卡券（coupon）：券码（唯一）、兑换单号、券类型、面值/内容、有效期起止、核销门店、核销时间、状态。

## 9. 非功能需求

| 类别 | 需求 | 说明 |
| --- | --- | --- |
| 性能 | 接口响应时间 | 核心接口（积分查询、兑换）P95 ≤ 300ms |
| 性能 | 并发支持 | 支持高峰时段 500 TPS 积分发放（按全部门店估算） |
| 可靠性 | 数据一致性 | 积分发放/扣减需保证最终一致，禁止重复发放；扣减采用防超扣机制（余额不足拒绝） |
| 可靠性 | 幂等 | 兑换、发放接口需幂等，防止重复提交产生重复积分/重复扣减 |
| 安全 | 数据安全 | 手机号等敏感信息脱敏存储；权限隔离（店长仅本店数据） |
| 安全 | 风控 | 兑换频率限制、异常积分发放告警 |
| 审计 | 操作留痕 | 积分规则修改、人工调分等敏感操作全量留痕 |
| 可用性 | 系统可用性 | 月度可用性 ≥ 99.9%，积分相关功能故障优先恢复 |
| 兼容性 | 端兼容 | 小程序兼容微信 iOS/Android 主流版本；后台兼容 Chrome/Safari/Edge 最新两个大版本 |

## 12. 风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| 积分重复发放 | 财务损失、用户投诉 | 发放接口幂等 + 订单维度去重 + 对账 |
| 兑换超发/库存不足 | 用户体验下降 | 库存扣减与兑换事务化、超卖兜底策略 |
| 店长误设过高积分比例 | 积分成本失控 | 总部设置比例上下限 + 修改二次确认 + 审计 |
| 积分薅羊毛 | 成本损失 | 风控规则（频次、设备、异常账号） |
| 跨店结算争议 | 门店间利益分配 | 积分成本按发放门店归集，总部统一结算 |

## 13. 附录

### 13.1 边界说明（本期不做）

- 不支持积分抵扣现金（仅兑换商品/券）。
- 不支持线上商城购物（仅到店消费积分）。
- 不做跨品牌/异业积分互通。
- 不做积分转赠。

### 13.2 待确认事项

1. 积分是否设置有效期（默认永久 vs 12 个月过期），需运营确认。
2. 积分成本单价（1 积分对应多少成本）需财务确认，用于成本看板。
3. 兑换实物是否需要接入物流系统，还是仅支持门店自提。
4. 与现有收银/会员系统的对接方式（API / 中间件 / 数据库直连）需技术确认。
