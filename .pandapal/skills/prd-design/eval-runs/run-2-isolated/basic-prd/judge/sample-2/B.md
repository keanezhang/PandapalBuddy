## ASCII 功能树绘制规范

**核心字符集**：
| 字符 | 用途 | 字符 | 用途 |
|------|------|------|------|
| `┌` `┐` `└` `┘` | 单线框四角 | `╔` `╗` `╚` `╝` | 双线框四角（阶段标题可选） |
| `─` | 横线 | `│` | 竖线 |
| `├` `┤` | 竖向分支 | `┬` `┴` | 横向分支 |
| `┼` | 十字交叉 | `▼` `►` `◄` | 方向箭头 |
| `......` | 省略占位 | | |

**绘制步骤**：
1. **先统计**：L1 域数、每个域的 L2 数、每个 L2 的 L3 数，确定画布宽度和深度
2. **自上而下**：L0 居中 → L1 均分宽度 → L2 在父域内居中 → L3 对齐父模块
3. **先画框再连线**：每个节点先画 `┌──┐` 框 + 内部文字，再画竖线 `│` 和横线 `─` 连接
4. **分支用 `├` `┤` `┬` `┴`**：一个父节点分叉到多个子节点时使用
5. **层级标注**：在右侧用 `◄ L0` `◄ L1` 等标注层级
6. **外部依赖**：用普通框 + 文字 `外部：XXX` 标注，放在图的右下方
7. **整体包裹**：整个图用 ` ```text ` 和 ` ``` ` 包裹

**对齐要点**：
- 每个中文字符占 2 个英文字符宽度，ASCII 制表符占 1 个宽度
- 框内文字 + 两侧空格 + 边框共 = 框宽，框宽为偶数
- L0 框约 26-30 字符宽，L1 框约 16-20 字符宽，L2 框约 14-16 字符宽，L3 框约 10-12 字符宽
- 竖线从父框底部中心 `┴` 出发，到子框顶部中心 `┬` 汇入


## ASCII 数据流图绘制规范

**核心字符集**：
| 字符 | 用途 |
|------|------|
| `┌─┐│└┘` | 节点框 |
| `─` `→` `►` | 横向流转箭头 |
| `│` `▼` | 纵向流转箭头 |
| `┌` `└` | 分支/汇合 |

**绘制规则**：
1. **节点框**：横向链路用 `┌──────┐` 框，一行排列 2~4 个节点
2. **流转箭头**：框之间用 `── 动作描述 ──►` 连接，动作描述用 4-10 个中文/英文
3. **纵向分支**：从框的底部 `└──┘` 向下引出竖线 `│` + `▼`，连接异常/分支路径
4. **异常路径**：用 `▼` 向下引出异常处理节点，虚线效果用文字 `<异常>` 标注替代
5. **回流箭头**：从底部节点用 `└── 重新触发 ──┘` 回到上方节点
6. **整体包裹**：整个图用 ` ```text ` 和 ` ``` ` 包裹

**链路数量**：
- 【中等】至少 1 条核心链路图
- 【复杂】至少 2 条核心链路图（不同角色或用例各一条）

- **目标**：审核门店规则、设定规则上下限、查看全品牌数据
- **前置条件**：总部管理员账号已开通

### 场景 6：退单/退款时的积分处理（异常）

- **发生时态**：异常
- **角色**：会员、店长
- **目标**：退款订单已发放的积分自动扣回，账户不虚增
- **前置条件**：存在已入账积分的订单发生退款

### 场景 7：积分过期与账户异常（异常/规模）

- **发生时态**：异常
- **角色**：会员、总部管理员
- **目标**：过期积分自动清零并通知会员；异常大额流水可追溯
- **前置条件**：积分设有效期（假设 12 个月）；系统运行中

### 3.2 业务链路

#### 核心链路 1：消费积分发放链路

```text
┌──────────┐ ① 支付成功 ┌────────────┐ ② 消费单+实付金额 ┌────────────┐
│ 收银系统  │ ─────────► │  订单系统   │ ────────────────► │  积分引擎   │
│  (POS)   │            └────────────┘                   └─────┬──────┘
└──────────┘                                                  │ ③ 匹配会员+规则
                                                              ▼
                                                       ┌────────────┐
                                                       │  会员账户   │
                                                       │  +N 积分    │
                                                       └─────┬──────┘
                                                             │ ④ 写流水
                                                             ▼
                                                       ┌────────────┐
                                                       │  积分流水   │
                                                       │ 状态:已入账 │
                                                       └────────────┘

<异常1> 未识别会员 → 不发放积分，收银端提示先注册/绑定
<异常2> 订单退款   → 自动生成负向流水（状态:已退回），余额实时冲减
```

**链路说明**：收银系统在支付成功后推送消费单（订单号、门店、实付金额、会员标识）→ 积分引擎按生效规则计算积分（floor(实付金额 × ratio)）→ 会员账户余额增加 → 生成积分流水并标记已入账。整个过程对收银结账零阻塞（异步处理）。

#### 核心链路 2：积分兑换与核销链路

```text
┌──────────┐ ① 选择商品 ┌────────────┐ ② 校验余额 ┌────────────┐
│ 会员小程序 │ ─────────► │  积分商城   │ ─────────► │  兑换引擎   │
└──────────┘            └────────────┘            └─────┬──────┘
                                                        │ ③ 扣减积分·生成核销码
                                                        ▼
                                                 ┌────────────┐
                                                 │  兑换订单   │
                                                 │ 状态:待核销 │
                                                 └─────┬──────┘
                                                       │ ④ 到店出示核销码
                                                       ▼
                                                 ┌────────────┐
                                                 │  店长核销   │
                                                 │ 状态:已核销 │
                                                 └────────────┘

<异常1> 余额不足 → 拦截兑换，提示差额
<异常2> 超时未核销 → 自动取消，积分退回
```

**链路说明**：会员在小程序选择商品提交兑换 → 校验余额并即时扣减积分、生成 12 位核销码 → 订单进入待核销 → 到店出示核销码，店
