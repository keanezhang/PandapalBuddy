#### 1.2 追问补齐（缺什么，问什么）

从输入中提取场景要素，信息不足时必须用 `ask_user` 追问：

- **谁用**？（角色名，不是"用户"——如"运营编辑""门店店长""普通会员"）
- **干什么**？（动词 + 宾语 + 目的）
- **在什么状态下开始**？（前置条件：已有数据？登录态？特定权限？）
- **出错了会怎样**？（至少 1 个异常情况的方向：网络断了？数据为空？无权限？）

> 追问直到能描述出**至少一个完整场景**（角色 + 动作 + 前置 + 异常方向）。用户说"你先猜"时，假设一个场景让用户确认，不通过继续问。
> 追问后仍无法获取 `角色名` + `干什么` → **终止**，告知"需要至少一个具体角色和核心动作才能开始"。

#### 1.3 穷举场景（面向产品层的场景识别）

基于已有信息，从四个维度穷举使用场景（通常 3~7 个，核心至少 2 个）：

| 维度 | 问什么 | 示例 |
|------|--------|------|
| **角色维度** | 不同角色使用时有何不同？ | 普通用户 vs 管理员；创作者 vs 消费者 |
| **时态维度** | 首次使用 vs 日常使用 vs 峰值时刻？ | 新手引导 vs 熟练操作 vs 高并发 |
| **异常维度** | 出错、断网、数据为空时？ | 提交失败、超时、无权限——是否存在不同场景？ |
| **规模维度** | 单人用 vs 团队用 vs 海量数据？ | 1 条 vs 10000 条，行为差异？ |

> 穷举不凑数——真实场景只有 2 个就列 2 个。

## ASCII 功能树绘制规范

**核心字符集**：
| 字符 | 用途 | 字符 | 用途 |
|------|------|------|------|
| `┌` `┐` `└` `┘` | 单线框四角 | `╔` `╗` `╚` `╝` | 双线框四角（阶段标题可选） |
| `─` | 横线 | `│` | 竖线 |
| `├` `┤` | 竖向分支 | `┬` `┴` | 横向分支 |
| `┼` | 十字交叉 | `▼` `►` `◄` | 方向箭头 |
| `......` | 省略占位 | | |

**绘制步骤**：
1. **先统计**：L1 域数、每个域的 L2 数、每个 L2 的 L3 数，确定画布宽度和深度
2. **自上而下**：L0 居中 → L1 均分宽度 → L2 在父域内居中 → L3 对齐父模块
3. **先画框再连线**：每个节点先画 `┌──┐` 框 + 内部文字，再画竖线 `│` 和横线 `─` 连接
4. **分支用 `├` `┤` `┬` `┴`**：一个父节点分叉到多个子节点时使用
5. **层级标注**：在右侧用 `◄ L0` `◄ L1` 等标注层级
6. **外部依赖**：用普通框 + 文字 `外部：XXX` 标注，放在图的右下方
7. **整体包裹**：整个图用 ` ```text ` 和 ` ``` ` 包裹

**对齐要点**：
- 每个中文字符占 2 个英文字符宽度，ASCII 制表符占 1 个宽度
- 框内文字 + 两侧空格 + 边框共 = 框宽，框宽为偶数
- L0 框约 26-30 字符宽，L1 框约 16-20 字符宽，L2 框约 14-16 字符宽，L3 框约 10-12 字符宽
- 竖线从父框底部中心 `┴` 出发，到子框顶部中心 `┬` 汇入


## ASCII 数据流图绘制规范

**核心字符集**：
| 字符 | 用途 |
|------|------|
| `┌─┐│└┘` | 节点框 |
| `─` `→` `►` | 横向流转箭头 |
| `│` `▼` | 纵向流转箭头 |
| `┌` `└` | 分支/汇合 |

**绘制规则**：
1. **节点框**：横向链路用 `┌──────┐` 框，一行排列 2~4 个节点
2. **流转箭头**：框之间用 `── 动作描述 ──►` 连接，动作描述用 4-10 个中文/英文
3. **纵向分支**：从框的底部 `└──┘` 向下引出竖线 `│` + `▼`，连接异常/分支路径
4. **异常路径**：用 `▼` 向下引出异常处理节点，虚线效果用文字 `<异常>` 标注替代
5. **回流箭头**：从底部节点用 `└── 重新触发 ──┘` 回到上方节点
6. **整体包裹**：整个图用 ` ```text ` 和 ` ``` ` 包裹

**链路数量**：
- 【中等】至少 1 条核心链路图
- 【复杂】至少 2 条核心链路图（不同角色或用例各一条）
