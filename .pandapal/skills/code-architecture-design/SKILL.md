# code-architecture-design — 生成技术架构图富卡片 HTML

---

## 用法

```
$ARGUMENTS
```

`$ARGUMENTS` 是要生成架构图的描述文字、文件路径或模块名。

**示例：**
- `用户认证系统架构：JWT签发→网关校验→服务鉴权→缓存用户信息`
- `assistant/perception/` — 读目录源码生成架构图
- `payment 支付模块架构` — 模块架构
- `微服务部署架构：Nginx→网关→服务A/B/C→Redis→PostgreSQL`

---

## 执行步骤

### Step 1：理解输入

路径约定：所有相对路径基于项目根目录。

如果 `$ARGUMENTS` 看起来像文件/目录路径（含 `/` 或 `\` 或扩展名）：
- 读取目标文件（`.py` / `.md`），提取模块信息和架构逻辑
- 如果是目录，glob `**/*.py` 读取核心文件（≤15 个全部读，超出按文件名判断核心文件）
- 提取：类名、方法签名、关键字段、import 依赖、类继承关系

否则 `$ARGUMENTS` 就是架构描述文本：
- 优先搜索：在项目中搜索是否已有相关模块名或类名，用于校准命名，了解确切的代码架构。搜不到也不影响生成。
- 如果搜索不到，根据描述文案按 Step 3 方法论直接生成。

**信息充足性检查**（开始前必须确认以下信息，缺什么问什么）：

- **必须有的**：要设计什么（系统/功能/模块名）？核心能力是什么（做哪几件事）？
- **必须有的**：现有代码上下文（项目路径？当前架构？）？关键约束（性能/技术栈/部署）？
- 信息不足 → `ask_user` 追问，直到能回答「做什么」+「核心能力」两项。

---

### Step 2：确定输出路径与加载样式

输出到 `docs/{name}/`，文件名从输入推断：
- 文件路径 → 取文件名去扩展名
- 描述文本 → 取前 2-3 个关键词
- 如: `docs/{name}/{name}_code-architecture-design.html`

加载样式：读取 `references/code-architecture-design-style.md`，取 cards 风格的完整 `<style>` 块。

---

### Step 3：组织架构内容（方法论）

根据输入类型选择组织方式：

#### A. 源码模式 — 基于代码提取

按以下顺序组织，某 section 无内容则跳过：

1. **概述** — 模块职责、入口、核心流程
2. **核心类/组件** — 每个主要类的职责、关键方法、重要字段
3. **数据结构** — 数据类、Pydantic/dataclass 模型、枚举、配置项
4. **依赖关系** — import 依赖图、对外暴露的接口、被哪些模块调用

类名、方法名严格取自源码，不虚构。

#### B. 描述模式 — 技术架构

关注"用了什么技术、怎么分层、怎么部署"：

内容维度：
1. **技术栈** — 语言、框架、中间件、存储
2. **分层架构** — 接入层→业务层→数据层，每层职责与组件
3. **核心组件** — 关键中间件/服务的选型与理由
4. **数据存储** — 数据库、缓存、消息队列的职责划分
5. **部署拓扑** — 节点、网络、负载均衡

呈现形式：**zone 分层包裹 + node-box 组件节点**
- 每一层用一个 `zone` 容器包裹，zone 内用 `node-box`（或 `panelist-grid` 排布多个 node-box）表示该层的具体组件
- 层与层之间必须用 **箭头 + 关系描述文字** 标注调用方向，如「gRPC 调用」「读写」「订阅」「SQL 查询」
- `node-box` 内只标注**组件名和技术标签**（如 `async`、`Redis`、`PostgreSQL`），不展开详细配置或内部实现
- 标题使用渐变 `linear-gradient(135deg, #7c3aed, #ec4899, #f97316)`（紫→粉→橙）

#### 内容原则
- 不虚构不存在的模块名/类名
- 信息不足时标注 `[待确认]`
- 卡片/zone 数量控制在 4~8 个，不要过度拆分
- **层间必须用箭头连线 + 关系描述文字**，不能只有孤立的卡片/节点
- **节点内部保持简洁**：仅写组件名和技术标签（如 `async`、`Redis`、`PostgreSQL`），不展开详细配置或内部实现
- 颜色语义：紫=策略/入口，蓝=数据流/处理，青=查询，绿=成功/写入，橙=通信/协议，粉=输出
- 标题渐变：`linear-gradient(135deg, #7c3aed, #ec4899, #f97316)`（紫→粉→橙，适合技术架构）

---

### Step 4：生成 HTML 文件

从 `references/code-architecture-design-style.md` 取 cards 风格的完整 `<style>` 块，嵌入 HTML。

替换：
- `<title>` 和 h1 → 架构图名称
- 各 section 内容 → Step 3 产出的文本
- 颜色/class 按颜色语义分配

---

### Step 5：写入文件并报告

写入目标路径，报告：
- 输出文件路径
- 架构图名称
